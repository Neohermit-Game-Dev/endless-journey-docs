Junk

The junk system spawns debris that floats past the train for players to collect with the GrabHook. The server owns spawning, weighted selection, and collection validation; the client renders junk with pooled instances and drives the movement simulation locally using a shared speed value.

At a glance​

LayerFileRole

Serversrc/ServerScriptService/JunkService.server.luauServer authority: weighted spawn loop, pity system, odometer, claim/finalize handshake

Configsrc/ReplicatedStorage/SharedModules/Configs/JunkConfig.luauAll tuning: spawn rates, speeds, tier weights, type chances, despawn distance

Packets: SpawnJunk, SetJunkSpeed, JunkCollected, ReqJunkClaim, ReqJunkClaimBatch, ReqJunkFinalize, BeginJunkRetract — see Networking Map Signals: SetTrainState, SetTrainStarted, ApplyTierMultiplier, ApplyTypeMultiplier, TryClaimJunk, TryClaimJunkBatch, TryFinalizeJunk, OnJunkCollected — see Signals Map

How it works​

Client rendering and pooling​

JunkController builds per-model GenericPoolInstance pools at startup, one per model name found in JunkAssets, with initial size 5, max 60, expand by 10. On SpawnJunk it checks the MAX_CLIENT_JUNKS = 250 cap, retrieves a model from the pool, sets Transparency = 0, parents it to workspace/JunksVisuals, and records it in activeJunks and junkMap. A PreSimulation loop advances the smoothstep speed ramp, moves each active junk by currentSpeed * dt along MOVE_DIRECTION, applies per-junk random rotation, and increments DistanceTraveled; junk despawns via RemoveJunkLocal when DistanceTraveled > DESPAWN_DISTANCE.

JunkController also bridges claim/finalize signals from GrabHook.client to Packets.ReqJunkClaim / Packets.ReqJunkFinalize via Signals.TryClaimJunk and Signals.TryFinalizeJunk, and exposes GetJunkIdFromPart(part) via BindableCore so GrabHook.client can resolve a junk ID from a raycast hit part.

Retraction and collection cleanup​

On BeginJunkRetract, the client removes the junk from simulation and moves it to retractingJunks. The local player's animation is driven by GrabHookVisuals.AnimateProjectile; other players see an observer lerp on RenderStepped. An 8-second safety-net timeout returns the model to the pool if JunkCollected never arrives. On JunkCollected, the client cleans up rope attachments and beams on the model and returns it to the pool.

Server spawn loop​

JunkService performs weighted tier selection: each tier's weight is multiplied by GlobalModifiers.TierMultipliers[tier], and a random number selects the tier by accumulated weight. Type selection uses pity: if spawnsSinceLastEnergy >= ENERGY_PITY_THRESHOLD (8), an Energy-type junk is forced; otherwise a type is chosen weighted by SpawnChance * TypeMultiplier. The pity counter resets on every Energy spawn.

Odometer and despawn​

The server records SpawnOdometer (the value of junkOdometer at spawn time) and SpawnPos for each active junk; the junk's current world position is reconstructed on claim as SpawnPos + MOVE_DIRECTION * (junkOdometer - SpawnOdometer). A distance-based despawn on Heartbeat removes any junk where (junkOdometer - SpawnOdometer) > DESPAWN_DISTANCE, mirroring the client-side DistanceTraveled check. The junk counter wraps at 65535 (NumberU16 boundary) to keep IDs compact in the SpawnJunk packet.

Claim and finalize validation​

ReqJunkClaim reconstructs the junk's world position, checks distance against GrabHookConfig.Physics.MaxDistance + 15 studs (latency slack), enforces a per-player cooldown, reserves the junk, computes retract time, and fires BeginJunkRetract to all clients. ReqJunkFinalize checks reservation ownership and a 5-second timeout, marks the junk collected, fires JunkCollected to all clients, and gives the tool to the player's Backpack. SetTrainState(isMoving) and SetTrainStarted(started) are wired to Signals.SetTrainState and Signals.SetTrainStarted for external control.

Spawn volumes​

SpawnHelper:Init() caches all BasePart children of workspace/SpawnVolumes weighted by volume; SpawnHelper.GetRandomPoint() picks a random world position inside one of the spawn volumes using volume-weighted selection. SpawnHelper:Init() must be called before the spawn loop — JunkService calls it at startup; if no SpawnVolumes parts exist in workspace, GetRandomPoint always returns nil and no junk spawns.

Disabling spawn volumes​

Spawn volumes can be grouped and toggled at runtime without touching the workspace. Author an optional SpawnGroup string attribute on a BasePart under workspace/SpawnVolumes; every part sharing the same value forms a togglable group. Parts with no SpawnGroup attribute are ungrouped and always active — never affected by a toggle. SpawnHelper exposes three methods on top of Init / GetRandomPoint:

  • SpawnHelper:SetGroupEnabled(groupName: string, enabled: boolean) — enables or disables every volume in groupName. warns on an unrecognized group name (typo guard) but still records the state.
  • SpawnHelper:IsGroupEnabled(groupName: string): boolean — true unless the group is currently disabled; unknown or ungrouped names always read true.
  • SpawnHelper:GetGroups(): { string } — the distinct SpawnGroup values authored across the spawn volumes, for validation/debug.

The pirate-ship event uses this to disable the ship-facing group during the at-range cannon phase: junk stops spawning toward the ship, and any junk already floating there clears out via the normal distance-despawn instead of being force-removed, so the area is clean by the time players board. If every group with volumes ends up disabled, GetRandomPoint() returns nil and the spawn loop simply idles until a group is re-enabled — no junk spawns, but nothing errors.

Gotchas​

Both sides integrate the same ramp — keep them in sync

The server (junkOdometer) and client (DistanceTraveled) both use the identical smoothstep ramp over SPEED_RAMP_DURATION. If you change the ramp formula in one place, change it in the other. Drift causes the server's proximity check to reject valid claims.

Reservation timeout is 5 seconds

If a client claims junk but never finalizes (e.g. disconnects mid-retract), the reservation expires after 5 seconds (RESERVATION_TIMEOUT). Another player can then claim the same junk. The client has an 8-second safety net (RETRACT_RECLAIM_TIMEOUT) that returns the model to the pool if JunkCollected never arrives — this value must exceed RESERVATION_TIMEOUT plus round-trip time.

  • Pool cleanup is mandatory. Every path that removes a junk from activeJunks or retractingJunks must call CleanupJunkModel then pool:InsertObject. Skipping cleanup leaks HookAttachment or Beam instances on the model, which will appear on the next retrieval.
  • workspace/JunksVisuals folder must exist. JunkController uses WaitForChild to find it; the folder should be created in the place file or by a server startup script.
  • Junk ID wraps at 65535. This is intentional for the NumberU16 wire type in SpawnJunk. Long-running servers are safe because entries are removed before the counter can collide.
  • Tier 5 weight is 0. Items in Tier 5 will never spawn under default config. Set the weight above 0 to enable them.

Data flow​

sequenceDiagram
    participant S as JunkService (server)
    participant C as JunkController (client)
    participant G as GrabHook (client)

    S->>S: selectRandomJunk() - weighted tier + pity type
    S->>S: assign id (U16), record SpawnOdometer + SpawnPos
    S->>C: SpawnJunk(id, modelName, startPos)
    C->>C: pool:RetrieveObject(startPos), add to activeJunks/junkMap

    S->>C: SetJunkSpeed(targetSpeed)
    Note over S,C: first receipt snaps currentSpeed; later receipts smoothstep-ramp

    Note over S,C: Shared speed ramp (identical smoothstep both sides)<br/>Server: junkOdometer += currentSpeed * dt<br/>Client: DistanceTraveled advances in PreSimulation<br/>Despawn when delta > DESPAWN_DISTANCE (both sides)

    G->>G: Player fires GrabHook -> Signals.TryClaimJunk(id, hitPos)
    G->>C: Signals.TryClaimJunk
    C->>S: ReqJunkClaim(id, hitPos)
    S->>S: proximity check vs junkOdometer, cooldown check, reserve junk
    S->>C: BeginJunkRetract(id, hitPos, retractTime, player)
    Note over C: local player -> GrabHookVisuals.AnimateProjectile<br/>other players -> observer lerp on RenderStepped

    G->>C: Signals.TryFinalizeJunk(id)
    C->>S: ReqJunkFinalize(id)
    S->>S: verify reservation + timeout, mark Collected, award Tool
    S->>C: JunkCollected(id, player)
    C->>C: pool:InsertObject (returns model)
