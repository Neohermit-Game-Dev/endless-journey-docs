Stamina & Sprint

Sprint is client-predicted for responsive feel and server-authoritative for integrity. The client applies WalkSpeed/FOV changes instantly on input; the server runs the canonical stamina simulation and pushes syncs at up to 10 Hz, which the client uses to gate visual and audio effects.

How it works​

Client prediction​

SprintController binds sprint to LeftShift and ButtonB (gamepad) via ContextActionService; a separate MobileSprintToggled signal handles the mobile toggle button. On each RenderStepped tick it calls canSprintNow() (wraps SprintValidation.CanHumanoidSprint) and calls setSprinting accordingly, which sets humanoid.WalkSpeed, tweens FieldOfView via TweenPlus, and fires Signals.OnSprintToggled. Sprint intent resets on CharacterRemoving and on WindowFocusReleased.

On StaminaStateSync the client clamps the received stamina, forces sprint off if the server says so, and fires Signals.OnStaminaValueChanged for the HUD. On StaminaBuffSync it forwards buff state to Signals.OnStaminaBuffsChanged for UI and icon updates.

Server authority​

StaminaManager maintains a StaminaRecord per player (Stamina, IsSprinting, SprintIntent, LastSprintTime, LastSyncTime). On the StaminaSprintIntent packet it immediately updates sprint state and calls syncPlayer. Its Heartbeat loop clamps dt to MAX_STAMINA_STEP_DT = 0.1 s to prevent large delta spikes, drains stamina at StaminaDrain * dt * UsageMultiplier while sprinting, and regenerates at StaminaRegen * dt * RegenMultiplier after RegenDelay seconds of not sprinting.

It syncs to the client when sprint state changes, stamina hits 0 (forced stop), stamina refills to max, or the periodic sync interval (STAMINA_SYNC_INTERVAL = 0.1 s) elapses while stamina is changing. It consults StaminaBuffManager each tick for buff multipliers and resyncs immediately on Signals.OnServerStaminaBuffStateChanged. StaminaManager.RestoreStamina(player, amount) is available for pickup items but has no caller yet. StaminaManager.Initialize() must be called exactly once — it is called by StaminaSystemLoader.server.luau.

Shared validation gate​

SprintValidation.CanHumanoidSprint(humanoid, rules) returns false if health is 0, MoveDirection magnitude is below MinMoveDirection, the character is moving backward beyond MaxBackwardComponent, or horizontal speed is below MinHorizontalSpeed. It is called identically on the client (canSprintNow) and the server (canPlayerSprint) so the gate condition can never desync between the two sides.

Buffs​

Buff presets (StaminaRegenBuff, StaminaUsageBuff, InfiniteStaminaBuff) define strength and duration for collectible buffs; BuffIcons holds asset ids for the HUD. Buff state is authoritative on the server — StaminaBuffSync pushes the current multipliers to the client for display only, and the client never applies buffs directly to the drain/regen calculation.

Gotchas​

Sprint logic must be mirrored on both sides

SprintValidation.CanHumanoidSprint is the shared gate. If you add a new sprint-blocking condition (e.g. stun), add it to SprintValidation and verify it is called by both SprintController (client) and StaminaManager (server). A condition added only to one side will cause desyncs.

  • WalkSpeed is client-only. The server does not validate movement speed (see audit note S3 in SprintController's source); a cheating client can move at any speed. If movement integrity becomes necessary, add a server-side speed sanity check.
  • STAMINA_SYNC_INTERVAL = 0.1 s (10 Hz). The server only sends a sync when stamina is actively changing — if stamina is full and the player is standing still, no sync is sent, which is intentional.
  • MAX_STAMINA_STEP_DT = 0.1 s clamp. The server caps the Heartbeat delta so a lag spike cannot drain or regen an unrealistic amount of stamina in one tick. Do not remove this clamp.

Data flow​

sequenceDiagram
    participant P as Player
    participant C as SprintController
    participant S as StaminaManager

    P->>C: Hold Shift / mobile toggle
    C->>S: Packets.StaminaSprintIntent(true)
    S->>S: record.SprintIntent = true
    loop Heartbeat (dt clamped to 0.1s)
        S->>S: drain or regen stamina by UsageMultiplier / RegenMultiplier
    end
    S->>C: Packets.StaminaStateSync(stamina, isSprinting)
    C->>C: currentStamina = stamina; force stop if !isSprinting
    C-->>C: Signals.OnStaminaValueChanged(stamina) -> HUD bar

    Note over C: RenderStepped, every frame
    C->>C: setSprinting(intent AND canSprintNow())
    C->>C: humanoid.WalkSpeed, FOV tween
    C-->>C: Signals.OnSprintToggled(isSprinting) -> HUD

    S-->>C: Packets.StaminaBuffSync(infinite, regenMult, usageMult)
    C-->>C: Signals.OnStaminaBuffsChanged(...) -> HUD / buff icons
