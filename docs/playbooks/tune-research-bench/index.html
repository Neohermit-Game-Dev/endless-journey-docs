Tune Research Bench

Goal: Adjust Research Bench node costs/durations, fuel/queue/refund constants, or add a node or a branch.

Steps​

  1. Change a node's cost or duration. Open src/ReplicatedStorage/SharedModules/Configs/ResearchConfig.luau and edit the Levels table on the node:

    Shield_Alpha = {
        DisplayName = "Shield α", Branch = "TrainShield", Tier = 1, Column = 0.5,
        Prereqs = nil, MaxLevel = 1,
        Effects = { { Type = "StatBuff", Key = "MaxHP", PerLevel = 50 } },
        Levels = { [1] = { Cost = { Metal = 25 }, Duration = 30 } },  -- ← cost / time
    },

    Cost is a { [material]: number } map spent from the server-wide Material Pool — only Wood and Metal are valid (any other key makes MaterialPool.Spend refuse the enqueue, and the GUI only draws Metal and Wood costs). Duration is in seconds of research while fuel is available — see step 2. Both values take effect for any job enqueued after the change; jobs already queued or active keep the cost/duration they were enqueued with. Every node ships at MaxLevel = 1, so only Levels[1] exists.

    Changing an Effects entry's PerLevel (for StatBuff) or DrainPerLevel (for FuelEfficiency) changes the buff granted — see step 5 for the effect shapes. ResearchEffectsDispatcher recomputes buffs from every node's Effects list on every level-up, and the detail panel's EFFECT row updates from the same number.

  2. Review the fuel and pause behavior before retuning it.

    • Bench fuel has no cap: players can store as much as the pool's Energy pays for.
    • FUEL_BURN_RATE (default 1.0/sec) — how fast fuel burns while a job is active. Raising this makes jobs pause more often; consider raising FUEL_PER_POINT with it.
    • FUEL_PER_POINT (default 2) — bench fuel per pool Energy point.
    • HOLD_TICK (default 0.1 s) and REFUEL_POINTS_PER_TICK (default 1) — how fast holding the REFUEL button grows the preview (10 Energy/s at the defaults). Nothing is spent until the player lets go; the server then spends only the points needed. While any player holds, the burn and the job timer stop for everyone.
    • MAX_HOLD_POINTS (default 255) — a hold pays by itself at this much Energy, or after the time that takes (25.5 s at the defaults) when a small pool stops the charge first. Keep it at or below 255: ReqResearchRefuel carries the points as a NumberU8.
    • HOLD_TIMEOUT (default 30 s) — a holder whose release never arrives (crash, lost packet) stops freezing the bench after this long. Keep it above MAX_HOLD_POINTS / REFUEL_POINTS_PER_TICK × HOLD_TICK so a real hold never times out.

    A job's elapsed only advances while fuel is available (ResearchState.advance clamps effectiveDt = min(dt, fuel / burnRate)), so each fuel point at the defaults buys one second of research.

  3. Change the queue depth. QUEUE_MAX (default 3) caps how many jobs can wait behind the active one (ResearchState.validateEnqueue rejects with QUEUE_FULL beyond this). The GUI has three slot cards (QueueButton1..3 under QueueContainer.Slots). To raise it, duplicate a slot in Studio and name it QueueButton4; the controller warns at load if a slot is missing.

  4. Change the cancel refund fraction. ACTIVE_REFUND_FRACTION (default 0.5) is the fraction of the active job's cost refunded when it is cancelled — queued jobs always refund at 1.0. The in-progress box reads "50% BACK" from this value (or "FULL BACK" while the Lab Insurance perk is active). This does not affect the cascade behavior (see Research Bench — Cascade-cancel).

  5. Add a node. One config entry; no Studio work. TechTreeGuiController clones a card from Templates.CardTemplate for every node of the open branch and draws its lines from Prereqs.

    • Pick a free slot: Branch (an Id from ResearchConfig.Branches), Tier (row, 1 = top, at most ResearchConfig.MAX_TIER = 5, the rows the tree canvas fits) and Column (0 left, 0.5 centre, 1 right). A centred node must be alone in its row. Prereqs must be in the same branch and a higher row.

    • A line from a prereq more than one row up runs straight down the prereq's column, so every slot it passes must stay empty (Ranged_SniperRifle → Ranged_EnergyFirearms keeps tier 4 column 1 empty).

    • Give it Unlocks = { "..." } (one detail-panel row per string) for an unlock-flag node, or an Effects list for a buff node. A new StatBuff key also needs a ResearchConfig.EffectLabels entry.

      Example — "Reinforced Hull" below Shield δ:

      Shield_ReinforcedHull = {
          DisplayName = "Reinforced Hull", Branch = "TrainShield", Tier = 5, Column = 0.5,
          Prereqs = { "Shield_Delta" }, MaxLevel = 1,
          Effects = { { Type = "StatBuff", Key = "MaxHP", PerLevel = 75 } },
          Levels = { [1] = { Cost = { Metal = 320, Wood = 60 }, Duration = 240 } },
      },

    • Effect shapes (a node can list more than one, see Shield_Efficiency/Shield_Delta):

      • { Type = "StatBuff", Key = <attributeName>, PerLevel = <number> } — ResearchEffectsDispatcher sums PerLevel * level across every node sharing the Key into that attribute on ReplicatedStorage/ResearchBuffs. Publishing a key with no consumer is safe but be deliberate about it.
      • { Type = "FuelEfficiency", DrainPerLevel = <number, 0 < n < 1> } — multiplies into ResearchBuffs.FuelEfficiency as DrainPerLevel ^ level. TrainFuelManager already reads it.
      • Any other Type warns and no-ops in ResearchEffectsDispatcher.
      • nil — an unlock-flag node. At level 1, ResearchUnlocked/<nodeId> is written; wire a Workbench recipe's RequiresNode to that id (see Workbench Crafting).

    • Optional Gamepass id: the card gets a gold rail and ticket, and the detail panel shows a "Game pass" chip.

    • Reload in Studio: ResearchConfig.validate() warns on an unknown branch or prereq, a bad Tier/Column, two nodes in one slot, a line through a card, a prereq cycle, a node with neither Unlocks nor Effects, an effect with no dispatcher handler, or a buff key with no label.

  6. Add a branch. Add { Id, DisplayName, Icon } to ResearchConfig.Branches (list order = tab order; Icon is a key of ResearchConfig.Icons), then give nodes that Branch. The tab list scrolls when the tabs outgrow it.

  7. Change an icon. Upload the PNG (white on transparent for line icons; the controller tints them) and paste rbxassetid://<id> into ResearchConfig.Icons under its key.

Verify​

  1. Join in Studio with API Services enabled, walk to the placed bench under workspace.PlacedObjects.
  2. Open the tree (TechPromptPart prompt), pick the branch tab, and check the new card sits where Tier/Column say, with its lines.
  3. Select a cheap node and press RESEARCH. Confirm materials are deducted at once, the in-progress box shows the job, and the card's stroke pulses.
  4. Let fuel run to 0 and confirm the bar stops, the running card reads PAUSED and the fuel hint reads "RESEARCH PAUSED". Hold REFUEL with Energy in the pool: the job box reads REFUELING and its timer stops. Release, and confirm one payment and the job resumes.
  5. Cancel the active job from the in-progress box — it refunds at ACTIVE_REFUND_FRACTION. Queue a job and cancel it from its slot — full refund.
  6. Let a StatBuff node complete and confirm the attribute in ReplicatedStorage/ResearchBuffs updates and the card turns green, or an unlock-flag node and confirm ReplicatedStorage/ResearchUnlocked/<nodeId> appears.
  7. For a Gamepass node, confirm enqueue is rejected with GAMEPASS_REQUIRED while not owned.
