Leaderboard

A giant floating monitor in the Lobby shows four all-time boards, one at a time: HIGHEST LEVEL, MOST COINS EARNED, LONGEST RUN and MOST KILLS. Each board shows the top 10 (the top 3 on a podium) and the viewer's own rank.

At a glance​

LayerFileRole
Configsrc/ReplicatedStorage/SharedModules/Configs/LeaderboardConfig.luauBoards (id, title, store, icon), art ids, timings, Studio write guard
Sharedsrc/ReplicatedStorage/SharedModules/LeaderboardFormat.luauNumber, run time, board value and rank text (Studio self-check selfCheck())
Server (both places)src/ServerStorage/SharedModules/LeaderboardWriter.luauBuffers stats per player, flushes them to the ordered stores (Studio self-check selfCheck())
Server (Lobby)places/Lobby/ServerScriptService/LeaderboardService.luauReads the top lists and own values, sends LeaderboardSync (Studio self-check selfCheck())
Client (Lobby)places/Lobby/StarterPlayer/StarterPlayerScripts/LeaderboardController.client.luauClones the SurfaceGui onto the monitor, renders, cycles boards

Packets: LeaderboardSync (S→C, Lobby only) — see Lobby Place → Packets Approved look: roblox-gui-prototypes/2026-10-27-leaderboard-gui-prototype.html (its build notes are the GUI spec)

How it works​

Data​

One OrderedDataStore per board, key = tostring(UserId), integer values. The ordered store is the record; no ProfileStore field holds these numbers.

BoardStoreValueWriteWritten when
levelLB_TotalXP_v1total EXP (shown as LV n)maxXP profile load + every XPManager.AddXP
coinsLB_CoinsEarned_v1coins actually added by CoinManager.AddCoins (not refunds, not the wallet)addevery AddCoins
runLB_LongestRun_v1best single-run played secondsmaxrun payout (RunEndService, Leave or run end)
killsLB_Kills_v1enemies killed, all runsaddrun payout (RunEndService)

Coins earned before the board shipped are not counted. Level backfills on the player's next join.

Writing (both places)​

LeaderboardWriter.Add / Max only touch an in-memory buffer keyed by UserId. Flush writes it: add → IncrementAsync, max → UpdateAsync that returns nil (no write) when the stored value is already as high. Flushes run every FLUSH_SECONDS (60), on PlayerRemoving and on the PersistenceRegistry flush. A failed write goes back into the buffer for the next flush. On BindToClose, Drain(20) flushes, waits up to 20 s for writes that other flushes already started (e.g. the last player's PlayerRemoving flush), then flushes once more to retry any that failed.

Studio never writes (WRITE_IN_STUDIO = false): the writer prints [LeaderboardWriter] Studio, not written: … instead, like the read-only ProfileStore sessions.

Reading (Lobby)​

Every REFRESH_SECONDS (120) LeaderboardService:

  1. reads each board's top 100 (GetSortedAsync(false, 100)); a failed board keeps its last good list;
  2. names the top 10: players in the server by DisplayName, the rest with one UserService:GetUserInfosByUserIdsAsync call (cached until the server restarts);
  3. reads every Lobby player's own values, one BatchGetAsync per board;
  4. sends each ready player their payload. A joiner gets theirs from the "Leaderboard" JoinSync sender.

Rank: 1 + the number of top-100 entries above the player's own (fresh) value, so a score that landed after the last refresh still ranks right. Below a full top 100 it reads 100+ (ordered stores cannot look up one key's rank); no score, or a board that was never read, reads — (no score also shows PLAY A RUN).

Monitor (client)​

LeaderboardController connects LeaderboardSync, waits up to 30 s for workspace.Lobby_TV_Animation.Screen (missing → one warning, no monitor), clones ReplicatedStorage.GuiAssets.LeaderboardGui into PlayerGui with Adornee = Screen (per player, because the YOU row differs), and applies the art ids from LeaderboardConfig. Every CYCLE_SECONDS (10) it shows the next board and runs the progress bar with MotionMaster. Before the first payload it shows LOADING SCORES…; a payload with status = "offline" shows SCORES OFFLINE · RETRYING. Head shots come from Players:GetUserThumbnailAsync (cached).

Data flow​

Game Instance / Lobby                         Lobby
CoinManager.AddCoins ─┐
XPManager.AddXP/load ─┼─► LeaderboardWriter ─► OrderedDataStores ─► LeaderboardService ─► LeaderboardSync ─► LeaderboardController
RunEndService payout ─┘     (buffer, 60 s)        (4 boards)          (top 100, 120 s)     (per player)        (SurfaceGui)

LeaderboardSync payload:

{
	status = "ok" | "offline",
	boards = { [boardId] = { { userId, name, value } } }, -- ≤ 10, index = rank
	mine = { [boardId] = { rank, value } }, -- rank 0 none, 1..100, 101 = "100+"
}

Studio setup (Lobby)​

  • Workspace.Lobby_TV_Animation (the floating TV Model, ModelStreamingMode = Persistent: the Lobby uses instance streaming, and a far monitor would not stream in; RootPart anchored, the other parts hang on it by Motor6D). Screen: an invisible Part (CanCollide/CanQuery/CanTouch off, Massless) laid flat on the glass of Lobby_TV_Monitor, front face out, 16:9, joined to the monitor by a WeldConstraint so it follows the TV animation. The glass is curved, so the GUI corners stand a little in front of it seen from the side. Move or scale the whole model freely.
  • ReplicatedStorage.GuiAssets.LeaderboardGui: SurfaceGui template, FixedSize 1600×900. Text labels for names are called PlayerName (a child called Name would clash with Instance.Name).
  • Art: the image ids are in LeaderboardConfig.ART and the board Icon fields. Edge/Fill are 9-slice images (SliceCenter 88,88,152,152, SliceScale 0.5), white, tinted in Studio. The source SVGs/PNGs were removed after upload; they are in git history (commit 0537bc3, roblox-gui-prototypes/assets/leaderboard/).

Tuning​

LeaderboardConfig: CYCLE_SECONDS 10, REFRESH_SECONDS 120, FLUSH_SECONDS 60, FETCH_COUNT 100 (page maximum), SHOW_COUNT 10 (the layout has 10 places), WRITE_IN_STUDIO false. Changing a Store name starts that board from empty.
