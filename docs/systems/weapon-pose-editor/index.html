Weapon Pose Editor

Players fix the weapon hold for their own avatar. The built-in hold (Weapons) is tuned on the block R15 rig and scales by arm reach and hand size. That does not fix unusual body meshes, so each player can move the weapon and the hands, and change the weapon size. Every weapon is set on its own. The pose saves to the player's settings profile (one save serves the Lobby and the Game Instance), and every client sees it. The server validates and clamps every value.

At a glance​

Weapons and values​

WeaponsValues
Two-hand (IK): Shotgun, SMG, SR, AR, RocketLauncher, MachineGun (the HoldAnimConfig.LeftHand keys)Weapon scale; weapon height / forward / side / turn / tilt / roll (gun); right hand slide / up / side / turn / tilt / roll (right); left hand the same (left)
One-hand (WeaponPoseConfig.OneHand): Pistol, GrabhookWeapon scale; weapon height / forward / side (gun.x/y/z)
  • Moves: ±Move studs. Gun turns: ±GunTurn°. Hand turns: ±HandTurn° per axis, and the combined turn of one hand is capped at HandTurnTotal°.
  • Scale: ScaleMin–ScaleMax (0.80–1.20), default 1.00.
  • Data: { Weapons = { [name]: { gun?, right?, left?, scale? } }? }. Sanitize keeps only known weapons and allowed fields, drops non-finite numbers, clamps the rest and drops defaults (0, scale 1). An empty pose = the built-in hold, exactly.

How it works​

Math (WeaponPose)​

All turns and all gun moves are in Handle space (+X = toward the muzzle = "forward", +Y = up, +Z = right): yaw about Y, pitch about Z, roll about X. Not shoulder space: the aim pose twists the waist, so the shoulder axes point away from the barrel ("forward" moved the AR sideways).

  • rightTarget: the right-hand IK target (shoulder space) moved by gun.x/y/z along the Handle axes and turned about the grip point. The gun moves; the hand follows it.
  • gripFor: the RightGrip C0.
    • Two-hand: the hand slides and turns on the gun by right (the gun stays at its target).
    • One-hand: there is no IK, so C0 moves the weapon by gun.x/y/z in the hand.
  • leftTarget: the left-hand target on the Handle, scaled with the weapon, then moved and turned by left.
  • toolGrip is Tool.Grip after Tool:ScaleTo(scale); the scale also scales the grip.

Server​

  • SettingsManager sanitizes the saved pose on load and sets the WeaponPose Player attribute (JSON). SaveWeaponPose is dropped inside SaveCooldown; otherwise the server sanitizes, stores and shares the pose.
  • ToolGripService fits each RightGrip on grip creation and on every attribute change: Tool:ScaleTo(scale) (pose weapons only), then C1 = Tool.Grip, then C0 = WeaponPose.gripFor(...). The scale is server-side, so all players see it.
  • WeaponPoseDisplay: on EquipPoseDisplay(name) the player holds a script-free copy of that weapon, named PoseDisplay with the attribute PoseOf = weapon name. The hold code reads it through HoldAnimConfig.holdName. Weapon systems look up WeaponConfig[tool.Name], so they ignore it (no fire, no ammo). It is destroyed when it leaves the character. SessionState.CaptureTools skips it. Source: ServerStorage.PoseDisplayWeapons (Lobby), else StarterPack.

Client​

  • WeaponIK reads every player's WeaponPose attribute. For the local player it uses Signals.WeaponPosePreview while the editor is open, and also previews the scale with a local Tool:ScaleTo. One-hand weapons are held only for the local player (to keep the previewed grip); other players get their one-hand grip from the server.
  • Each arm IK has an elbow pole (HoldAnimConfig.ElbowPole, scaled by the arm reach). The end effectors are grip Attachments, not the hands, so without a pole the solver does not treat the chain as an arm and can twist the shoulder or flip the elbow.
  • The left hand reaches at most 95% of the straight arm. Past that, its target slides back along the gun toward the right hand (LeftWarn), so the hand stays on the gun instead of floating off it.
  • The right-hand target is capped at ReachCap of the measured arm reach. WeaponIK fires Signals.WeaponPoseReach(rightCapped, leftSliding) when that changes; the editor shows the RightWarn / LeftWarn warnings.

Editor (WeaponPoseEditorController)​

  • Opens on Signals.OpenWeaponPoseEditor (Settings EDIT button). Picks the held weapon if it is a pose weapon, else the weapon picked last time.
  • While open: movement off; every other enabled PlayerGui ScreenGui and the TextChatService chat window and input bar are hidden (the Roblox top bar stays); an orbit camera puts the avatar on the free side of the screen. All come back on close.
  • Camera: left- or right-drag (or touch-drag) turns, middle-drag pans (up to PAN_MAX studs), wheel or pinch zooms. A mouse drag locks the cursor in place and reads GetMouseDelta; a press on the editor GUI (GetGuiObjectsAtPosition) does not start one. The Controls box (bottom left) lists these; on touch it shows DRAG / PINCH and hides Pan.
  • The preview is live: every slider step fires WeaponPosePreview, and WeaponIK moves the IK targets first and writes the RightGrip last.
  • Equipping a hotbar weapon closes the editor.
  • Sliders fill from the center (0 = middle). The value text is muted at the default.
  • Reset: this weapon back to the built-in hold. Reset all: asks first ("RESET ALL WEAPONS?").
  • Save: sends the full pose. A save inside SaveCooldown is queued and sent when the cooldown ends.
  • Close with unsaved changes asks first ("POSE NOT SAVED": CANCEL / DON'T SAVE / SAVE). SAVE saves, then closes. Death or respawn closes at once and drops unsaved changes.
  • Compact layout below a 0.68 scale (phones): a narrower Panel and smaller rows, built from the same templates.

Gotchas​

  • The server is the gate. A client can send any table; Sanitize is the only thing that reaches the profile and the attribute. Change limits in WeaponPoseConfig, never in the editor.
  • Change the math in WeaponPose only. Server (ToolGripService) and client (WeaponIK) both call it, so they agree.
  • The Lobby display weapons are copies. Re-copy a weapon into ServerStorage.PoseDisplayWeapons when its model changes in the Game Instance.
  • Check the math in the Command Bar: require(game.ReplicatedStorage.SharedModules.WeaponPose).selfCheck().
