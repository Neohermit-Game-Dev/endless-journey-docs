Proximity Pickup

Dropped craft-material Tools and shredder-ejected material handles register with a server pickup system; any player who walks into the detection sphere claims the item. Unclaimed items auto-collect to the owner after a configurable delay. The client plays a hover/spin effect on unclaimed items and a float-to-hand animation on claim.

At a glance​

Packets: PickupItemClaimed, PickupItemReady, RequestDrop — see Networking Map Signals: none — this system communicates only via Packets and Roblox-native events (AncestryChanged, CollectionService, zone.Touched)

How it works​

Drop path​

Pressing Backspace drops the equipped Tool as a direct child of workspace. A workspace.DescendantAdded listener in DroppedToolService catches craft-material Tools parented directly to workspace (the Roblox default Backspace drop path). The handle's CollisionGroup is set to "DroppedMaterial", CanCollide = true, Anchored = false. DropLandingHelper.waitForLanding(handle) then polls every DROP_POLL_INTERVAL (0.1 s) for DroppableSurface contact and a velocity below SETTLED_VELOCITY_THRESHOLD (0.5 studs/s). On landing, the handle is re-anchored with rotation reset to identity, and ProximityPickupServer.RegisterItem(tool, metadata, callback, keepModel=true) is called.

DroppedToolService also bootstraps two PhysicsService collision groups: DroppedMaterial (Tools that leave the player's hand) and DroppableSurface (tagged geometry). DroppedMaterial is non-collidable with Default and collidable with DroppableSurface, so dropped items fall through characters and walls but land on tagged floors.

Shredder path​

ShredderServer.ejectMaterials() anchors each handle at its landing position once its arc completes, then calls ProximityPickupServer.RegisterItem(handle, metadata, pickupCallback, false) and tags the handle "CraftMaterial" via CollectionService.

Registration and claim​

ProximityPickupServer.RegisterItem(part, metadata, callback, keepModel?) is the sole public registration entry. It generates a GUID itemId, sets PickupItemId on the part as an attribute, tags the part "PickupItem", spawns an invisible anchored sphere zone (DEFAULT_RADIUS = 6 studs) in workspace.PickupZones, and fires PickupItemReady to all clients. zone.Touched is the primary claim trigger — any player, shared-loot semantics. Claim(part, player) is the programmatic path used by the shredder's auto-collect loop. Both paths call the same executeClaimAsync, which transitions the record to "Claimed", destroys the zone, broadcasts PickupItemClaimed, then after FLOAT_DURATION (0.25 s) calls the callback and cleans up.

_TryMerge runs MERGE_DELAY (1 s) after registration and absorbs a newly registered handle into a nearby same-type unclaimed survivor within MERGE_RADIUS (2 studs), accumulating Quantity on the survivor. It skips keepModel items — merging would destroy one of the actual inventory objects, so only non-keepModel handles (shredder clones) are eligible.

Client hover and claim animation​

ProximityPickupController listens to two packets only; it creates no UI and does no proximity math. PickupItemReady applies a HoverEffect (bob + Y-spin) to the handle via a Janitor-managed cleanup handle, and wires AncestryChanged so the effect stops cleanly when the part is destroyed. PickupItemClaimed stops the hover effect, then for the local claimer plays a pickup SFX (via SoundManager.PlaySFXAt using CharacterAnchor to resolve the player's position) and tweens the handle toward the camera using MotionMaster.Play; for all other clients it destroys the handle immediately.

Auto-collect​

A 0.5 s poll loop in ShredderServer checks each dropped material's age. Once now - SpawnTime >= AUTO_COLLECT_DELAY (45 s), it calls ProximityPickupServer.Claim(mat, owner); if the item is not registered, the callback runs directly and the material is destroyed.

Gotchas​

Shared loot — not owner-only

Any player who steps into the pickup sphere claims the item, regardless of who dropped it or who the shredder owner was. The auto-collect timer (AUTO_COLLECT_DELAY in ShredderConfig, 45 s) returns unclaimed floor materials to the owner via ProximityPickupServer.Claim. If owner-only pickup is ever needed, the RegisterItem signature must be extended with an owner: Player? parameter and the zone.Touched handler must gate on it (see audit comment PP6 in ProximityPickupServer).

  • DroppableSurface tagging — no code change needed. Any BasePart tagged "DroppableSurface" in CollectionService is automatically assigned the DroppableSurface collision group at runtime via GetInstanceAddedSignal. To make a new floor or shelf surface catchable, tag it in Studio only.
  • Collision groups are registered in one place. CollisionGroups.luau (ServerStorage/SharedModules) is the sole registrar and owns the full collidability matrix. Besides DroppedMaterial/DroppableSurface, it defines Character (every character BasePart, assigned by CharacterCollisionService) and WeaponProjectile (thrown charges, assigned by ServerProjectile). Because characters now live in their own group rather than Default, dropped materials and projectiles both pass through players while still colliding with world geometry. Any system that needs a new group or a new pair rule should edit CollisionGroups.luau, not call PhysicsService directly.
  • keepModel semantics. When keepModel = true (the DroppedToolService path), the registered part is the actual Tool that will go into the player's Backpack — RegisterItem will not destroy it, and the callback sets tool.Parent = player.Backpack. When keepModel = false (the shredder path), the server clones the template, registers the clone, and the callback grants a fresh clone again; the floor handle is destroyed after claim.
  • Zone placement. Pickup zones are parented to workspace.PickupZones (not to the item part). This prevents "trying to set locked parent!" physics warnings when the zone is destroyed at claim time while the item is still mid-float.
  • Late-joining players. ProximityPickupServer registers a JoinSync sender ("ProximityPickups") that replays all currently "Unclaimed" PickupItemReady events once the joining client announces readiness, so items already on the floor will show their hover effect for late joiners. It no longer connects Players.PlayerAdded directly — see Join-Sync Snapshot Handshake for why a PlayerAdded push is unreliable.

Data flow​

sequenceDiagram
    participant P as Player
    participant DTS as DroppedToolService
    participant SS as ShredderServer
    participant PPS as ProximityPickupServer
    participant C as ProximityPickupController (client)

    alt Drop path
        P->>DTS: Press Backspace (Tool -> workspace)
        DTS->>DTS: DropLandingHelper.waitForLanding (poll 0.1s)
        DTS->>PPS: RegisterItem(tool, metadata, callback, keepModel=true)
    else Shredder path
        SS->>SS: ejectMaterials() arc completes, handle anchored
        SS->>PPS: RegisterItem(handle, metadata, callback, false)
    end

    PPS->>PPS: generate itemId, tag PickupItem, spawn sphere zone
    PPS->>C: PickupItemReady(part, itemId)
    C->>C: HoverEffect.Apply (bob + spin)

    par Zone touch
        P->>PPS: zone.Touched -> executeClaimAsync
    and Auto-collect (45s poll)
        SS->>PPS: Claim(mat, owner)
    end

    PPS->>PPS: record.State = Claimed, destroy Zone
    PPS->>C: PickupItemClaimed(itemId, claimer)
    C->>C: cleanup hover; if claimer == LocalPlayer, play SFX + float to hand; else destroy
    PPS->>PPS: after FLOAT_DURATION, callback(player, metadata) -> Backpack

Tuning​

  • Config module: ProximityPickupConfig — src/ReplicatedStorage/SharedModules/Configs/ProximityPickupConfig.luau
FieldDefaultEffect
DEFAULT_RADIUS6Studs; radius of the pickup sphere zone
FLOAT_DURATION0.25Seconds the handle floats to the player's hand after claim
HOVER_HEIGHT1.25Studs; bob amplitude of the hover effect
HOVER_DURATION2.25Seconds per half-cycle of the bob
SPIN_DURATION6Seconds per full Y-axis rotation while hovering
MERGE_RADIUS2Studs; maximum distance for same-type item merge
MERGE_ENABLEDtrueKill switch to disable merging globally
MERGE_DELAY1.0Seconds after registration before merge attempt
SETTLED_VELOCITY_THRESHOLD0.5Studs/s; handle velocity below this is considered at rest
DROP_POLL_INTERVAL0.1Seconds between GetTouchingParts checks during landing
DROP_LANDING_TIMEOUT60Seconds before giving up on a handle that never lands
