Battle Pass (Monthly)

A monthly, ProfileStore-backed pass with 60 levels and three reward tracks:

  • Scrap: free for everyone.
  • Flux: unlocked for one season with coins (BattlePassConfig.FluxPrice).
  • Void: unlocked for one season with a Robux developer product (BattlePassConfig.VoidProductId).

Pass EXP comes only from Pass Missions (see Quests — Pass Missions). The pass resets on a calendar-month boundary shared by every player and server. The GUI lives in the Lobby.

How it works​

Season and week maths​

BattlePassState.seasonIndex(now) = year*12 + (month-1), measured with the fixed BattlePassConfig.ResetTimezoneOffset (no daylight saving). seasonExpiresAt(now) is the unix time of the 1st of next month; the client uses it for the countdown. weekOfSeason(now) = floor((day-1)/7) + 1 (1..5) releases the weekly Pass Missions. The quest system's Season scope uses the same seasonIndex, so missions and the pass reset together.

Level is derived, never stored: levelFromExp(exp) and progress(exp) → (level, into, forNext) use ExpPerLevel (950 per level).

Profile​

{
    SeasonIndex = -1,                        -- -1 = adopt the current season on first load
    Exp = 0,
    Claimed = { Scrap = {}, Flux = {}, Void = {} }, -- [tostring(level)] = true
    Owned = { Flux = -1, Void = -1 },        -- season index the track was bought for
    Purchases = {},                          -- last 50 Void receipt ids
}

Claimed keys are strings: DataStores do not save sparse number keys. A track is owned when Owned[track] == seasonIndex, so ownership ends by itself on the 1st of the month. An old profile's ClaimedFree / ClaimedPremium maps move to Claimed.Scrap / Claimed.Void on load.

Rewards and claims​

BattlePassState.tierReward(level, track, seasonIndex) returns the card on one track (SeasonOverrides first, then Tiers). Server and client both call it, so they always agree. A reward is { Type = "Coins" | "Exp" | "PerkBox" | "SuperBox", Amount }:

TypePaid through
CoinsCoinManager.AddCoins
ExpXPManager.AddXP (player XP, not Pass EXP)
PerkBoxQuestManager.GrantBoxes(player, n, 0)
SuperBoxQuestManager.GrantBoxes(player, 0, n)

ClaimTier(player, track, level) checks, in order: profile loaded → level reached (NOT_REACHED) → track owned (NOT_OWNED; Scrap is always owned) → not claimed (ALREADY_CLAIMED) → the paying manager has the player's profile loaded (NO_PROFILE). Then it sets the claimed flag before the grant and replicates. ClaimAll(player) does the same for every card on every owned track, skips cards it cannot pay yet, and returns the grants merged by Type (NOTHING_TO_CLAIM when none).

Purchases​

  • Flux. BuyFlux → ALREADY_OWNED, or NOT_ENOUGH_COINS when CoinManager.DeductCoins(FluxPrice) fails, else Owned.Flux = season.
  • Void. RequestVoid (Lobby only):
    • NOT_FOR_SALE while VoidProductId == 0, when PolicyService reports ArePaidRandomItemsRestricted (the track holds super rare boxes), or when the policy call fails.
    • ALREADY_OWNED when owned this season.
    • UNKNOWN while a Void prompt is open (lock cleared by PromptProductPurchaseFinished or after 60 s).
    • Else it shows MarketplaceService:PromptProductPurchase.
  • Void receipt. Registered with ReceiptRouter only when sellVoid is true. It grants once per PurchaseId and returns PurchaseGranted only after a save holds the id (same settle pattern as the Quest Board products). A second Void receipt in a season that is already owned pays the Void track's coin total (trackTotals("Void", season).Coins) instead, so a double buy is never lost. The payout goes through CoinManager.RefundCoins (exact, no Fortune or party bonus), and the coin profile must save first (CoinManager.SaveAndWait): the receipt stays NotProcessedYet until the coins are saved, so a crash cannot grant the receipt with the coins lost.

Rollover​

ensureCurrent runs on join, before every EXP gain, claim and buy, and on the ROLLOVER_CHECK_SECONDS tick. When the season changed it first pays every reached, unclaimed card on Scrap and on each track owned in the old season, then resets Exp and Claimed. On join the manager waits (up to 30 s) for the coin, XP and quest profiles, so these grants land. Pass EXP that arrives before the profile is registered (the quest rollover pays old missions on join) is queued and added on load; it counts in the new season.

Client​

BattlePassClient caches the snapshot and exposes:

  • GetProgress(), GetLevel(), GetSeason(), GetSeasonExpiresAt(), GetWeek(), Owns(track)
  • GetTiers() → 60 rows { Level, Rewards = { Scrap, Flux, Void }, Unlocked, Claimed = { Scrap, Flux, Void } }
  • ClaimTier(track, level), ClaimAll() → (code, granted); Buy(track) → code (all yield)
  • Changed fires on every snapshot.

GUI (Lobby)​

StarterGui.BattlePassGui is built in Studio (not in Rojo). BattlePassGuiController binds it:

  • Open. The right-aligned TopbarPlus Pass icon (order 6) or Close. While open: Signals.RequestMouseIcon(true, "BattlePass"), ProximityPromptService.Enabled = false. Q / E switch tabs (key hints hidden without a keyboard). UIScale = min(1, w/1920, h/1080) on Pass, CoinConfirm and RewardsPopup.
  • Header. Level, Pass EXP bar, TIME LEFT (repainted every 30 s), season name (BattlePassGuiRules.seasonName).
  • Rewards tab. 60 LevelColumn clones in Scroller, scrolled so the current level is third from the left; the mouse wheel scrolls one column per notch. Card state = BattlePassGuiRules.cardState (lock / done / can / wait). A can card claims (ClaimTier); a lock card selects its track. Milestone shows milestoneFor(last visible level + 1). Claim All reads NOTHING TO CLAIM (disabled) when nothing can be claimed.
  • Detail. Badge click selects the track. Description = trackDescription(track, season). Scrap: FREE. Flux: YOU HAVE n + price; Buy opens CoinConfirm; NOT ENOUGH COINS / OWNED when disabled. Void: Robux price from GetProductInfoAsync (… until known); Buy → BattlePassClient.Buy("Void"); hidden while VoidProductId == 0; "NOT AVAILABLE IN YOUR REGION" when PolicyService restricts paid random items (or the policy call fails).
  • Missions tab. Categories WEEKLY (WEEK n MISSIONS OUT), SEASON (TIME LEFT …), EVENT (empty state NO EVENT RUNNING). Week tabs show released weeks only (BattlePassClient.GetWeek()); the latest is selected until the player picks another. Rows = QuestState.releasedSeasonQuests(week) with QuestClient.GetSeason() progress, sorted by BattlePassGuiRules.sortMissions (claimable → in progress → claimed, then config order). CLAIM → QuestClient.ClaimMission; Claim All → ClaimAllMissions; both open the popup with the Pass EXP. The latest week's rows show NEW until the player leaves that week (session memory). Amber dots on tabs, categories and weeks mark claimable missions (and the unseen latest week).
  • Popup. Every OK claim opens RewardsPopup with one card per granted reward (MotionMaster EaseOutBack pop-in, skipped with reduced motion). Ok or the dim closes it.
  • Errors show as a native SendNotification toast.
  • Icons. BattlePassConfig.Icons holds every pass image id: Coins, Exp, PerkBox, SuperBox, PassExp (reward cards, mission badges, the Flux price, the Quest Board super rare box row), Scrap / Flux / Void (track badge emblems) and Season (season card and topbar icon). A card whose icon id is empty shows a text label instead. The source PNGs are roblox-gui-prototypes/assets/battle-pass/out/sprites/ (coin, exp, perk_box, super_box, pass_exp, emb_scrap, emb_flux, emb_void, season).

Shop perk effects​

  • Season Surge (BPExpBonus): AddExp scales Pass EXP × (1 + bonus), rounded down, at least 1.

Gotchas​

Changing STORE_NAME orphans saved battle pass data

BattlePassConfig.STORE_NAME ("PlayerBattlePass") must stay identical in the Lobby and gameplay places. It is the shared ProfileStore key that lets session locking hand off across the teleport. Changing it points every player at a new, empty profile.

Void sells only in the Lobby

Only the Lobby registers the Void receipt. The Game Instance never prompts it; a stray Void receipt there returns NotProcessedYet and Roblox retries it in the Lobby.

Data flow​

sequenceDiagram
    participant QM as QuestManager (server)
    participant BPM as BattlePassManager (server)
    participant Client as BattlePassClient

    Client->>QM: ReqClaimMission(questId)
    QM->>BPM: Signals.OnQuestRewardGranted(player, reward)
    BPM->>BPM: AddExp(reward.BPExp) — ensureCurrent() first
    BPM->>Client: BattlePassStateSync

    Client->>BPM: ReqClaimPassTier(track, level) / ReqClaimAllPass()
    BPM->>BPM: checks; claimed flag set BEFORE grant
    BPM-->>Client: (code, granted)
    BPM->>Client: BattlePassStateSync

    Client->>BPM: ReqBuyPassTrack("Void")
    BPM->>BPM: policy check, prompt lock
    BPM-->>Client: code (OK = prompt shown)
    Note over BPM: ReceiptRouter → Void receipt → Owned.Void = season, save, PurchaseGranted
    BPM->>Client: BattlePassStateSync
