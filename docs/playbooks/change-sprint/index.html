Change Sprint Behavior

Goal: Adjust sprint speed, FOV curve, keybinds, or sprint state-machine logic.

Steps​

  1. Open the stamina/sprint config. Sprint constants share the file src/ReplicatedStorage/SharedModules/Configs/StaminaConfig.luau with stamina values. Both SprintController (client) and StaminaManager (server) read from this single config module.

  2. Update sprint speed.

    WalkSpeed  = 16   -- base walk speed (studs/s)
    SprintSpeed = 24  -- speed while sprinting

    Change SprintSpeed to the desired value. SprintController sets Humanoid.WalkSpeed directly and predicts locally; the server does not validate movement speed today (see Stamina & Sprint — Gotchas), so a speed change is purely a client-side/config edit.

  3. Update FOV.

    DefaultFOV = 70   -- camera FOV while walking
    SprintFOV  = 85   -- camera FOV while sprinting

    SprintController animates the transition. Changing these values alters the start and end points of the FOV tween — no animation code changes are needed.

  4. Update keybinds.

    SprintBinds = { Enum.KeyCode.LeftShift, Enum.KeyCode.ButtonB }

    Add, remove, or replace entries. Both gamepad and keyboard inputs are accepted in the same array. SprintController reads this array to register UserInputService listeners.

  5. If state machine behavior changes, mirror both sides. If you add a new sprint-blocking condition (e.g. a new "dash" state):

    • Edit src/StarterPlayer/StarterPlayerScripts/SprintController.client.luau for client-side prediction and visual feedback.
    • Edit src/ServerStorage/SharedModules/StaminaManager.luau for server-side authority and packet emission.
    • Update src/ReplicatedStorage/SharedModules/SprintValidation.luau if the validation predicates need to change (e.g. MinMoveDirection, MaxBackwardComponent, MinHorizontalSpeed) — this module is the single gate called identically by both sides.
    • Register any new packet in src/ReplicatedStorage/SharedModules/Packets/init.luau and document it in the networking map.

  6. Verify shift-lock interaction. SmoothShiftLock (vendored in src/ReplicatedStorage/SharedModules/SmoothShiftLock/) reacts to the sprint state. After changing sprint speed or keybinds, confirm that entering and exiting shift-lock while sprinting does not produce a stuck speed or FOV.

  7. Verify placement interaction. Build mode disables sprint while active. After changing sprint config, open build mode, attempt to sprint, and confirm it stays suppressed. Exit build mode and confirm sprint re-enables immediately.

  8. Test stamina drain under new speed. If SprintSpeed changed significantly, revisit StaminaDrain and StaminaRegen in the same config to ensure the economy still feels balanced. See Tune Stamina Economy for field details.

Verify​

Sprint in a straight line, confirm the WalkSpeed and FOV match the new config values. Trigger shift-lock while sprinting, confirm no stuck state. Enter build mode, confirm sprint is suppressed; exit, confirm sprint resumes. Open the Output window and confirm no StaminaManager sync errors.
