CoinManager

This item only works when running on the server. Server

Place-agnostic authority for the player coin wallet. Owns the PlayerCoins ProfileStore profile lifecycle (one session per player, key = UserId), the earn/spend/read API, and per-player replication via CoinStateSync.

Runs in BOTH the lobby and gameplay places. Coin sources (gameplay-session completion, daily/weekly challenges) and sinks (shop) are SEPARATE systems that call AddCoins / DeductCoins; they are not part of this module.

Cross-place: STORE_NAME + tostring(UserId) key are identical in every place of the universe, so the same DataStore record is shared. ProfileStore session-locking serializes the lobby↔gameplay teleport handoff automatically.

Functions​

GetCoins​

</>
CoinManager.GetCoins(player: Player) → number

Return the player's current coin balance, or 0 if the profile is not loaded.

AddCoins​

</>
CoinManager.AddCoins(
player: Player,
amount: number,
reason: string?
) → ()

Award amount coins to a single player. No-op if amount <= 0 or the profile is not loaded. Clamps the new balance to CoinConfig.MAX_BALANCE, then replicates. reason is an optional source tag recorded in the server log only (e.g. "DailyChallenge", "SessionComplete").

DeductCoins​

</>
CoinManager.DeductCoins(
player: Player,
amount: number
) → boolean

Atomically deduct amount coins from a single player. Returns true on success. Returns false with no mutation if amount <= 0, the profile is not loaded, or the balance is insufficient. This is the contract a future shop relies on.

RefundCoins​

</>
CoinManager.RefundCoins(
player: Player,
amount: number
) → ()

Return an exact amount of coins to a player (e.g. a perk-unlock refund). Unlike AddCoins, this is NOT scaled by the Fortune CoinGainBonus — a refund must return exactly what was paid, or unlock→respec cycling could mint coins. No-op if amount <= 0 or the profile is not loaded. Clamps to CoinConfig.MAX_BALANCE, then replicates.

Initialize​

</>
CoinManager.Initialize() → ()

Wire up the profile lifecycle. Call exactly once per server (from a loader).
