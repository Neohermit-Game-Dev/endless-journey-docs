Janitor Patterns

Janitor (howmanysmall/janitor) is the project's sole cleanup primitive. Never hand-roll { RBXScriptConnection } arrays with manual disconnect loops. Any scope that owns connections or instances — a per-character binding, a per-entity registration, a UI binding, a tool equip — must use a Janitor.

See Architecture Backbone for where Janitor fits in the broader module hierarchy.

Core rule: one Janitor per lifecycle scope​

Each distinct lifecycle gets exactly one Janitor. When that lifecycle ends, call :Cleanup or :Destroy on it (see below for which to use).

local ReplicatedStorage = game:GetService("ReplicatedStorage")
local Janitor = require(ReplicatedStorage.Packages.Janitor)

local janitor = Janitor.new()

-- Track a signal connection (cleaned up by calling :Disconnect)
janitor:Add(inst.Event:Connect(fn), "Disconnect")

-- Track an Instance (cleaned up by calling :Destroy)
janitor:Add(part, "Destroy")

-- Tear down and reuse (leaves the Janitor alive for the next cycle)
janitor:Cleanup()

-- Tear down and discard (the Janitor itself is gone afterward)
janitor:Destroy()

Cleanup vs Destroy​

MethodWhen to useTypical example
:Cleanup()The Janitor is module-level and reused across respawns or re-equips.characterJanitor, backpackJanitor — cleaned on every CharacterAdded, then refilled.
:Destroy()The Janitor is created per-entry and discarded when the entry is removed.WorkbenchEntry.Cleaner, engine/lever entry janitors.

Using :Destroy on a reused janitor silently breaks the next cycle because the object becomes unusable. Using :Cleanup on a per-entry janitor leaks the janitor table itself. Match the method to the ownership model.

Keyed-collection pattern​

When managing a dynamic set of entries (workbenches, junk pickups, registered engines, etc.), give each entry its own Janitor stored under a predictable key:

-- Type annotation (Luau)
type Entry = {
    model: Model,
    cleaner: Janitor.Janitor,
}

local registry: { [string]: Entry } = {}

local function register(id: string, model: Model)
    local entry: Entry = {
        model = model,
        cleaner = Janitor.new(),
    }
    entry.cleaner:Add(model, "Destroy")
    entry.cleaner:Add(model.ChildAdded:Connect(function(child)
        -- ...
    end), "Disconnect")
    registry[id] = entry
end

local function unregister(id: string)
    local entry = registry[id]
    if entry then
        entry.cleaner:Destroy()  -- per-entry → Destroy
        registry[id] = nil
    end
end

The pattern guarantees that removing an entry also disconnects every signal and destroys every instance that entry owns, with no possibility of leaking a handle.

Singleton exception​

Top-level controller connections that live for the full session do not need a Janitor. If the connection is created once at script root and never torn down (for example, Players.LocalPlayer.CharacterAdded at the top of a client controller), wrapping it in a Janitor adds overhead with no benefit.

Only use a Janitor when the scope can end before the script does.
