Battle Pass (Monthly)

A monthly, ProfileStore-backed progression track layered on top of the quest system's EXP feed. A single 60-tier track carries two reward rows — Free (everyone) and Premium (active Roblox subscribers) — and resets on a calendar-month boundary shared by every player and server. Structured shared/server/client like Quests and Perks. No GUI ships this cycle.

How it works​

Season math​

The season index is a calendar-month index, not a rolling 30-day window: BattlePassState.seasonIndex(now) = year*12 + (month-1), computed in the timezone defined by BattlePassConfig.ResetTimezoneOffset (a fixed seconds-from-UTC offset, pre-launch default US Eastern -5*3600, mirroring QuestConfig.ResetTimezoneOffset). Being a fixed offset, month boundaries do not track daylight saving.

BattlePassState.seasonIndex(now: number): number
BattlePassState.seasonExpiresAt(now: number): number -- unix ts of the 1st of next month

The underlying day math (daysFromCivil) is a pure-integer proleptic-Gregorian calculation (Howard Hinnant's algorithm), so client and server always agree without relying on os.date's host timezone handling. seasonExpiresAt is sent to the client so it can drive a countdown without any client-side date math. The server re-checks online players for a rollover — and refreshes cached premium status — every BattlePassConfig.ROLLOVER_CHECK_SECONDS (default 60s).

The quest system's Season scope (see Quests — Season quests) uses this exact same seasonIndex as its period key, so a battle pass season and its season-long quests always start and end together.

EXP earning​

There is no gameplay source that awards battle pass EXP directly. Instead, BattlePassManager subscribes to Signals.OnQuestRewardGranted — fired by QuestManager.grantReward on every quest reward grant, manual claim or rollover auto-sweep alike — and reads the optional Reward.BPExp field off the quest's reward table:

Signals.OnQuestRewardGranted:Connect(function(player, reward)
    if reward and reward.BPExp then
        BattlePassManager.AddExp(player, reward.BPExp, "Quest")
    end
end)

Any quest can feed the pass just by adding a BPExp number to its Reward table — no new signal or wiring per quest. The shipped pool leans on this for its dedicated Scope = "Season" quests: three quests (SeasonJunk, SeasonKills, SeasonDistance), the whole set active for the entire month, each paying 0 coins/exp but 3000 BPExp. Regular Daily/Weekly quests also carry smaller BPExp amounts (e.g. JunkDailyA pays 200), so ordinary questing keeps the pass moving too.

Tier track and bulk claim​

BattlePassConfig.Tiers[level] (level = 1..MAX_LEVEL, MAX_LEVEL = 60) is a { Free: Reward?, Premium: Reward? } pair. A Reward is either { Type = "Coins", Amount } or { Type = "Item", ItemId } (an empty ItemId = "" marks a milestone slot not filled in yet).

Tier kindFree rowPremium row
RegularCoins = 100 + (level-1)*10Coins = 150 + (level-1)*15
Milestone (15/30/45/60)Chunkier 500-coin bonusEmpty accessory Item slot (to be filled)

BattlePassConfig.SeasonOverrides[seasonIndex][level] sparsely shadows the base Tiers entry for one specific season only (e.g. swap in a different accessory for one month while keeping the rest of the track the same):

BattlePassState.tierReward(level: number, row: "Free" | "Premium", seasonIndex: number): BattlePassConfig.Reward?

tierReward resolves the override first, falling back to the base table, and is used identically by the server (grant) and client (display) so the two can never disagree.

Level is derived, never stored:

BattlePassState.levelFromExp(exp: number): number
BattlePassState.progress(exp: number): (level: number, expIntoLevel: number, expForNextLevel: number)

levelFromExp walks MAX_LEVEL down to 1 and returns the highest level whose cumulative EXP threshold (BattlePassConfig.ExpPerLevel — a flat per-level number or a { [level]: number } table) is met; progress additionally returns the two extra values for a progress bar (both 0 once level >= MAX_LEVEL).

There is only one claim entry point:

function BattlePassManager.ClaimBattlePass(player: Player): (boolean, number, number, number, number)

Packets.ReqClaimBattlePass (no payload) invokes it, and it bulk-banks every unlocked-but-unclaimed reward across both rows in one call — there's no per-tier claim. Premium-row rewards are only granted while the player is currently premium. Claimed flags (ClaimedFree[level] / ClaimedPremium[level]) are set before the grant executes (the same idempotent-guard pattern as QuestManager.ClaimQuest), so a re-entrant call finds nothing outstanding and returns NOTHING_TO_CLAIM rather than double-paying. Returns (ok, reasonCode, freeCount, premiumCount, coinsGranted); counts/coins are 0 on any failure. Result codes (BattlePassResultCodes): OK = 0, NO_PROFILE = 1, NOTHING_TO_CLAIM = 2.

Premium (subscriptions)​

Premium is never persisted — it's live-resolved from MarketplaceService:GetUserSubscriptionStatusAsync(player, SUBSCRIPTION_ID) and cached in-memory per session (premiumCache, keyed by Player). The cache is (re)populated at three points:

TriggerWhy
JoinBefore the first sweep/replicate
MarketplaceService.PromptSubscriptionPurchaseFinishedThe prompt closing doesn't guarantee a successful purchase, so status is always re-resolved rather than assumed
Periodic rollover tickBounds staleness to ROLLOVER_CHECK_SECONDS

resolvePremium yields (a web call), so it only ever runs from spawned contexts — never from the synchronous AddExp/ClaimBattlePass paths, which read the cache. On a false→true transition (a fresh subscribe), onPurchaseFinished retroactively runs a sweep granting the Premium row for every tier already reached this season, so buying mid-season immediately feels rewarding instead of only affecting future tiers. Packets.ReqPromptPremium (no payload, server-initiated) calls MarketplaceService:PromptSubscriptionPurchase — the prompt must originate server-side.

While BattlePassConfig.SUBSCRIPTION_ID = "" (the pre-launch default), premium is never granted and the subscription APIs are skipped entirely — resolvePremium short-circuits to false and ReqPromptPremium returns false without calling MarketplaceService, so pre-launch never spams errors for a subscription that doesn't exist yet.

Rollover and auto-grant sweep​

ensureCurrent (called at the top of AddExp and ClaimBattlePass, on join, and on the rollover tick) compares the profile's stored SeasonIndex against BattlePassState.seasonIndex(os.time()). On a mismatch it first auto-grants every reached-but-unclaimed tier from the old season (Free always; Premium only if the player is currently premium) via the same sweep helper the manual claim uses — nothing earned is lost just because a player never opened a claim UI before the month rolled. It then resets Exp = 0, ClaimedFree = {}, ClaimedPremium = {}, and advances SeasonIndex to the current value. Coins and items already granted by the sweep persist wherever they live (the coin wallet, a future inventory) — only the pass's own tier/EXP bookkeeping resets.

Item seam​

Item-type rewards fire Signals.OnBattlePassItemGranted(player, itemId) — a seam with no consumer this cycle, reserved for a future inventory/accessory system. Milestone tiers ship with an empty Premium Item slot (ItemId = ""); granting one is a no-op (no signal fires) and logs a one-time warning (warnedEmptyItem, a module-level flag) reminding a developer to fill BattlePassConfig with a real asset before launch. The claimed flag is still set even for an empty slot, so it's marked claimed and never re-offered.

Client​

BattlePassClient is a GUI-agnostic read-model, same shape as QuestClient/PerkClient. It caches the authoritative BattlePassStateSync snapshot and derives per-tier views using the same BattlePassState.tierReward the server grants from:

export type TierView = {
    Level: number, FreeReward: BattlePassConfig.Reward?, PremiumReward: BattlePassConfig.Reward?,
    IsUnlocked: boolean, IsFreeClaimed: boolean, IsPremiumClaimed: boolean,
}

Exposes GetProgress (level, expIntoLevel, expForNextLevel), GetLevel, IsPremium, GetSeasonExpiresAt, GetTiers (all 60, in order), GetClaimableSummary (a preview of what a Claim() would bank right now — counts + coin total, without actually claiming), and fire-and-forget Claim() / PromptPremium() commands. A Changed signal fires on every snapshot update. No GUI ships this cycle — a future screen requires BattlePassClient and subscribes to Changed.

Gotchas​

Changing STORE_NAME orphans saved battle pass data

BattlePassConfig.STORE_NAME ("PlayerBattlePass") must stay identical in the lobby and gameplay places — it's the shared ProfileStore key that lets session-locking hand off cleanly across the teleport boundary. Changing it points every player at a brand-new, empty profile: all season progress and claimed flags become unreachable.

An empty ItemId slot grants nothing — and is still marked claimed

A milestone Item reward with ItemId = "" is a placeholder. Granting it fires no OnBattlePassItemGranted signal (nothing to grant) but still flips the claimed flag, so the player never sees it offered again even after you fill in a real ItemId later — fill milestone slots before launch.

Data flow​

sequenceDiagram
    participant QM as QuestManager (server)
    participant BPM as BattlePassManager (server)
    participant Client as BattlePassClient (owning client)

    Note over QM: quest CLAIM or auto-sweep
    QM->>QM: grantReward() — CoinManager.AddCoins, XPManager.AddXP
    QM->>BPM: Signals.OnQuestRewardGranted:Fire(player, quest.Reward)

    alt reward.BPExp present
        BPM->>BPM: AddExp(player, reward.BPExp) — ensureCurrent() first
        BPM->>BPM: profile.Data.Exp += amount
        alt derived level rose
            BPM->>BPM: Signals.OnBattlePassLevelUp:Fire(player, newLevel)
        end
        BPM->>Client: BattlePassStateSync (season, exp, level, progress, claimed, premium, expiresAt)
    end

    Note over Client,BPM: bulk CLAIM
    Client->>BPM: ReqClaimBattlePass()
    BPM->>BPM: ensureCurrent(); sweep(1..level) — Free always, Premium if isPremium
    BPM->>BPM: claimed flags set BEFORE grant (idempotent guard)
    BPM-->>Client: (ok, reasonCode, freeCount, premiumCount, coinsGranted)
    BPM->>Client: BattlePassStateSync (reconciled snapshot)
