Economy (Coins)

Server-authoritative coin wallet persisted with ProfileStore, in a profile separate from XP. The balance is shared across the lobby and gameplay places.

At a glance​

LayerFileRole
Clientsrc/StarterPlayer/StarterPlayerScripts/CoinController.client.luauBridges CoinStateSync to Signals.OnCoinsChanged
Serversrc/ServerStorage/SharedModules/CoinManager.luauSole wallet authority: profile lifecycle, earn/spend/read API, replication
Serversrc/ServerScriptService/CoinSystemLoader.server.luauCalls CoinManager.Initialize() once per server (place-agnostic)
Configsrc/ReplicatedStorage/SharedModules/Configs/CoinConfig.luauSTORE_NAME, STARTING_BALANCE, MAX_BALANCE

Packets: CoinStateSync — see Networking Map Signals: OnCoinsChanged — see Signals Map

How it works​

Data model​

The PlayerCoins profile stores a single value, Coins. STORE_NAME ("PlayerCoins") and the UserId key are identical in every place of the universe, so the lobby and gameplay share one DataStore record; ProfileStore session-locking serializes the teleport handoff. Wallet bounds (STARTING_BALANCE, MAX_BALANCE) live in CoinConfig.

Wallet API (server-authoritative)​

CoinManager is the sole authority — every mutation goes through one of these four functions:

function CoinManager.GetCoins(player: Player): number
function CoinManager.AddCoins(player: Player, amount: number, reason: string?)
function CoinManager.DeductCoins(player: Player, amount: number): boolean
function CoinManager.RefundCoins(player: Player, amount: number)

AddCoins scales the amount by the Fortune perk's CoinGainBonus (math.max(1, math.floor(amount * (1 + bonus))), a 1-coin floor) and clamps to MAX_BALANCE; reason is an optional source tag logged server-side only. DeductCoins is atomic — it returns false with no mutation on amount <= 0, a missing profile, or insufficient funds. RefundCoins returns an exact amount and is not scaled by CoinGainBonus, so unlock→respec cycling can't mint coins.

Sources​

SourceCallNotes
Quest rewardsCoinManager.AddCoins(player, quest.Reward.Coins, "Quest:"..questId)Paid by QuestManager's shared grantReward path (manual claim or rollover auto-grant). Scaled by CoinGainBonus.
Battle Pass tiersCoinManager.AddCoins(player, reward.Amount, "BattlePassFree:"..level) / "BattlePassPremium:"..levelPaid by the bulk-claim sweep for Coins-type tier rewards. Scaled by CoinGainBonus. Premium row is gated by a Roblox subscription (BattlePassConfig.SUBSCRIPTION_ID), not a one-time purchase — that gates the reward row, it does not grant coins directly.

Quests also pay an EXP reward via XPManager.AddXP — a separate system with its own profile. See Quests and Battle Pass.

Sinks​

SinkCallNotes
Perk unlockCoinManager.DeductCoins(player, perk.UnlockCost)PerkManager.UnlockPerk pays a perk's one-time unlock cost. See Perks — Unlock gate.
Respec refundCoinManager.RefundCoins(player, perk.UnlockCost)PerkManager.Respec reverses the unlock cost exactly (not scaled by CoinGainBonus) for every perk it re-locks.

Perk unlocking is the first implemented sink; quest/battle-pass rewards are the first implemented sources.

Replication​

Every successful mutation fires CoinStateSync(balance: U32) to the owning client. CoinController re-fires it as Signals.OnCoinsChanged(balance) for a future coin HUD. There is no client→server packet — earning and spending are fully server-driven.

Not yet built​

Additional earning sources (gameplay-session completion), additional sinks (a shop + purchase packet), and the coin HUD are separate systems that would call the CoinManager API — they are not part of the wallet module.

Data flow​

sequenceDiagram
    participant QM as QuestManager / BattlePassManager (server)
    participant PM as PerkManager (server)
    participant CM as CoinManager (server)
    participant Client as CoinController (owning client)

    QM->>CM: AddCoins(player, amount, reason) — scaled by CoinGainBonus
    PM->>CM: DeductCoins(player, cost) / RefundCoins(player, cost) — exact, unscaled
    CM->>CM: clamp to MAX_BALANCE; profile.Data.Coins mutated
    CM->>Client: CoinStateSync(balance)
    Client->>Client: Signals.OnCoinsChanged:Fire(balance)

Tuning​

  • Config module: CoinConfig — src/ReplicatedStorage/SharedModules/Configs/CoinConfig.luau
  • No dedicated playbook for the wallet itself — reward amounts that flow through it are tuned via Tune Quests, Tune Battle Pass, and Tune Perk Unlocks.
