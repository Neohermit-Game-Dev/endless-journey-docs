Tune Shredder Economy

Goal: Adjust hold duration, arc animation, anti-exploit tolerances, or material yield for the Workbench Shredder.

Steps​

  1. Open the shredder config. All shredder constants live in src/ReplicatedStorage/SharedModules/Configs/ShredderConfig.luau.

  2. Tune hold duration. The required hold scales linearly between one junk item and MAX_JUNK_COUNT items:

    FieldDefaultEffect
    MIN_HOLD_DURATION0.3 sHold time required for exactly 1 junk item
    MAX_HOLD_DURATION3.5 sHold time required when carrying MAX_JUNK_COUNT or more items
    MAX_JUNK_COUNT10Junk count at which duration is fully capped at MAX_HOLD_DURATION

    Increase MAX_HOLD_DURATION to make large batches feel weightier. Keep MIN_HOLD_DURATION above the sum of normal round-trip latency to avoid the server rejecting fast single-item shreds.

  3. Tune arc animation.

    FieldDefaultEffect
    ARC_HEIGHT_BOOST5 studsExtra Y added to the bezier midpoint — controls arc peak height
    ARC_DURATION0.55 sTravel time per material Tool from spawn to landing
    ITEM_EJECT_DELAY0.125 sStagger between consecutive ejected materials
    LANDING_SCATTER_RADIUS1.5 studsRandom spread around LandingPoint for a natural pile effect
    MAX_ANIMATED_EJECT_ITEMS60Cap on visually animated items per shred
    MAX_STREAM_DURATION6.0 sBudget cap for the full ejection stream (compresses delay if needed)

  4. Handle anti-exploit tolerances with care. These fields directly affect server-side rejection rates. Tighten them only after validating against real network conditions:

    FieldDefaultRisk of over-tightening
    INTERACT_DISTANCE_TOLERANCE5 studsAdded on top of INTERACT_DISTANCE (10 studs) server-side to cover positional desync. Reducing below 3 will cause false rejections on high-latency clients.
    HOLD_COMPLETION_TOLERANCE0.5 sSubtracted from required hold when server validates timing. Setting below 0.3 will reject legitimate completions on 150ms+ RTT connections.
    PER_PLAYER_COOLDOWN1.0 sMinimum gap between consecutive successful shreds per player. Do not set below 0.5 s.

  5. Adjust material yield. Material types produced by a shred are determined by JunkConfig.MaterialRules in src/ReplicatedStorage/SharedModules/Configs/JunkConfig.luau:

    MaterialRules = {
        Metal  = {"Metal"},
        Wood   = {"Wood"},
        Energy = {"Energy"},
    }

    To add a new material output type, add an entry here and create a matching Tool template inside the CraftingMaterials folder in ReplicatedStorage (see step 6). After changing these mappings, re-test ShredderServer.buildMaterialSequence output in Studio.

  6. Verify Studio asset setup before testing. The shredder system requires the following to be in place in the live place:

    • Each workbench Model in Workspace must be tagged Workbench (CollectionService).
    • Each workbench Model must have its PrimaryPart set.
    • Each workbench must contain a child Model named TrajectoryPoints (field: TRAJECTORY_MODEL_NAME) with two invisible, anchored, non-collidable BasePart children: SpawnPoint (field: SPAWN_POINT_NAME) and LandingPoint (field: LANDING_POINT_NAME). Tag this model with PlacementIgnore.
    • ReplicatedStorage must contain a Folder named CraftingMaterials (field: MATERIALS_FOLDER) with Tool templates: Wood, Metal (and any new types). Each Tool must have a BasePart child named Handle and CanBeDropped = false.
    • Missing templates cause ShredderServer.ejectMaterials to fail silently.

  7. Test auto-collect delay. After ejection, materials lying on the floor auto-move to the owner's Backpack after:

    AUTO_COLLECT_DELAY = 45  -- seconds

    Adjust this if the window feels too long or too short for your gameplay loop.

Verify​

Run a solo session, carry a mix of junk counts (1 item, 5 items, 10 items), and hold the shredder interaction. Confirm hold durations roughly match the linear interpolation between MIN_HOLD_DURATION and MAX_HOLD_DURATION. Watch the arc animation and confirm materials land near LandingPoint. Check the Output window — a missing CraftingMaterials template will print a warning but not throw a visible error.
