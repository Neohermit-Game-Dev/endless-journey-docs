Chrono Replication

Character and NPC replication runs through Chrono (parihsz/chrono@2.2.0, Wally). Chrono replaces Roblox's fixed character interpolation delay with a dynamic buffer, and keeps server-side snapshot history that Weapons uses for lag compensation.

At a glance​

LayerFileRole
Sharedsrc/ReplicatedStorage/SharedModules/Chrono.luauWrapper: requiring it starts Chrono once; exposes Entity and client EnemyRenderTime()
Configsrc/ReplicatedStorage/SharedModules/Configs/ChronoConfig.luauSetConfig calls + ENEMY entity type
Serversrc/ServerScriptService/ChronoLoader.server.luauBoot-time start (player replication)
Clientsrc/StarterPlayer/StarterPlayerScripts/ChronoController.client.luauBoot-time start (interpolation)

Packets: none of its own — Chrono uses its own RemoteEvents inside the package. Lag compensation adds renderTime to ReqFireWeapon (see Networking Map). Signals: none.

How it works​

Start order​

Every consumer requires SharedModules/Chrono, never Packages.chrono directly. The wrapper calls chrono.Start(Configs.ChronoConfig) at require-time, so Chrono is always started (and its config locked) before any entity is created. ChronoConfig must only be required by Start — its SetConfig/RegisterEntityType calls assert if the config is already locked.

Players​

PLAYER_REPLICATION = "AUTOMATIC" (Chrono default). Chrono registers each character as a PLAYER entity (NATIVE mode, dynamic buffer, always replicated), owned by its player. No project code touches this.

Enemies (EnemyChrono)​

EnemySpawner.placeAt calls EnemyChrono.Track(model) right after parenting the model (before EnemyBrain.Register). Every spawned NPC — enemy or friendly — becomes an ENEMY entity in NATIVE mode: Roblox still replicates the model (animations, health, client raycasts and FX keep working), and Chrono overrides the client CFrame with its interpolated value. NATIVE was chosen over NATIVE_WITH_LOCK (server physics would act anchored, breaking Humanoid:MoveTo) and CUSTOM (hides the server model from clients).

EventActionWhy
Humanoid.DiedEntity.PauseReplicationClients stop forcing the CFrame; the body falls with normal physics.
Model leaves the DataModelEntity.Destroy, drop from tracked mapServer Entity.Destroy destroys the model, so it only runs once the model is already gone.

EnemyChrono.Tracked() returns the live { [Model]: Entity } map that LagCompensation reads. Server history: MAX_SNAPSHOT_COUNT (30) at 30 Hz = 1 s.

Lag compensation (LagCompensation)​

Server module used by WeaponServer for hitscan. See Weapons — Lag compensation for the flow. Key facts:

  • ENEMY.STORE_SNAPSHOTS = true is what makes rewind work — without it the server keeps only the latest CFrame.
  • Client render time is in the server os.clock() domain (Chrono sends server os.clock() quantized to 0.1 ms). ClampRewind snaps whole u32 wraps (~4.97 days of uptime).
  • Exploit ceiling: a cheater may choose any time inside their own window (≤ 1 s).
  • Limits: rigid rewind (current animation pose); half-ticked NPCs (> 150 studs) use the NORMAL clock as an approximation.

Gotchas​

  • wally install wipes TweenPlus's TweenPreallocations attribute — re-set it to 256 in Studio (see Toolchain).
  • wally install also deletes the empty ServerPackages/ folder (there are no server dependencies). default.project.json maps it as an optional path, so Rojo skips it when missing.
  • Chrono's source uses the Luau const keyword. If Luau LSP flags it inside Packages/, that is an LSP version issue only.
  • Server-side character teleports (e.g. PlacementServer's push-out PivotTo) are caught by Chrono's default REPLICATE_CFRAME_SETTERS = "PLAYER_ENTITIES": the HRP CFrame change becomes an Entity.SetCFrame teleport, so other clients snap (no slide) and the server ignores the owner's normal updates until a teleport-flagged packet arrives (≤ 0.5 s + ping).
  • Remote players are only interpolated if their PrimaryPart (HRP) is the assembly root — the built-in PLAYER type has ASSEMBLY_ROOT_PART_CHECK = true and silently skips otherwise (Warn.low). Verify with SingleCollider (CollisionPart) avatars.
  • Chrono sets every tracked NPC root's network owner to the server (nil).
  • StreamingEnabled interaction is unverified.
