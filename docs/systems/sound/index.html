Sound

A layered client audio system built around a single facade module, SoundManager. All game audio — one-shot SFX, positional SFX, looped sounds, background music, and ambience beds — flows through it; no other script creates Sound or AudioPlayer instances directly. It is built on the advanced audio API, and every asset is loudness-normalized automatically, so sounds play at the same level without hand-tuned volumes. Playback is entirely client-local except for positional SFX replication and BGM context, which are server-relayed/server-driven through Packets.

How it works​

Facade and playback​

SoundController.client.luau calls SoundManager.Init() once at startup. Init creates the bus graph and listener (Groups.Ensure), starts measuring every known asset in the background (Normalizer.Prime), warms the positional sound pool (Pool.Ensure plus per-asset pre-warm), connects the replication receiver (SFX.ConnectReplication), and autostarts any ambience beds listed in SoundConfig.Ambience.Autostart. Asset preloading happens earlier, in ReplicatedFirst/LoadingScreen.client.luau: it preloads every rbxassetid:// string in the Configs modules plus every Sound in the replicated services through PreloadLib.

After Init, any client script or tool may require(SharedModules.SoundManager) and call the facade (PlaySFX, PlaySFXAt, PlayLooped, PlayMusic, SetAmbience, SetVolume). The submodules (Groups, Normalizer, AudioMath, Pool, SFX, Music, Ambience) are internal and should not be required directly.

Signal chain​

flowchart LR
    P2D["AudioPlayer (2D SFX, loops, BGM, ambience)"] --> BA
    P3D["AudioPlayer (positional)"] --> SH[AudioPitchShifter] --> EM[AudioEmitter on a pooled part]
    EM -. "InteractionGroup SoundManager" .-> L[AudioListener on CurrentCamera]
    L --> BA
    BA["Bus fader A (SFX / BGM / Ambience)"] --> BB[Bus fader B]
    BB --> M["Master fader pair"] --> LIM["AudioLimiter (MaxLevel -1 dB)"] --> OUT[AudioDeviceOutput]

The listener feeds the SFX bus. The bus instances live in SoundService.SoundManagerBuses (client-created). Each sound's AudioPlayer.Volume = clamp(gain × mix × fade, 0, 10):

  • gain comes from the normalizer and is fixed for the whole play.
  • mix is the config Volume (or opts.Volume), default 1.0.
  • fade is the MotionMaster fade in / out / crossfade.

Bus and Master faders are set only by SetVolume (the Settings system).

Loudness normalizer​

Normalizer loads each asset in an unwired, never-played AudioPlayer, waits for IsReady (gives up after 10 s), and reads GetWaveformAsync(0..TimeLength, Samples). AudioMath.LoudnessDb splits the samples into ~400 ms windows, drops windows below GateDb (silent intros and tails), and takes the RMS of the rest. The gain is 10^((TargetDb − measured) / 20), clamped to MinGain..MaxGain; an asset with no window above the gate gets 1.0 (never boosted). One gain per asset id per session; two requests for the same id share one measurement.

Init primes every id in SoundConfig (beds and playlist tracks first, then SFX) one at a time in the background. When a sound plays before its gain is known:

  • One-shots (PlaySFX, PlaySFXAt, replicated sounds) play at once at gain 1.0; the next play uses the real gain.
  • Loops, beds and music tracks wait up to 0.5 s for the gain, then start at 1.0. PlayLooped still returns its handle at once.

The normalizer reads only the raw asset, never a bus. Raising a bus raises every sound on it by exactly that factor. SoundConfig.Normalize.Enabled = false makes every gain 1.0 (A/B listening switch). Self-check from the Studio command bar:

loadstring(game.ReplicatedStorage.SharedModules.SoundManager.AudioMath.Source)().SelfCheck()

Positional replication​

The server does not play audio itself — ReplicatedSoundService.server.luau acts only as a validated relay for Packets.ReplicateSoundAtLocation:

  1. Per-player rate limit (MIN_INTERVAL = 0.05s) rejects bursts.
  2. Payload shape is validated (data.SoundConfig.Id must be a string).
  3. The sound ID must be in ALLOWED_SOUND_IDS, built at startup from SoundConfig.GetReplicatedIds() — any SFX entry with Replicate = true is included automatically.
  4. The original payload is passed to every other connected player via FireClient.

The receiving client's SFX.ConnectReplication handler acquires a pooled voice at the given position and plays it, the same path PlaySFXAt uses locally. The payload carries the sender's mix volume, never its gain; the receiver applies its own gain.

BGM contexts​

SoundConfig.Music.Playlists defines six named playlists — one per BGM context (Normal, Combat, LowFuel, Jump, Pursuit, Boss). There is no generic/default playlist; Music.Play falls back to "Normal" only when called with no argument.

ContextTriggerGap behavior
NormalDefault; nothing else activeGapped — random silence between tracks
CombatServer calls MusicService.SetContext(player, "Combat")Continuous — overlapping crossfade, no silence
LowFuelAutomatic, client-derived from fuel levelContinuous — overlapping crossfade, no silence
JumpAutomatic, from Packets.JumpStateSync while JumpDriveConfig.IsJumpActive(phase)Continuous; Shuffle = false
PursuitAutomatic: train stalled (Signals.OnTrainStateChanged), or the Threat Timer phase is Imminent (Packets.ThreatStateSync)Continuous — overlapping crossfade, no silence
BossAutomatic: the Threat Timer phase is Arrived (Packets.ThreatStateSync); outranks Combat so enemy waves do not cut itContinuous — overlapping crossfade, no silence

BGM tracks (BGMs folder)​

Track ids do not live in SoundConfig. BgmTracks.Get(playlist, biome) reads them from ReplicatedStorage.BGMs each time a playlist starts, so the artist adds or removes tracks in Studio with no code edit:

  • Normal and Combat are per-biome (PerBiome = true). They read the folder SoundConfig.Music.BiomeFolders[CurrentBiome] (NormalArea, VolcanoArea, IceArea, Void, StormArea).
  • LowFuel, Jump, Pursuit and Boss read the shared folder BGMs.Shared.
  • The lowercase Sound name gives the role: the role word (normal, battle, lowfuel, jump, pursuit, boss), optionally followed by digits (normal2) or by the artist's "maybe" marker (normal(?), normal(?2)). A track that still has its library name (Blizzard Approaching) is skipped. Only SoundId is read.
  • No folder, no biome entry, or no matching track → the playlist's config Tracks (empty today → silence).

MusicDirector passes the CurrentBiome workspace attribute to PlayMusic. When the biome changes while a per-biome context plays, the music crossfades to the new biome's tracks. During Jump (or any shared context) the change waits until a per-biome context comes back. Music.Play primes the normalizer with the resolved ids, because Init only measures ids that are in SoundConfig.

Priority when more than one condition is true: Jump > Boss > Combat > Pursuit > LowFuel > Normal. MusicDirector.client.luau holds five local inputs — jumpActive (from JumpStateSync), combatContext (set by the server), stalledActive and lowFuelActive (both derived locally from Signals.OnTrainStateChanged), and threatPhase (from ThreatStateSync) — and recomputes the resolved context on every change to any of them, calling SoundManager.PlayMusic(context) only when the resolved context actually changes. A low-fuel state during combat is suppressed without losing track position when combat ends.

Driving combat from server gameplay code (an event or outpost zone):

local MusicService = require(game.ServerStorage.SharedModules.MusicService)
MusicService.SetContext(player, "Combat") -- on event/outpost enter
MusicService.SetContext(player, "Normal") -- on event/outpost leave

MusicService.SetContext is stateless — it only fires Packets.SetMusicContext to the targeted player. Passing "Normal" clears the combat override; the client then falls back to LowFuel or Normal based on its own fuel state. Low fuel itself needs no gameplay code: MusicDirector watches Signals.OnTrainStateChanged and activates LowFuel whenever fuel / TrainConfig.MAX_FUEL drops below SoundConfig.Music.LowFuelPct (default 0.25).

Volume persistence​

The four buses (Master, SFX, BGM, Ambience) persist across sessions as part of the generic Settings system, not inside SoundManager itself. SoundManager.SetVolume(group, volume) / GetVolume(group) remain the immediate-apply primitives — they set the Groups fader pairs directly and do nothing else. AudioFader.Volume tops out at 3, so each bus is two faders in series: v splits as a = min(v, 3), b = v / a, which covers 0..9. Settings above 9 cap at 9. GetVolume returns the player's number, not the fader product.

UI code that needs the change saved calls SettingsClient.Set("MasterVolume" | "MusicVolume" | "SFXVolume" | "AmbienceVolume", value) instead. SettingsClient.Set validates via SettingsSchema, applies it (SettingsAppliers maps the key to a bus via SettingsConfig.VolumeBusByKey and calls Groups.SetVolume), fires Signals.OnSettingChanged(key, value), and schedules a debounced save (Packets.SaveSetting) that coalesces rapid changes (e.g. a slider drag) into one trailing send. On join, SettingsManager delivers the saved settings map via Packets.SyncSettings; SettingsClient applies each entry the same way but never re-saves a synced value, so no feedback loop results. See Settings for the full validate/apply/persist flow.

Gotchas​

Never create ad-hoc Sound or AudioPlayer instances

All audio must go through SoundManager. A hand-made Sound or AudioPlayer skips the buses (volume settings have no effect), skips the normalizer, skips the positional pool (memory churn), and may leak across character reloads.

Emitters need the interaction group

SoundService.DefaultListenerLocation creates a default AudioListener with an empty interaction group, wired straight to the device output. An AudioEmitter with an empty group is heard by that listener and skips the buses. Every emitter SoundManager creates, and its own listener, use SoundConfig.InteractionGroup ("SoundManager").

  • SoundManager.Init() must be called before any Play* call. It is called once by SoundController.client.luau; do not call it again elsewhere.
  • PlaySFXAt parents a pooled BasePart at the given Vector3 in the workspace; the pool releases it after TimeLength + 0.05 seconds. An asset that is not ready within 2 s is skipped. Do not hold references to the part or player after the call.
  • PlayLooped returns a LoopHandle. The caller must call handle:Stop() or handle:Destroy() when done — an abandoned handle leaks a live AudioPlayer under SoundService. The handle's Player field is the AudioPlayer; FadeTo(volume) sets the mix, the gain stays applied.
  • A sound entry with Replicate = true and an empty Id ("") is excluded from the allowlist automatically by GetReplicatedIds(); the pool warm step also skips empty IDs.
  • The BGM and Ambience buses default below 1.0, so music and ambience sit under SFX at the same mix value.
  • The AudioLimiter after Master is a safety net only. At very high settings it may hold peaks down instead of distorting.

Adding a new replicable SFX needs only Replicate = true on the SoundConfig.Sfx entry — GetReplicatedIds() and ReplicatedSoundService pick it up automatically on next server start.

Music playlist fields (SoundConfig.Music.Playlists):

FieldDescription
RoleBGMs track role this playlist reads ("normal", "battle", "lowfuel", "jump", "pursuit", "boss")
PerBiometrue: read the current biome's BGMs folder; otherwise the shared folder
TracksFallback asset IDs when the BGMs folder gives none; played in Shuffle order if set, else array order
ShuffleRandomize track order each time the playlist (re)starts
FadeInSeconds to fade a new track up from 0 at start
FadeOutSeconds to fade a track down to 0 at its end; also the crossfade overlap window when continuous

VolumeMix for tracks in this playlist, on top of the normalized level; default 1.0

Normalizer (SoundConfig.Normalize): Enabled (true), TargetDb (-18 dBFS RMS), MinGain (0.25, −12 dB), MaxGain (4, +12 dB, protects near-silent assets), Samples (4000), GateDb (-60).

SoundConfig.Music.LowFuelPct (default 0.25) is the fuel-fraction threshold below which MusicDirector activates the LowFuel context. SoundConfig.Music.BgmFolder ("BGMs"), SharedFolder ("Shared") and BiomeFolders (biome id → BGMs subfolder) locate the tracks; every JumpDriveConfig.Biomes id needs a BiomeFolders entry.
