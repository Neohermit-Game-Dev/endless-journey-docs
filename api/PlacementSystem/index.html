PlacementSystem

Shared placement and validation system used by both the client-side preview (PlacementClient) and the server-side anti-exploit validator (PlacementServer).

Visual-only features (TweenPlus colour transitions, grid Texture instances) are guarded by IS_CLIENT checks inside each method, so the same object can be constructed on the server without side-effects.

Model structure

Items under ReplicatedStorage/PlaceableItems are expected to contain:

  • VisualMesh — MeshPart or Part; visible geometry.
  • CollisionBox — Part; axis-aligned collision volume used for overlap testing and height correction.
  • RootPart (optional) — animation rig root; treated as PlacementIgnore and hidden.

Parts tagged PlacementIgnore are fully hidden and excluded from all collision checks.

Signals fired

  • Signals.OnBuildValidityChanged — fired by UpdateGhostPosition when IsValid flips.
  • Signals.OnPlacementModeChanged — fired by SetGridMode when the grid toggle changes.

SetBuildMode​

</>
PlacementSystem:SetBuildMode(
isActive: boolean--

true to enter build mode, false to leave it.

) → ()

Activates or deactivates build mode.

When isActive is true, grid Texture instances are created on every tagged build-area part. When false, those textures are destroyed and the current ghost model is cleared.

Client only

The server sets IsBuildMode = true directly to avoid creating Texture instances that would permanently replicate to clients.

BuildObstructionFilter​

</>
PlacementSystem:BuildObstructionFilter(
extra: {Model}?--

Additional models to include in the obstruction check.

) → {Instance}--

List of instances to pass to OverlapParams.FilterDescendantsInstances.

Builds the OverlapParams include-filter list used by CheckValidity.

The filter includes: every instance tagged PlacementObstruction (placed items and static world fixtures), the ghost-models folder, every player character except self.ExcludePlayer, if set, every faction-tagged NPC (EnemyNPC / FriendlyNPC, see Factions), and any extra models supplied by the caller.

CheckValidity​

</>
PlacementSystem:CheckValidity(

World-space CFrame of the collision box centre.

Size of the collision box.

Custom include-filter; falls back to BuildObstructionFilter when nil.

) → boolean--

true if placement is valid (no obstructions).

Returns true when the given collision box does not overlap any obstruction.

Uses workspace:GetPartBoundsInBox with an include-filter. The local ghost's own parts (GhostOwnParts) are excluded so the ghost never blocks itself. Pass filterOverride to supply a pre-built filter (e.g. with other players' ghosts included); if omitted, BuildObstructionFilter(nil) is called automatically.

UpdateGhostPosition​

</>
PlacementSystem:UpdateGhostPosition(
position: Vector3--

Surface position from CalculatePlacement.

) → CFrame?--

The ghost pivot CFrame, or nil if no ghost is active.

Moves the ghost to position, runs the collision validity check, colorizes the ghost, and returns the final world CFrame.

Fires Signals.OnBuildValidityChanged with the new boolean whenever IsValid changes, so UI and audio systems can react without polling.

Called every Heartbeat tick on the client.

LerpGhost​

</>
PlacementSystem:LerpGhost(
dt: number--

Frame delta time in seconds.

) → ()

Smoothly interpolates the ghost model toward TargetGhostCFrame each frame.

In grid mode only rotation is interpolated (position snaps instantly in UpdateGhostPosition). In free mode, both position and rotation are smoothed using frame-rate-independent exponential decay.

Should be called every Heartbeat with the frame delta time.

CalculatePlacement​

</>
PlacementSystem:CalculatePlacement(
rayOrigin: Vector3,--

World-space ray origin (typically the camera or mouse position).

rayDirection: Vector3--

World-space ray direction (magnitude determines max distance).

) → Vector3?--

Resolved surface position, or nil if no valid build area was hit.

Raycasts against tagged build-area parts and returns the resolved surface position (grid-snapped or free, based on IsGridMode), or nil if no build-area part was hit or IsBuildMode is false.

The raycast uses an include-filter limited to build-area parts, so placed objects are transparent to the ray. Overlap with placed items is handled separately by CheckValidity.

Also caches the hit part as self.LastBuildAreaPart for callers that need the platform bounds afterward (e.g. push-out-of-the-way logic).
