Tune Perk Unlocks

Goal: Choose which perks are free starters, set a perk's one-time coin cost / level gate, and reason about how those choices interact with respec refunds and the schema migration.

Steps​

  1. Choose a starter perk. A perk with UnlockCost = 0 (or omitted) and UnlockLevel = 0 (or omitted) is a free "starter" — PerkManager.seedStarters auto-unlocks it for every player on load and after every respec of its pool, with no coin or level requirement. Today the two starters are PlayerHP (Vitality, Personal) and JunkRarity (Salvage Luck, Party) — one per pool, so a brand-new player always has at least one perk to invest points in per pool.

    PlayerHP = { Category = "Personal", BuffKey = "HPBonus", PerLevel = 0.04, MaxLevel = 10, Order = 1,
        DisplayName = "Vitality", Description = "+%d%% Max HP", UnlockCost = 0, UnlockLevel = 0 }, -- starter

    To make a different perk a starter, set its UnlockCost and UnlockLevel to 0. To stop a perk from being a starter, give it a nonzero UnlockCost and/or UnlockLevel. If you remove starter status from every perk in a pool, players in that pool have nothing to unlock for free — make sure at least one perk per pool stays a 0/0 starter.

  2. Set a perk's coin cost and level gate. Open src/ReplicatedStorage/SharedModules/Configs/PerkConfig.luau and edit the entry:

    PassiveRegen = { Category = "Personal", BuffKey = "RegenBonus", PerLevel = 0.10, MaxLevel = 10, Order = 2,
        DisplayName = "Regeneration", Description = "+%d%% HP regen rate", UnlockCost = 250, UnlockLevel = 3 },
    • UnlockCost — coins deducted once, via CoinManager.DeductCoins, when the player unlocks the perk (ReqUnlockPerk → PerkManager.UnlockPerk).
    • UnlockLevel — minimum player XP level required before the unlock is allowed (PerkState.canUnlock rejects with LEVEL_REQUIRED below this).

    Both checks are enforced server-side by PerkState.canUnlock (order: unknown perk → already unlocked → level → coins), so there's no way to bypass them from the client. Changes take effect immediately for any not-yet-unlocked perk — there's no re-pricing concern for perks a player has already paid for, since the cost is only ever charged once.

  3. Remember costs are one-time; leveling stays point-based. UnlockCost is charged exactly once, at unlock. It has no effect on leveling a perk up afterward — that still costs 1 derived point per level from the pool's point economy (see Perks — Point economy), same as before this system existed. Raising UnlockCost makes a perk more expensive to access, not more expensive to level.

  4. Account for the respec-refund consequence. PerkManager.Respec fully resets a pool: it clears levels, re-locks every perk in that pool, and refunds each perk's UnlockCost via CoinManager.RefundCoins (exact — not scaled by the Fortune perk's CoinGainBonus, unlike CoinManager.AddCoins). This means the coin cost you set is exactly what comes back on respec. A perk with UnlockCost = 800 (Heavy Ordnance) returns 800 coins when its pool is respecced; a starter (UnlockCost = 0) returns nothing and simply stays unlocked (starters are re-seeded after the clear). If you want respec to feel cheap or costly for the player, tune UnlockCost with that in mind — there is no separate respec-refund knob.

Verify​

  1. Join in Studio with API Services enabled.
  2. Confirm both starters (Vitality, Salvage Luck) show unlocked with no coin/level prompt, and every other perk shows locked with its UnlockCost/UnlockLevel.
  3. Earn enough coins and level to satisfy a locked perk's gate, unlock it, and confirm coins are deducted immediately and the perk becomes allocatable (buffs do not change from the unlock itself — only from subsequently spending points).
  4. Try to unlock a perk while under-leveled or under-funded and confirm the request is rejected (LEVEL_REQUIRED / NOT_ENOUGH_COINS) with no coin deduction.
  5. Allocate a few points into the unlocked perk, then respec its pool and confirm: levels clear, the perk re-locks, and its UnlockCost is refunded to the coin balance exactly (no Fortune scaling).

Gotchas​

Changing STORE_NAME wipes all saved perk + unlock data

PerkConfig.STORE_NAME ("PlayerPerks") is the ProfileStore key for both PerkLevels and Unlocked. Changing it points every player at a brand-new, empty profile — equivalent to wiping all perk progress and all unlocks. Only do this intentionally.

Lowering PerkSchemaVersion is not a way to re-wipe perk data

The one-time clean-slate migration (see Perks — Unlock gate) is guarded by profile.Data.PerkSchemaVersion < 1 and is deliberately one-shot per profile: it exists to wipe pre-unlock-gate allocations exactly once when this system shipped, not as a general-purpose "reset everyone" lever. Editing the stored version back down does not replay cleanly — PerkManager only ever bumps PerkSchemaVersion forward on load. If you need to force a full wipe later, change PerkConfig.STORE_NAME instead (see above), and expect it to also drop leveling progress, not just unlocks.
