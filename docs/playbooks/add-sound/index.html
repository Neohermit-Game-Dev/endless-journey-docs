Add a Sound (SFX / Music / Ambience)

Goal: Add a new game sound — one-shot SFX, positional SFX, looped SFX, a music playlist track, or an ambience bed — without ad-hoc Sound instances.

Rule: never create ad-hoc Sound instances. All audio goes through SoundManager. All asset IDs, volumes, and pitch live in SoundConfig.

Steps​

  1. Open SoundConfig. File: src/ReplicatedStorage/SharedModules/Configs/SoundConfig.luau. It exports three tables: SoundConfig.Sfx, SoundConfig.Music.Playlists, and SoundConfig.Ambience.Beds.

  2. Add your definition.

    One-shot / looped SFX — add an entry to SoundConfig.Sfx:

    MyNewSfx = {
        Id = "rbxassetid://XXXXXXXXXXXXXXXXX",
        Volume = 0.5,           -- optional; default engine volume if omitted
        Pitch = 1.0,            -- optional
        PitchRange = { 0.9, 1.1 }, -- optional; overrides Pitch; random per play
        Group = "SFX",          -- "SFX" | "BGM" | "Ambience"; default "SFX"
        Replicate = true,       -- set true only for positional sounds other clients should hear
        Debounce = 0.1,         -- optional; min seconds between plays (anti-spam)
        PoolInitial = 2,        -- optional; for PlaySFXAt only — pre-warms the pool at Init
        PoolMax = 8,            -- optional; hard cap for the positional pool
    },

    The SoundDef type (exported from SoundConfig) documents every field.

    Music track — add asset IDs to one of the three context playlists in SoundConfig.Music.Playlists (see BGM contexts below):

    Normal = {
        Tracks = { "rbxassetid://AAA", "rbxassetid://BBB" },
        Shuffle = true,
        FadeIn = 1.5,
        FadeOut = 1.5,
        GapMin = 60,
        GapMax = 300,
        Volume = 0.6,
    },

    Ambience bed — add to SoundConfig.Ambience.Beds and, if it should start automatically, add its name to SoundConfig.Ambience.Autostart:

    Beds = {
        MyAmbience = { Id = "rbxassetid://XXXXXXXXXXXXXXXXX", Volume = 0.4 },
    },
    Autostart = { "MyAmbience" }, -- fade in on SoundManager.Init()

  3. Play the sound from a client script. Require SoundManager (never instantiate a Sound directly):

    local SoundManager = require(ReplicatedStorage.SharedModules.SoundManager)

    -- One-shot 2D:
    SoundManager.PlaySFX("MyNewSfx")

    -- Positional (requires PoolInitial / PoolMax in the def for pre-warm):
    SoundManager.PlaySFXAt("MyNewSfx", somePosition)

    -- Looped SFX (returns a LoopHandle — call :Stop() to end it):
    local handle = SoundManager.PlayLooped("MyNewSfx")
    -- ...later:
    handle:Stop()

    -- Music playlist (normally driven by MusicDirector via context, not called directly):
    SoundManager.PlayMusic("Normal")

    -- Ambience (replaces current beds; use AddAmbience to layer):
    SoundManager.SetAmbience({ "MyAmbience" })
    SoundManager.AddAmbience("MyAmbience")
    SoundManager.RemoveAmbience("MyAmbience")
    SoundManager.StopAmbience()

    -- Volume bus (0..1):
    SoundManager.SetVolume("SFX", 0.8)

    SoundManager.Init() is called once by SoundController.client.luau — do not call it from feature code.

  4. Wire replication if needed. If other clients need to hear the sound when it plays at a world position, set Replicate = true in the SoundConfig.Sfx entry. The server relay uses SoundConfig.GetReplicatedIds() to build its allowlist. SoundConfig.GetPreloadIds() collects all non-empty IDs for ContentProvider:PreloadAsync.

BGM contexts​

Background music is context-driven, not played by name from feature code. MusicDirector.client.luau owns the active context and calls SoundManager.PlayMusic for you — you only ever add tracks to a playlist and (for combat) call the server API.

SoundConfig.Music.Playlists has exactly three entries, one per context:

ContextTriggerGap behavior
NormalDefault; nothing else activeGapped — random silence between tracks
CombatServer calls MusicService.SetContext(player, "Combat")Continuous — overlapping crossfade, no silence
LowFuelAutomatic, client-derived (see below)Continuous — overlapping crossfade, no silence

Priority when more than one condition is true: Combat > LowFuel > Normal.

Add asset IDs to Tracks on the relevant playlist — do not add new playlist names, the engine and director both assume exactly these three:

Playlists = {
    Normal = { Tracks = { "rbxassetid://AAA", "rbxassetid://BBB" }, Shuffle = true, FadeIn = 1.5, FadeOut = 1.5, GapMin = 60, GapMax = 300, Volume = 0.6 },
    Combat = { Tracks = { "rbxassetid://CCC" }, Shuffle = true, FadeIn = 1.0, FadeOut = 1.0, GapMin = 0, GapMax = 0, Volume = 0.7 },
    LowFuel = { Tracks = { "rbxassetid://DDD" }, Shuffle = true, FadeIn = 2.0, FadeOut = 2.0, GapMin = 0, GapMax = 0, Volume = 0.55 },
}
FieldMeaning
FadeInSeconds to fade the new track up from 0 at start
FadeOutSeconds to fade a track down to 0 at its end (or the crossfade overlap window when continuous)
GapMin / GapMaxRandom silence range (seconds) between tracks. GapMax <= 0 means continuous — the next track starts FadeOut seconds before the current one ends, producing an overlapping crossfade instead of silence
VolumeTarget playback volume for tracks in this playlist (pre-bus-volume)

Normal uses GapMin = 60, GapMax = 300 (a real silent gap between tracks). Combat and LowFuel use GapMin = 0, GapMax = 0 so they loop continuously with no silence.

Low fuel is automatic — never set it manually. Combat is the only context gameplay code drives, via the server-authoritative MusicService:

local MusicService = require(game.ServerStorage.SharedModules.MusicService)

MusicService.SetContext(player, "Combat") -- on event/outpost enter
MusicService.SetContext(player, "Normal") -- on event/outpost leave

SetContext fires the Packets.SetMusicContext packet to that one player; MusicDirector.client.luau receives it and resolves the active context by priority. Passing "Normal" clears the combat override — the client then falls back to LowFuel or Normal based on its own fuel state; it does not force Normal if fuel is still low.

Low fuel itself needs no code: MusicDirector watches Signals.OnTrainStateChanged and activates the LowFuel context whenever fuel / TrainConfig.MAX_FUEL drops below SoundConfig.Music.LowFuelPct (default 0.25).

Verify​

  1. Play-test in Studio (client context).
  2. Trigger the code path that calls PlaySFX / PlaySFXAt / etc.
  3. Confirm the sound plays. If silent: check the asset ID is correct, that Volume is not 0, and that the Group bus volume (SoundManager.GetVolume) is non-zero.
  4. For positional sounds with Replicate = true, check the Output window for server-relay errors.
  5. For BGM: confirm the track plays in Normal by default, that calling MusicService.SetContext(player, "Combat") from a server script switches it with a crossfade (no silence), and that draining fuel below SoundConfig.Music.LowFuelPct switches to LowFuel when not in combat.
