Tune Battle Pass

Goal: Launch the premium subscription, edit the tier track for a new month, fill in milestone item rewards, or add Scope = "Season" quests to feed the pass.

Steps​

  1. Set up the premium subscription. BattlePassConfig.SUBSCRIPTION_ID gates the entire Premium row. While it's "" (the pre-launch default), premium is never granted and the subscription APIs (GetUserSubscriptionStatusAsync, PromptSubscriptionPurchase) are skipped entirely — safe to ship pre-launch without spamming errors.

    • In the Creator Dashboard, go to Monetization → Subscriptions and create the subscription first (price, billing period, display copy).
    • Paste its id (format EXP-XXXXXXXXXX) into BattlePassConfig.SUBSCRIPTION_ID.
    • Keep the value identical in every place of the universe — BattlePassManager runs place-agnostic (lobby and gameplay both resolve premium status live), so a mismatch would make premium appear/disappear across a teleport.

  2. Edit the tier track. Open src/ReplicatedStorage/SharedModules/Configs/BattlePassConfig.luau. The base Tiers[level] table (level = 1..MAX_LEVEL) is generated in a loop; edit an individual tier after generation, or edit the loop itself for a track-wide change:

    -- Bump a single regular tier's Free reward after the fact:
    BattlePassConfig.Tiers[7].Free = { Type = "Coins", Amount = 300 }

    -- Or add a one-off Item reward on a non-milestone tier:
    BattlePassConfig.Tiers[20].Premium = { Type = "Item", ItemId = "SomeAccessoryId" }

    A Reward is { Type = "Coins", Amount: number } or { Type = "Item", ItemId: string }. An empty ItemId = "" is a placeholder milestone slot — see Gotchas. Milestone tiers (15, 30, 45, 60 in the shipped default) pay a chunkier Free coin bonus plus a Premium Item slot; regular tiers pay Coins on both rows.

  3. Add a SeasonOverrides entry for one month (optional). To swap in a different reward for one specific season only (e.g. a themed accessory for this month's milestone) without touching the evergreen base Tiers, add an entry to BattlePassConfig.SeasonOverrides, keyed by season index (year*12 + month-1, i.e. BattlePassState.seasonIndex), then by tier level:

    -- Override tier 30's Premium reward for a specific season (e.g. July 2026 = 2026*12+6 = 24318).
    BattlePassConfig.SeasonOverrides[24318] = {
        [30] = { Premium = { Type = "Item", ItemId = "JulyAccessory" } },
    }

    Any row present in SeasonOverrides[seasonIndex][level] shadows the base Tiers[level] entry for that row, for that one season only — an override that only sets Premium leaves Free on the base table for that tier. BattlePassState.tierReward resolves the override before falling back to Tiers, and both the server (grant) and client (display) call the same function, so they can never disagree.

  4. Fill milestone ItemIds. Every milestone tier ships with an empty Premium Item slot (ItemId = "") as a placeholder. Before launch, replace each with a real asset id:

    BattlePassConfig.Tiers[15].Premium = { Type = "Item", ItemId = "AccessoryAssetId15" }

    See Gotchas — an unfilled slot silently grants nothing and still marks itself claimed.

  5. Tune ExpPerLevel against quest BPExp. BattlePassConfig.ExpPerLevel (a flat number, or a { [level]: number } table for a curve) sets the cumulative EXP cost per tier. The only EXP source is Reward.BPExp on quests (fed via Signals.OnQuestRewardGranted — see Battle Pass — EXP earning), so a full clear's reachability is entirely a function of how much BPExp the quest pool pays out over a month:

    • Flat default: ExpPerLevel = 1000, MAX_LEVEL = 60 → 60,000 total EXP for a full clear.
    • The shipped Scope = "Season" quests alone pay 3000 BPExp each (SeasonJunk/SeasonKills/SeasonDistance = 9,000 for the month) — Daily/Weekly BPExp amounts (e.g. 200–1200 per quest, repeating every rotation) make up the rest.
    • To make a full clear reachable in a month: estimate the average daily/weekly BPExp a reasonably active player earns per day, multiply by ~30, add the Season total, and set ExpPerLevel (or the per-level table) so the running total lands near or under that number. Raise per-quest BPExp values instead of lowering ExpPerLevel if you want the quests to feel more rewarding rather than the track to feel shorter.
    • A { [level]: number } table lets early tiers cost less (fast early momentum) and late tiers cost more (a grind at the top) — BattlePassState.levelFromExp/progress handle either shape transparently.

  6. Add Scope = "Season" quests (optional). Season quests are the dedicated battle pass EXP feed — the whole set is active for the entire month (no rotation/shuffle, unlike Daily/Weekly). Add an entry to QuestConfig.Quests in src/ReplicatedStorage/SharedModules/Configs/QuestConfig.luau:

    SeasonCrafting = { Scope = "Season", Category = "Personal", Metric = QuestConfig.Metrics.JunkCollected,
        Target = 2000, DisplayName = "Season Scrapper", Description = "Collect 2,000 junk this season",
        Reward = { Coins = 0, Exp = 0, BPExp = 3000 } },

    Metric must be one of QuestConfig.Metrics, same as any other quest — see Tune Quests — Add a quest for wiring a brand-new metric. The shipped Season quests pay Coins = 0, Exp = 0 and only BPExp — Season quests exist purely to move the battle pass track, not the coin/XP economy — but this isn't enforced; a Season quest can also pay coins/exp if you want it to. No Counts entry applies to Scope = "Season" — every Season quest in the pool is always active, so add exactly as many as you want visible this month.

Verify​

  1. Join in Studio with API Services enabled.
  2. Confirm BattlePassClient.GetProgress() returns level 0, Exp 0 on a fresh profile, and BattlePassClient.GetTiers() reflects your edited Tiers/SeasonOverrides.
  3. Complete a quest carrying BPExp and confirm BattlePassClient.Changed fires with the level/progress advancing accordingly.
  4. Call BattlePassClient.Claim(); confirm BattlePassClient.GetClaimableSummary() returns (0, 0, 0) immediately after (idempotent — a second claim finds nothing outstanding).
  5. If testing Premium: set a real SUBSCRIPTION_ID, subscribe as a test account, and confirm BattlePassClient.IsPremium() flips to true and a retroactive sweep grants every reached Premium tier for the season.
  6. If you changed SeasonOverrides, confirm the override actually landed on the current season index (BattlePassState.seasonIndex(os.time())) — an override keyed to the wrong season silently never applies.

Gotchas​

Changing STORE_NAME orphans saved data

BattlePassConfig.STORE_NAME ("PlayerBattlePass") must stay identical in the lobby and gameplay places — it's the shared ProfileStore key that lets session-locking hand off cleanly across the teleport boundary. Changing it points every player at a brand-new, empty profile: all season progress and claimed flags become unreachable. Only do this intentionally, and change it in both places together.

An empty ItemId slot grants nothing — and is still marked claimed

A milestone Item reward left at ItemId = "" is a placeholder. Granting it fires no Signals.OnBattlePassItemGranted (there's nothing to hand off to an inventory system) but the claimed flag is still set, so the player never sees that tier offered again — even after you later fill in a real ItemId. Fill every milestone slot before launch, not after.
