Tune Perk Unlocks

Goal: Choose which perks are free starters, set a perk's level gate and one-time coin + point cost, and reason about how those choices interact with respec refunds and the schema migration.

Steps​

  1. Choose a starter perk. A perk with UnlockCost, UnlockLevel, and UnlockPointCost all 0 is a free "starter" — PerkManager.seedStarters auto-unlocks it for every player on load and after every respec of its pool. Today the two starters are IronConstitution (Personal) and ScavengersEye (Party) — one per pool, so a brand-new player always has a perk to upgrade in each pool. Starters still pay upgrade coins.

    IronConstitution = { Category = "Personal", DisplayName = "Iron Constitution", Order = 1,
        Description = "+{1} max health", MaxLevel = 10,
        Buffs = { { Key = "HPBonus", PerLevel = 0.04 } },
        UnlockCost = 0, UnlockLevel = 0, UnlockPointCost = 0, UpgradeCoinStep = 100 }, -- starter

    To make a different perk a starter, set its UnlockCost, UnlockLevel, and UnlockPointCost to 0. Make sure at least one perk per pool stays a 0/0/0 starter. A starter cannot be Hidden (a boot self-check asserts this).

  2. Set a perk's level gate and costs. Open src/ReplicatedStorage/SharedModules/Configs/PerkConfig.luau and edit the entry:

    MarathonLungs = { Category = "Personal", DisplayName = "Marathon Lungs", Order = 2,
        Description = "+{1} max stamina, −{2} sprint drain", MaxLevel = 6,
        Buffs = { { Key = "MaxStaminaBonus", PerLevel = 0.05 }, { Key = "SprintDrainReduction", PerLevel = 0.03 } },
        UnlockCost = 250, UnlockLevel = 2, UnlockPointCost = 1, UpgradeCoinStep = 100 },
    • UnlockLevel — minimum player XP level (LEVEL_REQUIRED below this).
    • UnlockCost — coins deducted once via CoinManager.DeductCoins at unlock, and recorded in the CoinsSpent ledger.
    • UnlockPointCost — points from the perk's own pool, spent once at unlock (NO_POINTS when the pool can't pay).
    • UpgradeCoinStep — each later level n costs UpgradeCoinStep × n coins plus 1 point.

    All checks are enforced server-side by PerkState.canUnlock (order: unknown → hidden → already unlocked → level → points → coins).

  3. Unlock is one-time; upgrades are paid per level. UnlockCost buys access. Each level after that costs 1 point plus rising coins (see Perks — Point and coin economy). UnlockPointCost competes with upgrades for the same pool, so a high point cost delays a player's first levels in other perks.

  4. Respec refunds come from the ledger. PerkManager.Respec (a pool) and RespecPerk (one perk) refund exactly CoinsSpent[perkId] — every coin the player paid on that perk — via CoinManager.RefundCoins (not scaled by Pocket Change). A coin-price re-tune therefore never changes what an existing player gets back. A starter refunds its upgrade coins, loses its levels, and stays unlocked. Unlock points always come back in full, because points are derived.

Verify​

  1. Join in Studio with API Services enabled.
  2. Open the Perk menu (P). Confirm both starters (Iron Constitution, Scavenger's Eye) show unlocked, locked perks show their coin + point price, and the six hidden perks never appear.
  3. Unlock Marathon Lungs (250 coins + 1 point), then upgrade it to level 1 (100 coins) and level 2 (200 coins). The button reads UPGRADE · 300 before level 3 and NEED COINS when short.
  4. Try to unlock a perk while under-leveled, out of points, or under-funded and confirm the request is rejected with no coin deduction.
  5. Reset the perk and confirm: the level clears, the perk re-locks, exactly 550 coins (250 + 100 + 200) come back, and the points return. Changing UpgradeCoinStep in Studio before the reset does not change the 550.

Gotchas​

Changing UnlockPointCost re-prices perks players already own

Points are derived: spent reads the current UnlockPointCost of every unlocked perk. Raising a perk's point cost from 1 to 3 takes 2 more points from every player who already unlocked it — their available points can drop to 0. Lowering it gives points back. Coins do not have this problem (the ledger records what was paid); points do. Tune point costs before launch, or pair a raise with a Respec announcement.

Changing STORE_NAME wipes all saved perk + unlock data

PerkConfig.STORE_NAME ("PlayerPerks") is the ProfileStore key for PerkLevels, Unlocked and CoinsSpent. Changing it points every player at a brand-new, empty profile — equivalent to wiping all perk progress, unlocks and the refund ledger. Only do this intentionally.

Schema migrations run once per profile

migrateAndSeed has two version-guarded steps: schema 1 (one-time wipe) and schema 2 (Perk Rework: bank the v1 unlock coins in PendingLegacyRefund, wipe, pay the refund once the coin profile loads). PerkManager only bumps PerkSchemaVersion forward; editing it back down does not replay cleanly. A future perk-id change that strands old ids needs a new guarded step (schema 3) with its own frozen refund table.
