Add / Show a Toast Notification

Goal: Surface a toast message to the local player — success confirmations, warnings, errors, or informational messages.

Rule: do not require NotificationManager directly from feature code. Fire a signal instead; NotificationManager is the sole consumer.

Steps​

  1. Choose a notification type. The canonical types are defined in src/ReplicatedStorage/SharedModules/Configs/NotificationConfig.luau:

    "success" | "info" | "warn" | "alert" | "default"

    Each type has a pre-configured background color (NotificationConfig.Colors), icon image (NotificationConfig.ImageIds), and stinger SFX (NotificationConfig.SfxNames). If an existing type fits, skip to step 3.

  2. (Optional) Add a new type. If none of the five built-in types fit, extend NotificationConfig (file: src/ReplicatedStorage/SharedModules/Configs/NotificationConfig.luau) by adding the new lowercase key to every relevant table:

    -- 1. Register the type name
    NotificationConfig.Types = { "success", "info", "warn", "alert", "default", "mytype" }

    -- 2. Background color
    NotificationConfig.Colors.mytype = Color3.fromRGB(80, 40, 120)

    -- 3. Background transparency (0 = opaque, 1 = invisible)
    NotificationConfig.BaseTransparency.mytype = 0.5

    -- 4. Icon asset ID
    NotificationConfig.ImageIds.mytype = "rbxassetid://XXXXXXXXXXXXXXXXX"

    -- 5. SFX stinger — must match a key in SoundConfig.Sfx
    NotificationConfig.SfxNames.mytype = "NotifDefault"

    If you add a custom stinger, first register it in SoundConfig.Sfx (see Add a Sound).

  3. Fire the signal from any client controller.

    local Signals = require(ReplicatedStorage.SharedModules.Signals)

    -- Basic timed toast (disappears after the default duration):
    Signals.RequestNotification:Fire("success", "Item placed!")

    -- Custom duration (seconds):
    Signals.RequestNotification:Fire("warn", "Low fuel!", 5)

    -- Executed-function toast (stays until the function returns, then closes):
    Signals.RequestNotification:Fire("info", "Loading...", nil, function()
        -- async work here; toast closes when this returns
        task.wait(2)
    end)

    -- Dismiss all active toasts:
    Signals.RequestClearNotifications:Fire()

    Signal signature (from src/ReplicatedStorage/SharedModules/Signals/init.luau):

    RequestNotification : Signal<string, string, number?, (() -> ())?>
      arg1  notificationType  (lowercase, must be in NotificationConfig.Types)
      arg2  message           (display text, wraps automatically)
      arg3  duration?         (seconds; nil = config default per device)
      arg4  executedFunction? (if provided, toast stays until function returns)

    The stack allows up to NotificationConfig.MaxConcurrent (default 5) concurrent toasts. When the cap is exceeded the oldest non-executed toast is automatically closed.

Verify​

  1. Play-test in Studio (client context).
  2. Trigger the code path that fires Signals.RequestNotification.
  3. Confirm the toast appears at the top of the screen, plays its stinger, and auto-dismisses after the expected duration.
  4. If the toast does not appear: confirm the type string is lowercase and present in NotificationConfig.Types; confirm NotificationController.client.luau has run NotificationManager.Init().
