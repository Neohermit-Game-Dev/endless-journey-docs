Quests (Daily & Weekly)

A per-player quest board, backed by ProfileStore and layered on top of the coin/XP economy. Each player has their own offered quests, slots and active quests for four buckets: Personal/Party × Daily/Weekly. Players accept, cancel, refresh and claim quests on the Lobby Quest Terminal; the Game Instance tracks progress and shows a hidden tracker. Claimed quests fill a 5-checkpoint mileage track per period, and the last checkpoint gives perk boxes. A separate, non-board Season scope feeds the Battle Pass. Progress is server-authoritative. The system is split shared/server/client like Perks.

Spec: docs/_superpowers/specs/2026-10-15-quest-board-design.md (repo only).

How it works​

Board​

Each period (Daily, Weekly) × category (Personal, Party) has its own box in profile.Data.Board[scope][category]:

FieldMeaning
OfferOffered quests { Id, Used }. OFFER_SIZE (5) at each reset. Used = refreshes spent on that offered slot
ActiveAccepted quests { Id, P, Claimed, Used, Mult }. P = progress, Mult = Contract Bonus locked at completion
TempTemporary slots bought this period

Each scope also stores Period, Pts (mileage points, 0–5) and Got (claimed checkpoints). The profile root holds RefreshCredits, Boxes and Purchases (the last PURCHASE_HISTORY processed receipt ids).

  • Eligible quests. QuestBoardState.eligible(scope, category) lists the pool quests whose Metric is a key of QuestConfig.Metrics. Quests with a metric that has no source yet are never offered. A Personal quest also needs its metric in QuestConfig.PersonalMetrics (reported with an actor through ReportProgress); ownerless metrics such as BiomeJumps advance Party quests only, so a Personal quest on them stays off the board. A small pool gives fewer than 5 offers.
  • Slots. BASE_SLOTS (3) + owned slot passes of that period + Temp. Passes + temporary slots are capped at MAX_EXTRA (3). A claimed quest keeps its slot until the reset. When slots shrink below the active count, the actives stay and accept returns SLOTS_FULL.
  • Accept moves an offered quest into a free slot. Cancel is allowed only while P == 0 and the quest is not claimed; the quest returns to the offered list with its Used count.
  • Refresh replaces one offered quest with another eligible quest that is not offered or active. Each offered slot has FREE_REFRESHES (1) free refresh; the replacement inherits the count. After that, a refresh spends a paid RefreshCredit; with none, the server shows the refresh product prompt (NEEDS_PURCHASE). No other eligible quest → NO_REPLACEMENT, and the free refresh is not spent.
  • Claim (Lobby) pays the period × category reward from QuestBoardConfig.Rewards, multiplied by the locked Mult, and adds 1 mileage point. Daily/Weekly quests pay coins + EXP only, no battle pass EXP.
  • Mileage. Checkpoint k needs k points. Each checkpoint pays coins + EXP once; checkpoint 5 also adds perk boxes (Daily 1, Weekly 5).
  • Perk box. OpenBox picks uniformly from every non-hidden Consumable/Expiring perk in ShopPerkConfig (except the box-only super rares, so the odds list shows each perk once) and grants it through PerkInventoryManager.Grant (no level gate): a consumable gives ConsumableCopies; an expiring perk banks one of its own lengths (Variants[i].Seconds), picked by PerkBox.LengthWeights — 1 length 100%, 2 lengths 70/30, 3 lengths 60/30/10, shortest first (QuestBoardState.rollLength). A running clock gets the seconds added, never reset. A SuperRareChance (0.1%) roll picks one of the 16 BoxOnly perks (QuestBoardState.superRareIds). The box is spent only when the grant succeeds. The GUI shows the odds from QuestBoardState.boxOdds (the same pool and config as the roll): a tier line on the box screen (QuestGuiRules.oddsLine) and every perk in the ODDS panel, 2 decimals. Each expiring name carries its length odds, e.g. XP Booster (1 h 60% · 12 h 30% · 1 d 10%) or Scrap Pay (1 d), so every chance a player can roll shows before they open or pay (Roblox paid random items rule). The opening result reads 12 H OF USE.

Reset​

On join, QuestManager registers the player only after CoinManager and XPManager report their profiles loaded, because both drop grants before that. Until then every quest request returns NO_PROFILE.

ensureCurrent runs on join, before every request and progress report, and on the ROLLOVER_CHECK_SECONDS tick. When a scope's Period differs from the current index, QuestBoardState.sweep pays the old period's finished-but-unclaimed quests and reached-but-unclaimed checkpoints exactly once (boxes included). Then the scope is rebuilt with fresh offers, empty slots, Pts = 0 and Temp = 0.

Purchases (Lobby only)​

  • Temporary slot: 4 Developer Products (period × category). ReqBuyQuestSlot → the server shows the prompt; the receipt adds Temp += 1.
  • Perk boxes: 2 Developer Products, Products.PerkBox.Single (3718951532, "Perk Mystery Box 1x", R$49) and .Bundle (3718951579, "Perk Mystery Box x5", R$199, PerkBoxBundleSize = 5). ReqBuyPerkBox(bundle) → the server shows the prompt; the receipt adds the boxes to Boxes. A bought box is the same box as a free one: same pool, same 0.1% super rare roll, same length odds. Lobby only.
  • Paid random item policy: when PolicyService:GetPolicyInfoForPlayerAsync says ArePaidRandomItemsRestricted (or the call fails), the client hides GET BOXES (the Open button says NO BOXES at 0) and BuyBox returns NOT_FOR_SALE. Free mileage boxes still open.
  • Refresh: 1 Developer Product. The receipt adds a RefreshCredit and spends it on the pending refresh target if it is still valid.
  • Slot passes: 6 game passes (Daily I–III, Weekly I–III). Each owned pass gives +1 Personal and +1 Party slot of that period. Ownership is read with UserOwnsGamePassAsync at join and updated on PromptGamePassPurchaseFinished; it is not saved. Passes can be bought in any order (also from the website), so QuestStateSync sends the first configured pass the player does not own (QuestBoardState.nextPass) and the PERMANENT button offers that one.
  • ReceiptRouter owns the place's single ProcessReceipt (Roblox allows one per server). It runs in the Lobby only; a receipt that reaches a Game Instance server has no handler there and returns NotProcessedYet, so Roblox retries it later. Unknown products, absent players and handler errors also return NotProcessedYet.
  • QuestManager.settle(player, info, apply) makes each receipt grant once: (1) no profile → NotProcessedYet; (2) PurchaseId already in LastSavedData.Purchases → PurchaseGranted; (3) not in Data.Purchases → run apply and record the id (QuestBoardState.recordPurchase, last PURCHASE_HISTORY ids); (4) profile:Save() and wait up to 20 s for LastSavedData to hold the id → PurchaseGranted, else NotProcessedYet.
  • Product and pass ids are 0 until they exist; 0 = not on sale (the server refuses with NOT_FOR_SALE, the GUI hides the button).
  • Teleport hand-off. QuestManager registers PersistenceRegistry.RegisterHandoff: the Lobby ends the quest session without a kick right before a party teleport, so the Game Instance opens it at once, and reopens it if the teleport fails.

Period math​

Period indices come from os.time() (UTC), never client input:

FunctionFormula
QuestState.dayIndex(now)floor((now - DailyResetOffset) / 86400)
QuestState.weekIndex(now)floor((now - WeeklyResetOffset) / 604800)
QuestState.dailyExpiresAt(now)Unix timestamp the current daily period ends
QuestState.weeklyExpiresAt(now)Unix timestamp the current weekly period ends

Daily rolls at 00:00 local (QuestConfig.DailyResetOffset); Weekly rolls Monday 00:00 local (QuestConfig.WeeklyResetOffset, a 4-day base offset — the Unix epoch was a Thursday, so shifting 4 days aligns week starts to Mondays). Both offsets are derived from QuestConfig.ResetTimezoneOffset — a fixed seconds-from-UTC offset defining the timezone "midnight" is measured in (pre-launch default US Eastern, -5 * 3600). It's fixed, so it does not track daylight saving; set it to 0 for pure UTC resets (DailyResetOffset = -ResetTimezoneOffset; WeeklyResetOffset = 345600 - ResetTimezoneOffset). The expiry functions are sent to the client so it can drive a live countdown with no client-side period math.

Season quests​

Scope = "Season" quests stay in QuestConfig.Quests and are not on the board. QuestState.seasonQuests() returns the whole curated set (Personal ids then Party ids, each sorted), active for the whole month. The period index is BattlePassState.seasonIndex(now), so Season quests reset with the battle pass. The Season rollover runs only where options.rollSeason is true (the Game Instance, where BattlePassManager runs).

A Season quest pays on completion: advancePlayer sets SeasonClaimed before the grant, pays Reward.Coins/Reward.Exp and fires Signals.OnQuestRewardGranted(player, quest.Reward), so BattlePassManager adds Reward.BPExp in the same season. The shipped pool pays Coins = 0, Exp = 0 and BPExp = 3000. The rollover still sweeps any finished, unpaid Season quest.

Attribution​

Two entry points on QuestManager mirror XPManager.AddXP/AddPartyXP:

function QuestManager.ReportProgress(actor: Player, metricKey: string, amount: number)
function QuestManager.ReportPartyProgress(metricKey: string, amount: number)
FunctionHas an actorAdvances
ReportProgressYes (e.g. junk collection)Bumps the actor's own Lifetime metric, advances the actor's Personal quests, and fans the same amount out to every living online player's Party quests for that metric (down players get nothing, see Paid Revive)
ReportPartyProgressNo (e.g. enemy died, train distance)Advances every living online player's Party quests and bumps each one's Lifetime metric total (down players get nothing)

Either path calls ensureCurrent first (rolls any elapsed period before applying progress) and only replicates (QuestStateSync) to players whose progress actually changed.

Contract Bonus​

The Contract Bonus perk (QuestRewardBonus, id QuestTracker) is locked when a quest completes during a run. In the Game Instance, options.bonusFor(player) reads PerkBuffRead.Personal(player, "QuestRewardBonus"); QuestBoardState.advance stores 1 + bonus in Active.Mult on the below-target → at-target step. The Lobby claim pays floor(reward × Mult). A quest completed without the perk keeps Mult = 1.

Sources​

QuestSourcesLoader (gameplay-only — safe to run in the lobby place, where these events simply never fire) wires the QuestConfig.Metrics to their gameplay triggers:

MetricCategoryTrigger
EnemyKillsPartyHumanoid.Died on any CollectionService-tagged ENEMY_TAG ("EnemyNPC") model — one Janitor per tracked enemy
DistanceTravelledPartyA recurring task.wait(DISTANCE_TICK_SECONDS) loop credits DISTANCE_PER_TICK while Signals.SetTrainState reports the train running
JunkCollectedPersonalSignals.OnJunkCollected — fired by JunkService once per successful finalized junk grab (collector, junkId)

A pool quest that uses one of these Metric keys is offered with no code change. A pool quest with any other metric stays off the board until its key is added to QuestConfig.Metrics and wired here. Wiring a brand-new metric needs one new source hookup in QuestSourcesLoader (see Tune Quests).

Perk seam​

profile.Data.Lifetime is a { [key]: number } table that is never reset by rollover — distinct from the per-period board. advancePlayer bumps Lifetime["QuestsCompleted"] by 1 on every below-target → at-target transition, and both report functions bump Lifetime["metric:"..metricKey] by the raw reported amount.

function QuestManager.GetLifetimeStat(player: Player, key: string): number

This is a deliberate seam for a future PerkConfig unlock criterion (e.g. "unlock this perk after QuestsCompleted >= 25") — not wired to any perk this cycle.

Client​

QuestClient is a GUI-agnostic read-model, the same shape as PerkClient. It caches the QuestStateSync snapshot (board, passes, refresh credits, boxes, expiry timestamps, Season progress, lifetime stats), exposes getters for the GUIs and yielding request wrappers (accept, cancel, refresh, claim, claim mileage, buy slot, open box) that return the server's result code. A Changed signal fires on every snapshot. QuestGuiRules holds the shared display rules (number and clock text, slot kinds, cancel eligibility, tracker rows). The Lobby quest board (QuestBoardGui) and the Game Instance tracker (QuestTrackerGui) consume both.

QuestClientReturns
Init(), IsReady(), ChangedBootstrap, first snapshot received, change signal
GetScope(scope)Live ScopeData (read-only by convention)
GetPasses(scope), GetExpiresAt(scope), GetRefreshCredits(), GetBoxes(), GetLifetimeStat(key), GetSeason()Snapshot values
Accept / Cancel / Refresh(scope, category, questId)(ok, code) (yields)
Claim(scope, category, questId)(ok, code, coins, exp) (yields)
ClaimMileage(scope, index), BuySlot(scope, category)(ok, code) (yields)
OpenBox()(ok, code, perkId, superRare) (yields)

QuestGuiRules: fmt (thousands separators), clock (HH:MM:SS, ND HH:MM:SS past a day), slotKind(index, base, passes) (Base/Pass/Temp), canCancel, progressText, trackerRows (unclaimed actives, unfinished first), readyToClaim (a finished quest or a reached checkpoint waits in the Lobby).

Lobby quest board GUI​

StarterGui.QuestBoardGui (Lobby place, built once through the Studio MCP; plan docs/_superpowers/plans/2026-10-15-quest-board-lobby-gui.md Task 2) is driven by places/Lobby/StarterPlayer/StarterPlayerScripts/QuestBoardGuiController/init.client.luau (child modules Fx, BoxOpening, OddsPanel, ClaimFx; motion plan docs/_superpowers/plans/2026-10-15-quest-board-motion.md). The visual spec is the prototype at roblox-gui-prototypes/2026-10-15-quest-board-prototype/index.html.

  • Open. A part tagged QuestKiosk with a ProximityPrompt (the Lobby's QuestTerminal), or the right-aligned TopbarPlus "Quests" icon next to Perks / Loadout / Shop. The prompt hides while the board is open; the × button or the icon closes it.
  • Layout. Board (1560×900, one UIScale: min(1, W/1640, H/960)) holds Head (title, perk box button, reset clock, close), Mileage (the DAILY/WEEKLY rail beside 5 checkpoint cells) and Body (offered column with the PERSONAL/PARTY filter, active column). Row templates live in Templates and are cloned on every QuestClient.Changed. Overlay (a sibling of Board with the same size, position and scale, kept equal by fit()) holds BoxModal and the Fx layer for float labels and arcs, so neither is placed by the board's UIListLayout. Pieces that pop or rotate sit centred in fixed-size holders (CountHolder, CheckHolder, checkpoint Body, Claimed.Inner).
  • Rows. An offered row shows the reward and a refresh button: FREE while the slot has a free refresh, PAID while refresh credits remain, else the Robux price (hidden when the refresh product id is 0). ACCEPT reads SLOTS FULL when no slot is free. An active row shows progress, a slot chip (PASS, or TODAY / THIS WEEK for a temporary slot), CANCEL only at 0 progress, then CLAIM and CLAIMED.
  • Extra slot row. EXTRA <CATEGORY> QUEST SLOT with pips for the extras left and two pay buttons: TODAY ONLY / THIS WEEK ONLY (the temporary product, with a live "Gone in" countdown) and PERMANENT (the next unowned slot pass, prompted on the client with PromptGamePassPurchase). A button with id 0 hides; the row hides when both do.
  • Mileage. A reached, unclaimed checkpoint turns green with CLAIM; a claimed one shows a check. The period rail shows n/5 and a dot when something waits to be claimed (QuestGuiRules.readyToClaim).
  • Claim feedback (ClaimFx). After a successful claim the controller waits for the snapshot that shows it (runPending, 2 s cap; only on the same period and category): the row flashes, CLAIMED pops, the reward floats up from Overlay.Fx, and a mileage point arcs to the segment it fills (on phone outside the MILEAGE pane, to the visible n/5 count; if the player switches period during the arc, the landing does nothing). A claimed checkpoint pops, its tick spins in, and its perk boxes arc to PERK BOX. Ready checkpoints pulse their stroke while the board is open.
  • Perk box. PERK BOX ×n opens Overlay.BoxModal. OPEN (or a tap on the box) runs BoxOpening.play: the request goes out at once while the box lifts and takes 3 hits; each hit waits for the player (tap, click, Space or ButtonA; no auto hit). The glow colour hints the tier (an Expiring perk sometimes shows teal first; super rare goes amber, then a hue loop and an overload beat). The 3rd hit waits for the answer (10 s cap). Then: flash, the box splits into its 3 faces, rays and confetti, the perk card flips in, the tier tag lands and the name types in (MaxVisibleGraphemes). SKIP jumps to the end; closing stops it. A failure goes back to the closed box with a toast. An ok answer that the run did not reveal (the board closed first, or it came after the 10 s cap) still names the perk: a toast while the board is open, else a Roblox notification. Reduce Motion keeps only fades and colour. Odds disclosure: the box screen always shows the tier line (QuestGuiRules.oddsLine); ODDS opens OddsPanel over the card with every perk and its chance, from QuestBoardState.boxOdds (so a new perk or a new chance updates it with no text edit). GET BOXES (in the card's TitleRow, and the Open button itself when no box is left) opens BoxModal.ShopPanel over the card (same frame as OddsPanel; opening one closes the other): a 1-box and a bundle offer (the bundle shows a 3-box pyramid of Box icons and a SAVE n% tag from QuestGuiRules.bundleSave, rounded down, shown only when both prices are known), each with its per-box price and a price button (ReqBuyPerkBox), then WHAT'S INSIDE: super rare / expiring / consumable totals from the same boxOdds, and ALL ODDS (opens OddsPanel). Prices come from GetProductInfoAsync; … until known. A finished purchase prompt (PromptProductPurchaseFinished, UI only) closes the panel; the receipt adds the boxes.
  • Requests. One request at a time (busy); the result code becomes a toast. The board repaints only from the next snapshot.
  • Phone (touch, width < 1000): scale 0.62, one pane at a time (OFFERED / ACTIVE / MILEAGE switch), DAILY/WEEKLY in the header. Resize or rotation keeps the selected period and category.
  • Icons. Every icon ImageLabel has an Icon attribute naming a QuestBoardConfig.Icons key; the controller sets Image from it ("" until uploaded).

Game Instance tracker​

StarterGui.QuestTrackerGui (Game Instance place, built once through the Studio MCP; plan docs/_superpowers/plans/2026-10-15-quest-tracker-gui.md Task 2) is driven by src/StarterPlayer/StarterPlayerScripts/QuestTrackerController.client.luau. It only shows progress; claiming happens in the Lobby.

  • Hidden by default. A right-aligned TopbarPlus "Quests" icon (caption "Quests · Tab / hold J") toggles the panel. Tab also toggles it: the controller disables the Roblox player list (CoreGuiType.PlayerList) and binds Tab with TopbarPlus bindToggleKey (ignored while typing in chat). Holding J (keyboard) or ButtonY (gamepad) shows it while held (ContextActionService, so typing in chat does not open it). Releasing J keeps it open while the icon is selected.
  • Sections. Collapsible DAILY and WEEKLY sections (only the ones with active quests) with a done count and the reset clock. Rows come from QuestGuiRules.trackerRows: unclaimed actives, unfinished first, each with its category glyph, task and progress.
  • Notices. A quest that completes while the panel is hidden adds a notice to the icon and a Roblox notification; opening the panel clears them. Quests already done at join do not notify.
  • Fit. Root is 440 px wide at the top right with one UIScale = max(min(W/1920, H/1022), 0.6). The list stops at 78% of the screen height (58% on touch, above the mobile buttons); extra rows scroll. While PartyVoteGui is enabled, the panel moves below its banner.

Gotchas​

Changing STORE_NAME orphans saved quest data

QuestConfig.STORE_NAME ("PlayerQuests") is the ProfileStore key for progress, claimed flags, and the never-reset Lifetime table. Changing it points every player at a brand-new, empty profile — all prior quest progress and lifetime stats are orphaned (not deleted, just unreachable). It must stay identical in the lobby and gameplay places for the cross-place session handoff to share the same record.

Personal progress from ReportProgress also advances Party quests

ReportProgress(actor, metricKey, amount) is not Personal-only — it fans the same amount out to every online player's Party quests for that metric, then additionally advances the actor's Personal quests. A Party pool quest that uses a Personal-sourced metric (JunkCollected) is live with no new source wiring.

Only live metrics are offered

QuestPool holds all 100 quests, but QuestBoardState.eligible offers only quests whose Metric is a key of QuestConfig.Metrics. A bucket with few live quests shows fewer offers, and refresh returns NO_REPLACEMENT when nothing else is eligible.
