GrabHook

The GrabHook is a player tool that fires a tethered hook to collect floating junk. The client owns all raycasting and rope visuals; the server validates the claim and awards the item.

At a glance​

LayerFileRole
Clientsrc/StarterPack/Grabhook/GrabHook.client.luauTool activation, spherecast aim, force-field highlight, grapple animation orchestration, sound scheduling
Serversrc/ServerScriptService/JunkService.server.luauValidates claim/finalize requests (see Junk)
Sharedsrc/ReplicatedStorage/SharedModules/GrabHookVisuals.luauBeam creation and projectile / observer animation loops
Configsrc/ReplicatedStorage/SharedModules/Configs/GrabHookConfig.luauAll physics, visuals, and sound timing constants

Packets: none directly — claims/finalizes flow through Packets.ReqJunkClaim / ReqJunkClaimBatch / ReqJunkFinalize, fired by JunkController on behalf of the GrabHook (see Junk and Networking Map) Signals: TryClaimJunk, TryClaimJunkBatch, TryFinalizeJunk, RequestShootingCamera, RequestReticleScale — see Signals Map

How it works​

Aiming​

GrabHook.client.luau runs entirely as a LocalScript inside the Grabhook Tool under StarterPack. On equip, mouse.TargetFilter is set to the PlacedObjects folder so placed items don't occlude aim, and Signals.RequestShootingCamera(true) puts CameraController into aim mode. Every RenderStepped frame while equipped, GetAimedJunk(rootPart) performs a Spherecast from the handle's Attachment.WorldPosition toward mouse.Hit.Position — radius Physics.HitboxRadius (2 studs), max distance Physics.MaxDistance (150 studs), gated to within 90° of the character's forward vector. The junk ID is resolved by invoking GetJunkIdFromPart via BindableCore (registered by JunkController).

A force-field highlight (ReplicatedStorage/ForceField template cloned to workspace) tracks the currently aimed junk part on every RenderStepped tick; if aim is found it calls ShowForceField(junkPart, junkId), and a 0.08-second grace window prevents flickering (HideForceField) when the spherecast briefly misses.

Firing​

On tool.Activated, after a cooldown check (Physics.Cooldown = 1.1 s), the client fires Signals.TryClaimJunk(id, hitPoint) (handled by JunkController), increments fireToken to version all pending callbacks, then calls FireGrappleAndAttach(targetPart, hitPoint, junkId, token):

  1. Creates an Attachment on the junk part ("HookAttachment").
  2. Calls GrabHookVisuals.CreateBeam(handleAtt, junkAtt, targetPart).
  3. Calls GrabHookVisuals.AnimateProjectile, a three-phase animation: Flight (junkAtt.WorldPosition lerps toward the junk at Physics.Speed = 200 studs/s, beam curves oscillate with Amplitude=12, Frequency=40, Decay=4), Latch (a single transition frame, curves flattened to 0), Retract (targetPart.Position lerps back to the handle at Physics.RetractSpeed = 50 studs/s).
  4. On retract complete, fires Signals.TryFinalizeJunk(id) (handled by JunkController).

SoundManager.PlaySFXAt("GrabHookFire") plays a shot replicated to all clients; SoundManager.PlayLooped("GrabHookLoop") schedules a fade-in/out loop. When retraction completes, FireGrappleAndAttach also plays a positional pickup sound at the character's CollisionPart/UpperTorso/HumanoidRootPart anchor resolved by CharacterAnchor. The loop sound is scheduled with a LoopStartDelay (0.15 s) fade-in and a timed fade-out matched to the total hook animation duration.

Unequipping​

On unequip, fireToken is incremented (invalidating all pending task.delay callbacks), loopHandle:Destroy() runs, and Signals.RequestShootingCamera(false) returns CameraController to its normal mode.

Net Cast perk (multi-catch)​

The NetCast perk (see Perks) raises hook capacity beyond 1. netCapacity() reads PerkBuffs/<UserId>.NetCapacityBonus client-side: capacity = 1 + NetCapacityBonus. At capacity 1 (no perk levels) the tool is byte-for-byte identical to the base single-hook path (GetAimedJunk + Signals.TryClaimJunk). At capacity ≥ 2:

  • Aim — GetAimedJunks(rootPart, capacity) replaces the single spherecast with workspace:GetPartBoundsInBox at GrabHookConfig.Physics.NetHitboxRadius (4 studs) along the aim line, returning up to capacity NetTargets ({ id, part, hitPos }) sorted by distance.
  • Fire — one tool.Activated still means one cooldown, one GrabHookFire sound, and one loop sound, but drives a beam per target. Claim ids are batched through Signals.TryClaimJunkBatch:Fire(ids) (consumed by JunkController, which invokes Packets.ReqJunkClaimBatch) instead of the per-junk TryClaimJunk. Finalize remains per-junk (Signals.TryFinalizeJunk / ReqJunkFinalize) once each beam's retraction completes.
  • Server clamp — JunkService.ClaimJunkBatchForPlayer never trusts the client's capacity or positions: it re-reads NetCapacityBonus from the published buff folder, clamps to GrabHookConfig.Physics.NetMaxTargets (5, hard cap), and reconstructs each junk's position from the junk odometer (SpawnPos + MOVE_DIRECTION * (junkOdometer - SpawnOdometer)) before reserving it.
  • Reticle — on equip, if netCapacity() >= 2, fires Signals.RequestReticleScale(CameraConfig.NetReticleScale) (1.6×) so CameraController enlarges the aim reticle; otherwise fires RequestReticleScale(1). Unequip always fires RequestReticleScale(1) unconditionally, so the reticle never gets stuck enlarged.
  • Highlighting — the force-field highlight loop shows one force field per currently-aimed NetTarget instead of a single one when capacity ≥ 2.

Shared visuals​

GrabHookVisuals.CreateBeam(att0, att1, parent) instantiates a Beam and copies all properties from GrabHookConfig.Visuals onto it. AnimateProjectile(beam, startAtt, targetPart, hitPos, onCleanup) runs the three-phase RenderStepped loop (Flight / Latch / Retract), aborts if targetPart leaves workspace (e.g. pool reclaim), and calls onCleanup when retraction completes or on abort. AnimateObserver(beam, startAtt) is a simpler decay loop for other players watching the retraction animation, started by JunkController on BeginJunkRetract.

Server-side validation​

ReqJunkClaim reconstructs junk world position from SpawnPos + MOVE_DIRECTION * (junkOdometer - SpawnOdometer), checks player distance against GrabHookConfig.Physics.MaxDistance + 15 studs, enforces per-player cooldown, and reserves the junk. ReqJunkFinalize checks reservation ownership and the 5-second timeout, marks the junk collected, broadcasts JunkCollected, and gives the corresponding tool to player.Backpack. See Junk for the full server-side claim/finalize detail.

Gotchas​

Server proximity check uses a latency slack of 15 studs

The claim check compares the player's position against the reconstructed junk position with GrabHookConfig.Physics.MaxDistance + 15. The extra 15 studs compensates for network latency. Increasing MaxDistance without adjusting the slack (or vice versa) can allow or block claims unexpectedly.

  • Shift-lock / aim camera interplay. Equipping the GrabHook fires Signals.RequestShootingCamera(true) to enter aim mode. Unequipping fires (false) to exit. If you add another system that also drives RequestShootingCamera, ensure the signals do not conflict (last writer wins).
  • mouse.TargetFilter = PlacedObjects prevents placed items from blocking the aim raycast. If new workspace folders are added for collidable world geometry that should also be ignored, add them to the filter.
  • fireToken versioning. Incrementing fireToken on unequip cancels all pending task.delay callbacks (sound fade-out, finalize). Never skip the token check inside scheduled callbacks or sounds will play on the next hook cycle.
  • Force-field template must exist. GrabHook.client uses ReplicatedStorage:WaitForChild("ForceField") at startup. If the template is missing, the script will yield indefinitely.
  • Beam and attachment cleanup. AnimateProjectile destroys both the Beam and the HookAttachment on cleanup. If you add more attachments or constraints to the junk part during a hook cycle, extend the CleanupJunkModel function in JunkController to remove them on pool return.
  • CharacterAnchor resolves the positional SFX anchor. The pickup sound plays at CollisionPart → UpperTorso → HumanoidRootPart (first found). SingleCollider avatars that lack HumanoidRootPart but have CollisionPart are handled correctly.

Data flow​

sequenceDiagram
    participant P as Player
    participant G as GrabHook (client)
    participant Cam as CameraController
    participant JC as JunkController
    participant S as JunkService (server)

    P->>G: Equip GrabHook tool
    G->>Cam: RequestShootingCamera(true)
    loop RenderStepped while equipped
        G->>G: GetAimedJunk - Spherecast toward mouse.Hit
        alt junk found
            G->>G: ShowForceField(junkPart, junkId)
        else aim lost > 0.08s
            G->>G: HideForceField
        end
    end
    P->>G: tool.Activated (cooldown check)
    G->>JC: Signals.TryClaimJunk(id, hitPoint)
    JC->>S: ReqJunkClaim
    S->>JC: BeginJunkRetract (broadcast)
    G->>G: FireGrappleAndAttach: Flight -> Latch -> Retract
    G->>JC: Signals.TryFinalizeJunk(id)
    JC->>S: ReqJunkFinalize
    S->>JC: JunkCollected (broadcast)
    P->>G: Unequip tool
    G->>Cam: RequestShootingCamera(false)
