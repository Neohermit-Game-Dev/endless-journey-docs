Progression (XP & Level)

Server-authoritative, party-shared XP & Level system persisted with ProfileStore. Level and progress are always derived from a single stored lifetime value via a pure curve module, so re-tuning the curve never desyncs saved data.

At a glance​

LayerFileRole
Clientsrc/StarterPlayer/StarterPlayerScripts/XPController.client.luauBridges XPStateSync/XPLevelUp to Signals.OnXPChanged and shows the level-up toast
Serversrc/ServerStorage/SharedModules/XPManager.luauProfile lifecycle, award API (AddXP, AddPartyXP), replication — runs in both places
Serversrc/ServerScriptService/XPSystemLoader.server.luauGameplay-only earner wiring (distance ticks, kills)

Configsrc/ReplicatedStorage/SharedModules/Configs/XPConfig.luauCurve constants, level cap, earning rates

Packets: XPStateSync, XPLevelUp — see Networking Map Signals: OnXPChanged, OnPlayerLevelUp — see Signals Map

How it works​

Data model and curve​

The profile stores a single value, TotalXP (lifetime cumulative). Level and progress are never stored — they're derived from it every time via XPCurve:

XPCurve.xpToNext(level: number): number
-- round(CURVE_COEFF * level ^ CURVE_EXP) + CURVE_OFFSET, 0 at/above MAX_LEVEL
XPCurve.levelFromTotal(totalXP: number): number
XPCurve.progress(totalXP: number): (level: number, xpIntoLevel: number, xpForNextLevel: number)

Defaults: CURVE_COEFF = 5, CURVE_EXP = 1.5, CURVE_OFFSET = 45, MAX_LEVEL = 100. Total XP to reach level 100 is roughly 204,000. All constants live in XPConfig.

Earning (party-shared)​

XP is shared with the whole party; one party occupies one server, so every player in the server receives the full award via XPManager.AddPartyXP.

SourceAmountTrigger
DistanceDISTANCE_XP_PER_TICK (1) every DISTANCE_TICK_SECONDS (5s)Train is in its "go" state (running, not braked/stalled) — driven off Signals.SetTrainState
KillsKILL_XP (10)Any EnemyNPC-tagged model's Humanoid.Died (attribution-agnostic)

The train starts braked, so no distance XP accrues before the first un-brake.

function XPManager.AddXP(player: Player, amount: number)
function XPManager.AddPartyXP(amount: number)

Both are no-ops if amount <= 0 or the profile isn't loaded. AddXP fires XPLevelUp and Signals.OnPlayerLevelUp when the level increases, then replicates XPStateSync.

Cross-place sharing (lobby ↔ gameplay)​

DataStores are universe-wide: both places use the same STORE_NAME and key (tostring(UserId)), so XP/Level are shared automatically, and ProfileStore session-locking serializes the teleport handoff. The lobby place must run XPManager.Initialize() and XPController (for display + clean handoff) but not XPSystemLoader — there are no earners in the lobby. The lobby mirror is a separate deployment, not part of this repo.

Not yet built​

An XP bar HUD (would consume OnXPChanged), level rewards (hook: XPLevelUp), per-killer attribution, and additional XP sources are all unbuilt.

Data flow​

sequenceDiagram
    participant Loader as XPSystemLoader
    participant Manager as XPManager (server)
    participant Client as XPController (owning client)

    Note over Loader: distance tick (train running) or enemy Humanoid.Died
    Loader->>Manager: AddPartyXP(amount) / AddXP(player, amount)
    Manager->>Manager: TotalXP += amount; XPCurve.progress(TotalXP)
    alt level increased
        Manager->>Client: XPLevelUp(level)
        Manager->>Manager: Signals.OnPlayerLevelUp:Fire(player, level)
    end
    Manager->>Client: XPStateSync(level, xpIntoLevel, xpForNextLevel)
    Client->>Client: Signals.OnXPChanged:Fire(level, xpIntoLevel, xpForNextLevel)
