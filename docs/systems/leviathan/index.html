Leviathan

The Leviathan is the boss that the Threat Timer counts down to. When the timer runs out, it swims out of a black hole rift and fights the train. It cannot die: the party either drives it off (its HP reaches 0: it screams, leaves through a rift, and every player gets a large reward) or escapes with a jump. Each later visit in the same run is stronger and pays more.

Segments and server time​

Every move is a segment: world head path Points, timing Keys, a server Start time, style overrides, the laser Sweep, Rifts, and Cut (when the next move takes over). The server builds it (LeviathanPlanner; random paths only on the server), sends it once (LeviathanSegment, Start = now + 0.1 s) and poses its hitboxes with the same maths. Clients pose the mesh from workspace:GetServerTimeNow() - Start, so a late joiner (JoinSync sends the current segment) lands mid-move. Each move starts from the body at its own start time and keeps the head's speed.

Generated paths steer like an animal: constant speed, a capped turn rate (SteerRadius 245 studs), a waypoint every 85 studs (WaypointSpacing). No turn is tighter than MinTurn (136 studs; LeviathanPlanner.selfCheck, 50 seeds): a path that bends tighter is redrawn (prowl and frenzy: a new random plan; laser lead-in: another start direction and distance to the first waypoint). These studs are set for the current body (spine ~572); rescale them with the body (see LeviathanConfig).

Its hits​

  • Slam (Impact): Slam.Damage to the train at the deck point under the head (clamped onto the train), through TrainShieldManager.ApplyDamage(…, ThreatConfig.BOSS_DAMAGE_SOURCE, …): shield first, then fuel, then a hull hit ends the run (LEVIATHAN_STRIKE). Players within Slam.Radius take Slam.PlayerDamage.
  • Laser: every Laser.Tick in the fire window, the same at the moving beam target; players within Laser.Radius.
  • Players take ShieldUpPlayerFactor (50 %) of their share while the shield is above 0 (read before the hit), and 100 % at 0. All its damage is × 1 + DamagePerVisit × (visit − 1). No hits during a jump.

Taking damage​

Every weapon and turret, on the whole body. The server body is a Humanoid model (tag EnemyNPC, KillReward = 0, AoeAtSurface) with hitboxes in 4 zones. Each hitbox has a DamageMult attribute (ZoneDamage): player gun damage is x1.2 on the head, x1 on the body and x0.7 on the wings.

Hit feedback. The hitter gets a damage number at the hit point in the screen-sized far style (see Damage Numbers; the server body does not replicate, so the packet carries the point). Everyone sees a hit glow: LeviathanController calls HitFlash.Play on the client mesh when LeviathanHealth drops. The body fills much of the screen, so HitGlow keeps it faint (From 0.8 → 1 over Time 0.25 s) and starts it at most once per Gap 0.35 s: steady fire is a soft pulse, not a strobe.

ZoneHitboxGun damage
Body (neck, body, tail)One cylinder per spine segment from Tail10 to Neck3 (radius HitboxRadius Body / Tail). It bends with the spine. The first cylinder reaches back to the tail fin tip.x1
HeadOne box around Wyrm_Head and Wyrm_Horns, on the Head nodex1.2
WingL, WingROne box around each wing mesh, on the wing root's spine nodex0.7

The boxes and the tail fin reach are measured from the template meshes at rest (plus HitboxPad), so a new model needs no new numbers. The head box is named Hb_Head, not Head, so it does not get the gun headshot bonus. Turrets, shell blasts and other area damage hit the whole body at x1. The body lives under the server's workspace.CurrentCamera: Camera children do not replicate, so moving them every frame costs no network, but server rays and overlap queries still see them. DamageTakenMult is 1 only in Prowl, Slam, Frenzy, Laser and Hold.

  • Gun rays (LagCompensation.Raycast) test it at the shooter's shot time with an analytic ray test (LeviathanBody:RaycastAt); its parts are left out of the world ray.
  • Turrets, shell fuses, AOE hit the hitboxes at the current pose (TrainWeaponDamage.liveEnemies lists it; the head hitbox is the aim point).
  • Schwarmfeuer lock-on: the gunner's client locks the look it sees; the lock travels as LeviathanConfig.LockToken, the server swaps it for the body, and sends the token back in SchwarmfeuerLaunched so clients fly the missiles at their look. The body's aim point (its PrimaryPart) is the hitbox at the node the client mesh rides on, so server missiles and client pictures home on the same spot; turret auto-aim and shell fuses use it too.

HP = BaseHealth × (1 + HealthPerVisit × (visit − 1)) × (1 + PerExtraPlayer × (players − 1)), set when the first Prowl starts. A player who leaves lowers max and current HP by the same share; joiners change nothing.

How a visit ends​

EndWhat happens
Driven off (HP 0)Attacks stop at once (no slam hit, no laser tick). Scream (the Defeat move, below), then RiftOut. When RiftOut starts, every player gets DriveOffXP / DriveOffCoins × 1 + RewardPerVisit × (visit − 1) × (1 + KillXPBonus / KillCoinBonus + party PartyKillRewardBonus), and OnLeviathanDrivenOff fires: the threat timer restarts a full Counting. Swarms it called stay until cleared.
JumpRiftOut (from Away: gone at once). No reward. Called swarms are removed. The timer resets on arrival as before.
Game overHold: prowls, no attacks.

The visit counter is per server (one run). While LeviathanPresent is true, VoidSwarmEvent.gateOpen() is false: no random swarm and no pirate ship starts (one already running finishes).

Rifts and camera shake​

Rifts use the approved look: ReplicatedStorage.VoidRift × RiftScale (~720 studs, a bit wider than the ~632-stud wingspan), particles off, billboard twirl on, grow RiftGrow, shrink RiftShrink. Every bone behind a rift's plane (within 1.2 rift radii of its axis) moves onto the plane (LeviathanPath.hide): no stretch, no wing fold. The mesh stays hidden until the entry rift is fully open, and hides before the exit rift shrinks. A rift closes once the tail is RiftClear past it. Fog paints far parts in its own colour (an entry rift ~1600 studs out showed as bright sky in the first fade seconds), so a Highlight on the rift's BlackOrb (RiftHole, near black, DepthMode = Occluded) keeps the hole dark at any distance; the body swimming out still covers it.

Laser flare​

While the laser charges and fires, the animator writes LaserGlow (0..1, charge × fade, a small flicker while firing) and LaserMouth, and lights the head with a PointLight on the charge orb. LeviathanLook draws LaserFlare: three soft glow images (Image, the LevelUpVFX Bloom texture) in a ScreenGui (LeviathanLaserFlare, under the HUD) at the mouth's screen point, sized from world studs (Layers = { studs wide, peak opacity, colour }) for the camera distance. A ScreenGui is drawn after the fog: 3D parts, billboards and lights all fade in it, so this is the only way the glow stays blinding at the laser's ~500–700 studs. A camera → mouth ray (RespectCanCollide, the look excluded) hides it while the train is in the way. The look also sets LaserGlow on its model; LeviathanWeather.Apply then mixes the fog colour toward Weather.LaserGlow.Color and adds Exposure, so the fog itself lights up.

Roar VFX​

On the Roar event LeviathanLook._roar clones ReplicatedStorage.LeviathanRoarVFX (Studio only; meshes and textures come from Blender Projects/LeviathanRoarVFX/build_roar_vfx.py). It follows LeviathanAnimator.MouthCFrame (the mouth, facing where the head looks, flinch included). LeviathanConfig.Roar drives it:

  • Rings shock tubes (Ring, SurfaceAppearance with an emissive mask), one each RingGap s. Each flies RingTravel studs out of the mouth, grows RingGrow x and fades over RingLife s. A Shock particle ring goes out with each one.
  • The sound Cone (narrow end on the mouth, streak texture) fades in over ConeIn, grows to ConeGrow x, and fades out over the last ConeOut of Seconds.
  • The Mouth part's Emit attachment: Flash (Flash glow puffs at the start) and Mist (on for Seconds).

A new roar replaces the last one. Fog fades 3D parts at a distance (see Laser flare), so the effect is weaker far out.

Every player's camera shakes (CameraShake) on Impact (2.2° / 0.8 s), Roar (0.7° / 2.2 s) and Dive (1.4° / 1.2 s, laser move time 12.6 s); values in LeviathanConfig.Shake.

Boss bar​

LeviathanBossBarController enables StarterGui.LeviathanBossBar (slides in from the top) while LeviathanPresent and LeviathanMaxHealth > 0, so the bar first shows when the first prowl sets the HP. Everything comes from workspace attributes, so late joiners see it too. The art is pixel art at 4× (ResampleMode = Pixelated): Frame (wings, track, name) and Head images are set in Studio; the fill is an image inside FillClip (ClipsDescendants, width = HP share × 712) that the controller swaps by state. Weather​

LeviathanWeatherController (client) fades a weather layer over the current biome for the whole visit (LeviathanPresent, rift time included): deep sea twilight zone fog: everything far away, sky included, melts into one deep blue fog wall, under a dark storm sky and dim cold blue light. At Density 0.4 the Leviathan at prowl range (~400 studs to the side) is a dim shape from the deck, with its blue glow. An optional Highlight named WeatherSilhouette (dark fill, drawn over the fog, DepthMode = Occluded) on the client model workspace.LeviathanLook.Leviathan can make it a clear dark shape at any density (Silhouette.Opacity, now 0 = off); its opacity follows the fade, and a hidden mesh (rifts) draws no highlight. There is no screen filter, so the train keeps its own colours. It fades in over FadeIn (4 s) and out over FadeOut (6 s), smoothstepped, and calls LeviathanWeather.Apply(biomeId, weight) every frame of the visit. Apply blends from the biome's own values in ReplicatedStorage.Biome.<Id> (the Atmosphere template and the Brightness, OutdoorAmbient, Ambient and ExposureCompensation attributes), so a biome swap mid-fade stays correct and the biome's own look still shows through. Past SkySwapAt (weight 0.5) it replaces the biome Sky with LeviathanWeatherSky (six storm textures from LeviathanConfig.Weather.Sky); below it, it clones the biome Sky back. The sky swap matters: the fog takes its hue from the sky's light, so under a blue skybox it turns teal. Atmosphere fog only thickens with distance (the train area within ~200 studs stays clear), so workspace.LeviathanMist, an invisible part with a box ParticleEmitter (built-in smoke texture), rolls soft mist clouds front → back (+X, the scroll direction) through a box around the train. The box is sized from TrainPlatforms when the mist starts (Upstream studs in front, SidePad each side); Rate and Opacity scale with the fade weight, and weight 0 removes the part. About Rate × Lifetime (~150) large particles: check phones. Values: LeviathanConfig.Weather (Mist for the clouds, Silhouette for the shape); PerBiome overrides any key for one biome (empty now).

The sky textures come from the Creator Store "Turbulent Dark Sky" (118806768825977). Its package also hides an obfuscated backdoor script (Runtime, a RemoteFunction, a fake GUI), so never insert the package; only the texture ids are used.

Preview in edit mode from the command bar (no playtest):

local m = game.ReplicatedStorage.SharedModules local c = m.LeviathanWeather:Clone() c.Parent = m require(c).Preview("Void") c:Destroy() -- or Normal, Volcano, Ice, Storm

Preview switches Lighting to that biome (BiomeVisuals.Apply) and applies full weather from a fresh clone of LeviathanConfig, so re-running it after a config edit shows the new values; the Clone of the module itself does the same for code edits (a plain require in the command bar keeps the first loaded copy). The preview has no Leviathan, so the silhouette shows only in a playtest. Run Preview("Normal", 0) before you save the place. To see the real fade, start a playtest and type /leviathan.

Dev command​

/leviathan [visit] (place owner / group rank 250+) starts a visit now; visit 0 or empty = the next one. /leviathandefeat (same gate) sets its HP to 0, so the real drive-off plays (Defeat, rift exit, reward, OnLeviathanDrivenOff). It works only while it can be hurt (Prowl, Slam, Frenzy, Laser, Hold: from its first prowl, not in a rift); else the server warns in the output.

Model and animation​

Model layout​

Six skinned MeshParts (Wyrm_Body, Wyrm_Head, Wyrm_Horns, Wyrm_Tail, Wyrm_WingL, Wyrm_WingR) share one bone tree (61 bones, plus 4 unweighted Glow light bones) under RootPart, the PrimaryPart. Its -Z is the head direction. The model is ~711 studs long (spine ~572), with a ~632-stud wingspan. The old single-mesh model is ServerStorage.Leviathan_OldBackup until the new one is playtested. The animator finds the bones by name:

BonesMoves with
Spine chain Tail10 … Tail1, Spine2, Spine1, Neck1 … Neck3, HeadCode: the path. These are the nodes.
Root, ChestCode: their nearest node
HeadCode: looks along the path (or at the laser target)
Everything under Head (Jaw, horns, frills, barbels), Wing*, Fin*The Blender clips (LeviathanAnimConfig.Clips)

The model's MouthOffset attribute (RootPart space) is where the laser starts, inside the open mouth.

Blue glow: EmissiveStrength 8 with EmissiveTint (110, 190, 255) on the body, head, horns and tail SurfaceAppearances makes the crystals, spine spots and eyes glow at any distance. Four extra unweighted bones named Glow (under Head, Chest, Spine2 and Tail10) sit just outside the mesh, each with a PointLight (colour 70, 170, 255, no shadows). They light the head, the back crystals and the tail fin up close (Roblox culls lights far from the camera). A light inside the mesh would light only the inside faces. SetVisible turns the lights off with the mesh while it is in a rift.

Clips​

The AnimationController plays the Blender clips (LeviathanAnimConfig.Clips) on top of the code pose. The clips rotate their bones and do not move them:

ClipPriorityPlayed
HeadSwayIdleLooped from the start: barbels and frills drift
Wings* (Calm, Prowl, Fast, Scream, Laser)MovementLooped. Each move's Wings = { clip, speed }; a new move cross-fades over WingFade
Jaw* (Yawn, Bite, Roar, Laser, Growl)ActionOne-shot at each Jaw = { time, clip } entry. A late joiner starts it part way; the next move does not cut it
DefeatAction4Drive-off one-shot (5.5 s, a Jaw entry of the Defeat move): flinch, pain roar, then wings, fins and frills fold back and the jaw shuts. It keys only wing, fin, jaw, frill and barbel bones and overrides every other clip on them. It freezes at 4.5 s, inside its still folded pose (AdjustSpeed(0): a finished one-shot drops its pose), so the wings stay folded until the look is removed. The freeze runs on server time, not the track's clock: a track that loads after Play (a late joiner) is seeked once it loads, and a track that one long frame ran past its end is played again, frozen. The drive-off RiftOut repeats the entry (shifted), so a late joiner gets the folded pose too; a running clip is not restarted

A clip bone behind a rift is moved onto the rift plane in the same way as a code bone. The clip's own Transform comes back once the bone is out.

Posing​

Every frame LeviathanAnimator:

  1. Finds where the head is on the move's path (Keys, smooth monotone interpolation).
  2. Places each spine node on the path at its rest distance behind the head. Before the first path point the path extends straight back, so the body always has room.
  3. Adds the swim wave (side and up), from 0 at the head to full at the tail.
  4. Builds a frame per node (look = toward the head, up carried down the chain so the body does not twist).
  5. Moves every part rigidly with the root's node (one BulkMoveTo, so no part is culled). It then sets the Transform of each code bone to the bone's wanted world pose, relative to its parent's new pose. It runs on Heartbeat, after the Animator has stepped the clip bones.

Defeat (drive-off)​

LeviathanPlanner.Defeat builds the drive-off move from the current body. From deep below (after the laser dive) it first climbs back up, as the swarm-call scream does, and every reaction key below starts after the climb. Then it drifts on nearly stopped (Drift: 60 studs/s for 2.2 s); if it is diving (mid-slam or mid-laser dive, head direction below −0.3) it levels out instead, slowly, so it neither drifts into the train nor loops down under it. Then it turns at SteerRadius toward "out from the train centre" until its flat heading is within 20° of it, pitches down Turn.Pitch (35°), and dives straight on for Turn.Dive (1.2 s). Waypoint speeds ramp from 60 to Turn.Speed (300) over the first turn waypoints. Cut is the end of the turn (~4.3 s from a prowl hold), then RiftOut takes over. The turn stays at or above MinTurn, and a drive-off mid-slam goes no lower near the train than the swarm-call scream does (LeviathanPlanner.selfCheck).

On top of the path (client only, the server hitboxes keep the path pose; it takes no damage then):

  • Flinch: LeviathanPath.flinch reads the move's Pitch keys (head up 18°, 0.15–0.4 s, back by 2.2 s) and Shake keys (±10° side to side at ShakeHz 2, 0.4–2.2 s). Neck1, Neck2, Neck3 and Head rotate about the Spine1 node by 1/4, 2/4, 3/4 and all of it (pitch about the head frame's right axis, yaw about its up axis), before the rift hide.
  • Glow: the Glow keys scale every SurfaceAppearance's own EmissiveStrength (8 → 2 over 2–4 s). The drive-off RiftOut repeats the keys (shifted), so the glow stays dim and a late joiner sees it dim. The next visit clones a fresh look, so nothing needs a reset.
  • Clip: the Defeat clip (see Clips); the roar sound and camera shake at 0.6 s (Roar event; only SwarmScream spawns a swarm on it).

The bind (node + offset per bone) is read once in LeviathanAnimator.new, which resets every Transform first. Note: Bone.WorldCFrame ignores Transform; read TransformedWorldCFrame for the posed bone.

Cost​

The old single-mesh model cost about 0.04 ms per frame in Studio (1 part move and 59 bone transforms). The old primitive model (936 parts) cost about 4.5 ms, because the engine had to move every part. The new model has 7 parts in one bulk move, 18 code bones and 43 clip bones; it has not been measured yet.

Moves​

All positions are in train space: origin = train centre, +X = train rear (the train heads -X), +Z = the train's left.

MoveWhat it doesEvents
IdleLeftSwims beside the train on its left, then dives away
IdleRightThe same on the right
CircleComes in from behind on the left, circles the train once (forward on the left, back on the right), dives away
SlamBody slam from wherever it is now (stop an idle or the circle, then play it): rears up on its side, crashes across the train centre, dives off the far sideImpact
SlamBackComes in high from behind, rears up, crashes along the roof, dives off the frontImpact
SlamRightComes in from the right, rears up, crashes across the train, dives off the leftImpact
LaserArches over from the left with its body across the train, charges an orb in its open mouth, sweeps a beam from the rear to the front end, keeps diving the way it faces, under the trainLaserFire

The idles and the circle keep the head at Y = 5 in train space: the eyes are then about level with players on the deck, so they can aim at it.

Slam is a FromCurrent move: its path starts with the body's current spine nodes. Then come its Lead points in head space (origin = the current head, +X = its flattened heading, -Z = out away from the train): a wide loop on along its heading, out away from the train and back in, because a ~900-stud body cannot turn tight. Then its Path points in slam space (train centre, -Z = out to the Leviathan's side): rear up, crash across the train centre, dive off the far side. Key point 0 is the current head, and the head keeps its current speed into the move. SlamBack and SlamRight remain as entries from far away.

Smooth turns​

  • All paths are centripetal Catmull-Rom. The uniform kind overshoots and even loops where point spacing changes (for example the 54-stud body chain next to a 450-stud step), which showed as sharp turns, a body that jumped back ~50 studs, or a head facing backwards.
  • Outside the crash itself, generated turns stay at or above MinTurn (136 studs; the slam loop is ~258). The crash bend (head hits the roof and flattens out) is about 90 studs, as in SlamBack and SlamRight.
  • The head's up vector carries over from the last frame (leaning back to world up), so a head pointing straight down does not flip the body 180°.

The laser's hold point is set so the path already points the head down at the train: the head turns at most ~20° to follow the target, so the neck does not bend unnaturally. The sweep ends are fractions of the train length (From = 0.5 = rear end, To = -0.5 = front end), so a longer train gets a longer sweep.

local anim = LeviathanAnimator.new(model)
anim.OnEvent = function(name) end -- "Impact", "LaserFire"
local _, size = workspace.TrainPlatforms:GetBoundingBox()
local seconds = anim:Play("SlamBack", CFrame.new(trainCentre), size.X)

Play builds a segment that starts now (the preview tools use it); the fight calls PlaySegment(segment). Rifts (a list) holds the rifts that bones hide behind; SetVisible hides the mesh; GetNodes returns the last spine pose.

Preview​

In Game Instance edit mode, paste tools/studio-previews/leviathan-anim-preview.luau into the Command Bar: it plays the config moves on the code bones. It counts down first; delete its Workspace folder to stop it. Edit mode does not step the Animator, so the Blender clips show only in a playtest. Rifts and the fight cycle: playtest with /leviathan.

Checks​

Edit mode, modules loaded fresh: LeviathanPath.selfCheck(), LeviathanPlanner.selfCheck(50), LeviathanBrain.selfCheck(), LeviathanBody.selfCheck(), LeviathanService.selfCheck() (stubbed collaborators, fake clock), LeviathanLook.selfCheck(), CameraShake.selfCheck().
