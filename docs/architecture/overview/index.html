Architecture Overview

Endless Journey uses a three-layer runtime architecture: Client, Shared, and Server. Network traffic between the client and server always flows through typed Packets; in-process events on the client flow through the Signals event bus.

Runtime Layers​

Client​

Client code lives under src/StarterPlayer/StarterPlayerScripts/ (controllers, *.client.luau) and src/StarterPack/Grabhook/ (tool scripts). Controllers own local prediction, UI, camera, and visual rendering. They never write game state directly — they send Packet requests and react to Packet syncs or Signal events.

Shared​

Shared code lives under src/ReplicatedStorage/SharedModules/ and is require-able from both the client and the server. This layer contains the cross-cutting backbone modules, typed packet definitions, config tables, pooling utilities, and shared validators used by both sides of the authority pattern.

Notable modules:

  • Signals/init.luau — in-process event bus
  • Packets/init.luau — typed network packet registry
  • Configs/ — all gameplay tuning tables
  • PlacementSystem.luau — shared placement validation logic
  • SprintValidation.luau — shared sprint validation helpers
  • CameraRig.luau — stateless camera CFrame composition
  • ShredderMath.luau — shared hold-duration computation
  • ShredderResultCodes.luau — shared result-code enum
  • SoundManager/init.luau — unified audio API
  • NotificationManager/init.luau — signal-driven toast system
  • MotionMaster.luau — animation library (replaces TweenService)
  • GenericPoolInstance.luau / GenericPoolObject.luau — instance pooling
  • WeaponValidation.luau / WeaponTypes.luau — shared weapon fire validation and type definitions
  • Factions.luau — faction/team identity helpers used by combat
  • QuestState.luau — shared quest period/bucket math
  • BattlePassState.luau — shared season/tier math
  • PerkState.luau — shared perk point/level math
  • XPCurve.luau — shared level curve derivation

Server​

Server authority modules live under src/ServerScriptService/ (entry-point scripts) and src/ServerStorage/SharedModules/ (authority modules required by server scripts). The server validates every state-changing request, owns the source of truth, and syncs relevant state back to clients via Packets.

Communication Diagram​

flowchart TB
    subgraph Client["CLIENT"]
        Controllers["Controllers / UI"] -->|Signals| Controllers
        Controllers -->|fire Packet request| ClientPackets["Packets layer\n(typed; no raw Remotes)"]
    end
    ClientPackets -->|RemoteEvent / RemoteFunction| ServerPackets
    subgraph Server["SERVER"]
        ServerPackets["Packets layer"] -->|sync / response Packet| Authority["Authority Modules\n(StaminaManager, PlacementServer, WeaponServer, XPManager, …)"]
    end

Signals are client-only and in-process — they never cross the network. All cross-boundary traffic uses Packets.
