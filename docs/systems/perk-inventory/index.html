Perk Inventory

Shop perks are the 70 perks that players buy with coins and equip in the Lobby only. There are two kinds: Consumable (the run uses one copy when it starts, and the effect lasts the whole run) and Expiring (a real-time clock that starts on the first equip and never stops). The Game Instance reads the loadout once per run and never changes it. Permanent perks are a different system: see Perks.

This page covers the data: inventory, coin shop, loadout and run start. Stat effects come in Perk Rework part 3. Until then, equipping a shop perk changes no stat.

How it works​

Kinds​

KindBuyStockActive
ConsumablePrice coins for one copyCopies[id]The whole run that used a copy, even at 0 copies left
ExpiringOne of Variants (Seconds, Price)Banked[id] (clock stopped) or Expires[id] (clock running)While Expires > now

Expiring clock. The first equip moves Banked into Expires = now + Banked. Time added while the clock runs (a purchase or a grant) extends Expires. Time added while it is stopped goes to Banked. Unequip never pauses the clock, and the clock also runs while the player is offline.

Loadout rules​

  • Slots: Personal 3, +1 at Lv 10, 20 and 30 (max 6). Party 1, +1 at Lv 30 (max 2). Tuned in ShopPerkConfig.Slots.
  • Equip appends to the end of the pool. Unequip removes one slot and the later slots move up. The saved lists never have gaps.
  • Equip checks, in this order: unknown → hidden → wrong pool → level → not owned → already equipped → no slot.
  • Same perk once: a pool holds each perk at most once. Perks of one Family stack: Hollow Points (+6%) and Marksman Tonic (+8%) give +14% gun damage. Family is a label for the catalog and GUI.
  • Level gate applies to buy and equip, not to Grant. A granted perk above the player's level waits in the inventory.
  • Hidden perks (22, built in Perk Rework part 5) cannot be bought or equipped: Vampire Rounds, Harpoon, Tracer Rounds, Quick Respawn, Lucky Coin, Recharge Plating, Hot Hands, Fuel Line, Spare Tank, Ammo Locker, Shield Capacitor, Overclock Core, Salvage Drone, Jump Spark, Rally Banner, Parallel Lab, Salvage Beacon, Auto-Loader, Free Runner, Lucky Charm, Quest Hunter, Treasure Map.
  • Prune runs on every profile load and before each buy, equip and grant. It deletes ended clocks and removes each loadout entry that is unknown, hidden, in the wrong pool or no longer owned. Unequip does not prune, so the slot index the client sent still points at the perk it shows.

Coin shop​

Buy(player, id, variantIndex) checks that both the inventory and coin profiles are loaded, then the level gate and price (PerkLoadoutState.canBuy), then calls CoinManager.DeductCoins. Only after a successful deduct does it add the stock. A failed deduct changes nothing.

Grant​

PerkInventoryManager.Grant(player, id, amount, reason) gives stock with no price and no level gate: amount is copies for a consumable and seconds for an expiring perk. Hidden perks can be granted. Drops and the Battle Pass (Perk Rework part 6) use it.

Run start​

The Game Instance passes a run id to PerkInventoryManager.Initialize: game.PrivateServerId (the reserved server), else game.JobId, else a fresh GUID (both are empty in Studio, so each Studio Play is a new run). On each profile load, the manager first asks SessionCoordinator.IsAuthorized(player) (it yields until the roster is read, and is always true under the Studio bypass). A player the party lock bounces back to the Lobby keeps every copy: no run starts for them. For an authorized player, BeginRun:

  1. If ConsumedRun == runId, this is a rejoin: ActiveRun stays and nothing is used.
  2. Otherwise it prunes, copies Loadout into ActiveRun, uses one copy of each equipped consumable, sets ConsumedRun, and prunes again. The second prune unequips consumables that reached 0, so the next run's loadout is honest. An expiring perk whose clock ended is not in ActiveRun.
  3. Fires Signals.OnShopPerksChanged(player) and replicates.

The Game Instance binds no buy, equip or unequip handler, so ActiveRun cannot change during the run. GetActiveRun(player) is the list Perk Rework part 3 reads. It returns the saved ActiveRun only when ConsumedRun is this server's run id; otherwise (the Lobby, a bounced player, a profile whose last run was another server) it returns empty lists, so an old run's perks can never apply.

Effects: PerkEffectsDispatcher reads GetActiveRun and GetExpires (the expiring clock ends) and republishes on OnShopPerksChanged and at each expiry; see Perks — Shop perk layer.

Teleport hand-off​

A profile that is still open in the Lobby delays the session start in the Game Instance. PartyCreation.TeleportParty therefore calls PersistenceRegistry.ReleaseForTeleport(members) right before party:TeleportMembers. Each manager's release marks the player released, saves and ends the session, and its OnSessionEnd handler skips the usual kick. If TeleportMembers errors, or TeleportService.TeleportInitFailed fires for one member, PersistenceRegistry.Reopen starts the sessions again and the client gets fresh snapshots. In Studio ReserveServerAsync fails first, so this path runs only in a published test.

Saved data​

Store PlayerPerkInventory (key = UserId), separate from PlayerPerks:

{
	Copies = {}, -- { [shopPerkId]: number }
	Banked = {}, -- { [shopPerkId]: seconds }, clock not started
	Expires = {}, -- { [shopPerkId]: os.time() clock end }
	Loadout = { Personal = {}, Party = {} },
	ConsumedRun = "",
	ActiveRun = { Personal = {}, Party = {} },
	SchemaVersion = 1,
}

Gotchas​

  • Equipping changes no stat until Perk Rework part 3 adds the shop layer to PerkEffectsDispatcher.
  • The client commands yield until the server answers. In the Game Instance there is no handler, so they return nil after the Packet's 10 s timeout.
  • The run start lives in PerkSystemLoader, a gameplay script, so a future Tutorial place would also use consumables. Decide that when the Tutorial exists.
