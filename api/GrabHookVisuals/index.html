GrabHookVisuals

Client-side beam and rope animation helpers for the grabhook tool.

All visual parameters (colour, width, curve amplitude, travel speed, etc.) are read from GrabHookConfig.Visuals and GrabHookConfig.Physics so that tuning never requires touching this module.

Three entry points are provided:

  • CreateBeam — builds a Beam instance between two attachments.
  • AnimateProjectile — three-phase flight/latch/retract animation for the tool user.
  • AnimateObserver — simplified decay animation for spectating clients who observe another player's grabhook.

AnimateProjectile​

GrabHookVisuals.AnimateProjectile(

The beam created by CreateBeam.

startAtt: Attachment,--

The origin attachment (handle side).

targetPart: BasePart,--

The junk part being reeled in.

hitPos: Vector3,--

The world position where the hook latched.

onCleanup: (() → ())?--

Optional callback invoked when the animation ends.

) → RBXScriptConnection--

The RenderStepped connection driving the animation.

Drives the three-phase grabhook animation for the tool user on RunService.RenderStepped:

  1. FLIGHT — the hook attachment lerps toward hitPos over a duration derived from distance and GrabHookConfig.Physics.Speed, with a sinusoidal rope wave that decays as the hook approaches.
  2. LATCH — a single transition frame that flattens the curve and records the retract distance.
  3. RETRACT — targetPart.Position is lerped back to the handle each frame. When retraction completes (or if targetPart leaves workspace), the beam and junk attachment are destroyed and onCleanup is called.

Returns the RBXScriptConnection so the caller can disconnect early if needed.

AnimateObserver​

</>
GrabHookVisuals.AnimateObserver(
beam: Beam,--

The beam to animate.

startAtt: Attachment--

The origin attachment to clean up when done.

) → RBXScriptConnection--

The RenderStepped connection driving the animation.

Drives a simplified rope-wave animation for spectating clients. Since the observer receives the event after server confirmation the hook is already assumed latched; the wave simply decays over time using a standard 1 / (1 + elapsed * decay) envelope.

Automatically disconnects and destroys startAtt when the Beam is destroyed by the owning controller.
