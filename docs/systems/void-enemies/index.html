Void Enemies

Five flying void creatures attack the train: Void Cyst, Bileplume Drifter, Shatterbeak, Ogler and Sirenspine Chorus. The server owns invisible bodies with a Humanoid (so guns, the cannon, kill credit and perks work as on any NPC) and moves only their root part. Each client clones the full part-built look from a saved Studio model and animates it. Every enemy hit goes through one shield rule: while the train shield is above 0, it takes every attack, including attacks aimed at players.

How it works​

Bodies and looks​

A body (ServerStorage.EnemyAssets.<Id>, ModelStreamingMode = Atomic so a streaming client gets the root and the look together) is an invisible anchored HumanoidRootPart, a Humanoid (BreakJointsOnDeath and RequiresNeck off, display off) and 1–2 invisible hitboxes welded to the root (CanQuery on, so hitscan and AOE find them). VoidEnemyService.Spawn clones it, sets HP from config, tags it EnemyNPC, sets attribute Visual = <Id>, parents it to workspace.ActiveEnemies, and calls EnemyChrono.Track (player hitscan gets lag compensation).

A look (ReplicatedStorage.EnemyModels.<Id>) is the full part model. VoidEnemyController clones it for every body with a Visual attribute, eases it toward the body root (1 - exp(-LookEase·dt)) and poses it every frame within LookNear, every 3rd frame within LookFar, else every 10th. A missing look warns once per Id; the body still works.

Only the body root replicates its movement. The server sets it every Heartbeat along the current MoveTo; behaviors decide at 10 Hz.

Look rig format​

Editing a look in Studio needs no code as long as it keeps this format:

  • Root — invisible PrimaryPart at the model pivot; the name tag hangs on it.
  • Joints/J_<name> — invisible pivot parts. Attributes: Parent (another joint's name, or empty = the root), Kind, and the numbers that kind reads.
  • Every other part — attribute Joint = <name> follows that joint; no attribute = static.
  • A Parent loop (A → B → A) warns once and hangs the joint where the loop closes off the root.

Each frame: pose(joint) = pose(parent) * restOffset(joint) * wiggle(Kind, t). Rest offsets come from the saved model, so moving, resizing, recoloring, adding or deleting parts and joints just works. A new ray is a copy of an old ray's joints and parts.

The shield rule​

VoidEnemyService.Impact(origin, target, attack, attacker) is the only way an enemy deals damage:

jump:        nothing (a glob still in the air when the jump starts)
shield > 0:  point = VoidEnemyMath.clipToShield(origin, target, front, rear, radius) or target
             TrainShieldManager.ApplyDamage(Damage, Source, { Position = point, Severity })
             -- players and deck take nothing, even when the attack was aimed at a player
shield == 0: TrainShieldManager.ApplyDamage(Damage, Source, nil, spareHull)  -- fuel, then hull
             CombatService.ApplyAOE(target, Radius, PlayerDamage, "AOE", attacker, { attacker })

The shield shape is the upper half-capsule around the front and rear dome centers (VoidEnemyMath.shieldLine, same shape RockService uses). Curved paths (bile arc, a diving Shatterbeak) test each short step. EndPoint(origin, target) gives the same point without damage, so rushes and dives aim at the shield surface. The client clips its visuals with the same math while TrainStateCache.ShieldFraction() > 0.

Every shield hit shows the forcefield for a random 0.5–1.25 s — see Train Shield — Dome.

PickTarget aims only at players who stand on the train (OnDeck: over the TrainPlatforms box, at most 15 studs above it), never at a player who fell off.

Sirenspine buff​

Each pulse sets DamageTakenMult, AttackRateMult and Buffed on every other void enemy within BuffRadius, and clears them on enemies that left the radius. When the Sirenspine dies or is removed, OnGone clears all three at once. CombatService.ApplyToModel multiplies NPC damage by DamageTakenMult (see Enemy Combat). The client draws a gold highlight and three tethers to the nearest Sirenspine's closest pipe tips while Buffed is set.

Spawning​

The Void channel in Events Orchestrator rolls every 600 odometer studs (~21 s at cruise). VoidSwarmEvent.CanTrigger blocks every roll until the crew has finished any weapon research (a RangedWeapon or TrainWeapon node at level 1 or more) or the train has made its first jump to a new biome (VoidSwarmEvent.unlocked). After that it blocks rolls during a jump and passes with the current biome's Chance. Both conditions are for this run only (research is session-only). Start picks a pack by the biome's Weights, spawns it into an EnemyWave, and finishes when the wave clears, on a jump, or after MaxActiveSeconds. The wave is on the event's Janitor, so every end path despawns survivors.

Testing​

No test suite. In edit mode, each of these returns without an error (Command Bar):

loadstring(game.ReplicatedStorage.SharedModules.VoidEnemyMath.Source)().selfCheck()
loadstring(game.ReplicatedStorage.SharedModules.VoidEnemyRig.Source)().selfCheck()
loadstring(game.ServerStorage.SharedModules.VoidEnemyService.Source)().selfCheck()
loadstring(game.ServerStorage.SharedModules.Events.VoidSwarmEvent.Source)().selfCheck()
-- and each VoidEnemyBehaviors.<Id>.selfCheck()

In a playtest, on the server: require(game.ServerStorage.SharedModules.Events.VoidSwarmEvent).Force("Ogler") spawns one pack now. Shield damage needs a started train (Signals.SetTrainStarted:Fire(true)).

Team preview: tools/studio-previews/void-enemy-preview.luau runs all five in edit mode with the Studio looks; set PHASES and SHIELD_ONLINE at the top and paste it into the Command Bar.

Config surface​

VoidEnemyConfig: Archetypes (per Id: Name, TagHeight, Hp, attack Damage/PlayerDamage/Radius/Severity, and the timings named above), Packs, Biomes, Fx, MaxActiveSeconds, DeathLinger, LookNear, LookFar, LookEase. See Config Map.
