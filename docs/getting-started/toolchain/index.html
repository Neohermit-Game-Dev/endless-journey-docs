Toolchain & Build

Endless Journey uses a small, pinned toolchain. All tools are declared in rokit.toml and managed by Rokit.

Initial Setup​

After cloning the repo, run this once:

rokit install

This installs the pinned versions of Rojo, Wally, wally-package-types, and selene into your local toolchain.

Common Commands​

CommandPurpose
rojo serveStart the live-sync server for Studio editing.
rojo build -o "Game Instance.rbxlx"Emit a static place file from src/.
rojo sourcemap default.project.json -o sourcemap.json --include-non-scriptsRegenerate the sourcemap used by Luau LSP. Re-run after adding or moving files.
wally installFetch Wally dependencies into Packages/ (shared) and ServerPackages/ (server).
wally-package-types --sourcemap sourcemap.json Packages/Regenerate type exports for Wally packages. Run after every wally install so Luau type-checking sees package types.
selene srcLint Luau source against the Roblox standard library (std = "roblox", config in selene.toml).

After wally install — Manual Studio Step Required​

TweenPlus TweenPreallocations

After every wally install, you must manually re-set the TweenPreallocations attribute in Studio — or TweenPlus will crash on load.

wally install deletes and regenerates the entire Packages/ directory. The TweenPlus package (Packages/_Index/alexanderlindholt_tweenplus@<ver>/tweenplus) reads a TweenPreallocations number attribute from its own script instance at require-time with no nil fallback (table.create(script.Parent:GetAttribute("TweenPreallocations"))). When the attribute is absent the package throws:

invalid argument #1 to 'create' (number expected, got nil)

This error cascades: TweenPlus → PlacementSystem → SprintController → every consumer fails to load.

Steps to fix after wally install:

  1. Open Studio with rojo serve running.
  2. In the Explorer, navigate to: ReplicatedStorage → Packages → _Index → alexanderlindholt_tweenplus@<ver> → tweenplus
  3. In the Properties panel, add an attribute:
    • Name: TweenPreallocations
    • Type: number
    • Value: 256
  4. Save the place file. The attribute persists until the next wally install.

A default.project.json $properties override cannot be used here: in live Rojo sync, Rojo recreates the path-synced instance instead of patching it, so the attribute would be wiped on every sync cycle.

No Automated Tests​

note

There is no automated test suite. All verification happens by playtesting in Studio. See the How-To Playbooks for the manual smoke-test steps specific to each system.
