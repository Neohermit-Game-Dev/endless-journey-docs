Crosshair

One dynamic crosshair whose on-screen size is the real spread cone: shots land inside it. Firing and moving make it grow (and make aim worse); pausing and standing still let it shrink back. Client-only drawing, with turret spread rolled on the server from the same shared maths. Game Instance only — the Lobby has no aim tools and does not map CrosshairController.

When it shows​

The Crosshair ScreenGui (ResetOnSpawn = false, IgnoreGuiInset = true) shows while aim mode is on (OnShootingCameraToggled(true)), no turret is mounted (OnTurretMounted carries nil) and the character is alive. IgnoreGuiInset puts the image on the exact ViewportSize / 2 the gun and turret aim rays use. On death the controller drops its own aim flag, because CameraController leaves aim mode on death without firing OnShootingCameraToggled.

Sources​

Whoever owns the aim publishes a source with Signals.SetCrosshairSource(source?), where source is CrosshairMath.CrosshairSource:

OwnerSourceCleared on
GunHandler (hand guns){ Style = "Cross", Cone = coneNow } — base spread + firing bloom + movement bloom (Weapons)unequip
GrabHook{ Style = "Circle" }unequip
TrainTurret/ShellWeapon (Cannon, AutoCannon, Burst Cannon, Energy Cannon, CIWS gunner){ Style = "Cross", Cone = SpreadBase + bloom }, the same bloom the server rolls shells indismount (Gunner session cleanup)
SchwarmfeuerController (gunner){ Style = "Cross", Cone = salvo kick } — visual only, missiles have no spreaddismount (Gunner session cleanup)

Owners clear with SetCrosshairSource(nil, theirSource). CrosshairMath.applySource makes such a clear take effect only while that owner's source is current: mounting a turret while holding a gun sets the turret source first and then unequips the gun, and the gun's late clear must not wipe the turret's. Leaving aim mode only resets the GrabHook net-perk multiplier. Character removal clears the source in both consumers (a torn-down character never unequips its tool) and drops the aim flag, like CameraController's resetModes.

TurretGui crosshair​

While a turret is mounted the hand crosshair hides and TurretGuiController draws the turret one: StarterGui.TurretGui.Crosshair.Image (the cross image), mint, amber while reloading. It reads the same SetCrosshairSource cone and sizes with the same CrosshairMath.crossSizePx and SizeEaseRate, on the per-mount RenderStepped. Its size is real pixels, so the Crosshair frame's UIScale stays 1. The Sturmlanze publishes no source, so its crosshair stays at the floor size.

Size​

For Style = "Cross" the cone edge sits at

radiusPx = tan(cone) / tan(camera.FieldOfView / 2) * (ViewportSize.Y / 2)

never below MinRadiusScale * ViewportSize.Y (spread-0 weapons keep a visible crosshair). The image is 2 * radiusPx / ConeEdgeRatio px square (CrosshairMath.crossSizePx), because the cone edge sits at ConeEdgeRatio of the image's half-width. The live FOV is read every frame, so the sprint FOV change keeps the size honest. The size eases toward its target at SizeEaseRate on one RenderStepped that is bound only while the crosshair is visible.

For Style = "Circle" the image is CircleScale * ViewportSize.Y * netMultiplier px square. RequestReticleScale(m) sets netMultiplier (the GrabHook Wide Net perk sends 1.6).

Bloom maths​

CrosshairMath.Bloom = { value, at } stores bloom in degrees and the os.clock() it was last written. current(b, now, recovery) subtracts recovery * elapsed (never below 0); shoot(b, now, spec) returns the bloom before the shot (the cone that shot rolls — what the player saw), then stores it plus perShot, capped at max. Nothing is stepped per frame, so a server and a client that saw the same shot times agree on the cone.

Run the self-check from the Studio Command Bar:

loadstring(game.ReplicatedStorage.SharedModules.CrosshairMath.Source)().selfCheck()
