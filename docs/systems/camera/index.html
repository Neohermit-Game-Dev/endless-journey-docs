Camera

A fully script-owned third-person camera. CameraController sets Camera.CameraType = Enum.CameraType.Scriptable and computes Camera.CFrame every frame from yaw/pitch/distance state, rather than decorating Roblox's default Custom camera. Mouse-look, scroll zoom, wall occlusion, and character-facing are all one render step in one script; a small stateless module (CameraRig) does the CFrame math. The system is client-only — there is no server component.

At a glance​

LayerFileRole
Clientsrc/StarterPlayer/StarterPlayerScripts/CameraController.client.luauState machine, mouse-look, zoom, occlusion, offset spring, render step, signal wiring
Clientsrc/StarterPlayer/StarterPlayerScripts/PlacementCameraController.client.luauOwns the camera during build mode; see Placement camera
Sharedsrc/ReplicatedStorage/SharedModules/CameraRig.luauPure, stateless CFrame composition (Compose, ClampPitch)
Configsrc/ReplicatedStorage/SharedModules/Configs/CameraConfig.luauOffsets, look angles, spring tuning, reticle, zoom range, occlusion buffer

Packets: none — camera state is entirely client-local Signals: consumes RequestShootingCamera, RequestMouseIcon, RequestReticleScale, OnBuildModeChanged, OnSettingChanged; produces OnShootingCameraToggled — see Signals Map

How it works​

State machine​

Two orthogonal booleans select the mode (aim wins over free-look):

  • aimMode — set exclusively via Signals.RequestShootingCamera. No player keybind activates aim directly; only tools (GrabHook on equip), weapons (WeaponController on weapon equip/unequip), and systems (PlacementClient on build-mode entry) fire this signal.
  • freeLookMode — toggled by LeftAlt via ContextActionService:BindAction("ToggleCameraMode", ...); inert while aimMode is true (the action sinks the input but silently no-ops).

Two more flags participate in lookActive()/applyState() without being a "mode" of their own:

  • guiRequestsMouse — set by Signals.RequestMouseIcon; frees and shows the cursor and suspends mouse-look, independent of freeLookMode.
  • buildModeActive — set by Signals.OnBuildModeChanged; see Placement camera.

On every CharacterAdded a new MotionMaster.Spring (offsetSpring) is created bound to a plain { Value, Parent = true } holder (offsetHolder), not directly to humanoid.CameraOffset — the spring drives offsetHolder.Value, which the render step then feeds into CameraRig.Compose as the screen-relative offset. The spring's Omega/Zeta come from CameraConfig; it is destroyed on CharacterRemoving. The render step runs at Camera priority via RunService:BindToRenderStep("Camera", Enum.RenderPriority.Camera.Value, ...).

CameraRig.luau is pure, stateless camera math shared by nothing else today but kept separate so it's independently testable/reviewable: CameraRig.ClampPitch(pitch, minPitch, maxPitch) is a math.clamp wrapper, and CameraRig.Compose(focusPosition, offset, yaw, pitch, distance, lookOffset) rotates offset into the yaw/pitch look frame, adds it to focusPosition, then backs the camera off distance studs along the look vector, returning (cameraCFrame, adjustedFocusPosition).

lookOffset is an optional Vector2 (radians, X=pitch, Y=yaw) that rotates the look direction about the fixed camera position — the camera position and the occlusion raycast (which fires before Compose runs) are untouched. CameraConfig.ShootingLookAngle and CameraConfig.ThirdPersonLookAngle supply this in degrees; CameraController blends the active mode's angle with a second MotionMaster.Spring, mirroring offsetSpring/offsetHolder exactly (retargeted on the same applyState() calls, created/destroyed alongside it).

Modes​

Locked third-person (default) — mouse always drives yaw/pitch (lookActive() returns true); MouseBehavior = LockCenter, cursor hidden; the HRP lerps to face humanoid.MoveDirection while moving.

Aim — entered only via Signals.RequestShootingCamera(true). Shoulder offset (CameraConfig.ShootingOffset) via the offset spring, reticle visible, mouse locked+hidden, HRP lerps to face the camera's yaw (not movement direction) so aiming and strafing look correct together. Exiting fires Signals.OnShootingCameraToggled(false).

Free-look — toggled by LeftAlt when not aiming. Cursor is freed and shown (MouseBehavior = Default), but lookActive() only returns true while the right mouse button is held — a faithful port of the old default-camera free-look behavior. HRP still lerps to face movement direction, same as locked third-person.

Signals.RequestMouseIcon is orthogonal to all three modes: while guiRequestsMouse is true (and aimMode is false), the cursor is freed/shown and lookActive() returns false regardless of freeLookMode, for GUIs (e.g. the workbench) that need a clickable cursor.

Sensitivity​

sensitivity is read once at startup from SettingsClient.Get("CameraSensitivity") and kept live-updated by subscribing to Signals.OnSettingChanged (filtering on key == "CameraSensitivity"). Every frame that lookActive() is true, raw pixel delta from UserInputService:GetMouseDelta() is scaled by CameraConfig.MouseLookBaseSpeed * sensitivity before being applied to yaw/pitch. See Settings for how CameraSensitivity is defined, synced, and persisted.

Zoom​

Scroll wheel input adjusts targetDistance by CameraConfig.ScrollZoomStep per notch, clamped to [CameraConfig.CameraMinZoomDistance, maxDistanceForMode()]. maxDistanceForMode() returns ShootingCameraMaxZoomDistance in aim mode or ThirdPersonCameraMaxZoomDistance otherwise.

Occlusion​

Each frame, a raycast runs from the offset focus point toward the desired camera position, excluding the local character. If it hits, occludedDistance is clamped to hitDistance - CameraConfig.BoomBuffer (floored at CameraMinZoomDistance); otherwise it's just targetDistance. A separate renderDistance is lerped toward occludedDistance at BoomSmoothingSpeed * dt per frame and is what actually gets passed to CameraRig.Compose — targetDistance (the zoom-wheel target) is never touched by occlusion, so releasing from behind a wall smoothly zooms back out to the player's chosen distance.

Placement camera​

While build mode is active, PlacementCameraController.client.luau — a separate script, not part of CameraController — takes exclusive ownership of the camera:

  • Sets Camera.CameraType = Enum.CameraType.Scriptable and drives Camera.CFrame every frame: fixed height and pitch above the player (PlacementConfig.TopDownHeight/TopDownPitch), locked to whatever yaw the player was facing when build mode started.
  • Eases into and out of the top-down angle via an exponential chase-lerp (alpha = 1 - exp(-CameraTransitionSpeed * dt)) rather than snapping instantly. On exit it eases toward an approximation reconstructed from the camera's offset relative to the player's HumanoidRootPart at the moment build mode was entered, then hands off to Enum.CameraType.Custom once that blend has settled (EXIT_SETTLE_TIME, ≈0.2s at the default speed).
  • Fades any PlacementConfig.OccluderTag-tagged parts (e.g. roofs) to OccluderTransparency for the duration, restoring their original transparency on exit.
  • Fires Signals.RequestMouseIcon(true) on PC (gated on UserInputService.MouseEnabled and UserInputService.KeyboardEnabled) so CameraController frees and shows the cursor instead of locking it to screen-center — needed because the placement camera doesn't rotate with mouse movement, so mouse.UnitRay (used by PlacementClient for the placement raycast) needs a cursor that can move to aim anywhere.
  • Restores Enum.CameraType.Custom immediately (hard cut, no blend) on CharacterRemoving — a backstop in case build mode didn't cleanly exit first, e.g. character death.

CameraController and PlacementCameraController both own the Scriptable camera at different times, and coordinate via Signals.OnBuildModeChanged. CameraController subscribes to this signal and sets buildModeActive accordingly; its render step's first statement is if buildModeActive then return end, a full no-op for the duration of build mode. On resume it reasserts camera.CameraType = Enum.CameraType.Scriptable (guarded — only writes if not already Scriptable).

Gotchas​

Aim mode is signal-only

There is no keybind that activates aimMode directly. Only external systems fire Signals.RequestShootingCamera. If a new tool or system needs to enter aim mode it must fire this signal — do not read or write the aimMode local directly.

Accepted ~0.2s exit-stutter

PlacementCameraController's own exit-blend keeps writing camera.CFrame for EXIT_SETTLE_TIME (≈0.2s at the default CameraTransitionSpeed) after build mode ends, before it hands CameraType back to Custom. Since CameraController resumes its own Scriptable writes immediately when OnBuildModeChanged(false) fires, there is a brief window where both scripts could write Camera.CFrame on the same frame-ish timescale, producing a small visual stutter. This is a known, accepted residual limitation — eliminating it would require either a new cross-module "exit fully settled" signal or coupling CameraController to PlacementCameraController's private EXIT_SETTLE_TIME constant, judged not worth it for a sub-quarter-second cosmetic blip.

  • Do not use TweenService to animate the camera offset. offsetSpring is a MotionMaster.Spring driver bound to offsetHolder.Value; bypassing it will produce conflicting states and the spring will override any TweenService tween on the next frame.
  • CameraController and PlacementCameraController both write Camera.CameraType/Camera.CFrame and must never run their write paths in the same frame — that's what buildModeActive exists to prevent. Do not add a third script that writes Camera.CFrame without wiring it into this same coordination.
  • The offset spring is re-created on every CharacterAdded and destroyed on CharacterRemoving. Holding a reference to an old spring past the character death will produce a dangling driver pointing at a destroyed Humanoid.
  • freeLookMode frees and shows the mouse cursor, but does not re-enable humanoid.AutoRotate; CameraController always drives HRP facing itself and sets humanoid.AutoRotate = false unconditionally (skipped entirely while humanoid.Sit is true).
  • A GUI that needs a clickable cursor fires Signals.RequestMouseIcon:Fire(true); while set (and not aiming) the camera holds MouseBehavior = Default and shows the cursor, restoring LockCenter on Fire(false).
  • CameraSensitivity changes take effect on the very next frame via Signals.OnSettingChanged — there is no need to re-fetch SettingsClient.Get manually or restart the character.

Data flow​

sequenceDiagram
    participant U as UserInputService
    participant C as CameraController
    participant Cam as Camera
    participant Ext as External systems

    U->>C: GetMouseDelta() (every RenderStep, when lookActive())
    C->>C: yaw/pitch -= delta * MouseLookBaseSpeed * sensitivity
    C->>C: CameraRig.ClampPitch(pitch, MinPitch, MaxPitch)

    U->>C: MouseWheel scroll
    C->>C: targetDistance = clamp(targetDistance + step, MinZoom, maxDistanceForMode())

    loop RunService RenderStep "Camera" (Priority = Camera)
        C->>C: if buildModeActive then return end
        C->>C: reassert CameraType = Scriptable
        C->>C: occlusion raycast -> renderDistance lerped toward occludedDistance
        C->>Cam: CameraRig.Compose(subject, offset, yaw, pitch, renderDistance, lookOffset)
        C->>C: lerp HRP facing toward camera yaw (aim) or move direction
    end

    Ext->>C: Signals.RequestShootingCamera(true/false)
    C->>C: aimMode = value; applyState()
    C->>C: offsetSpring/angleSpring retarget; MouseBehavior; reticle visible
    C-->>Ext: Signals.OnShootingCameraToggled(aimMode)

    U->>C: LeftAlt (non-aim only)
    C->>C: freeLookMode toggles; applyState()

    Ext->>C: Signals.RequestMouseIcon(visible)
    C->>C: guiRequestsMouse = visible; applyState()

    Ext->>C: Signals.OnBuildModeChanged(isActive)
    C->>C: buildModeActive = isActive (render step becomes no-op while true)
